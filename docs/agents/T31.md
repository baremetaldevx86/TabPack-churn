# T31 — Lightweight cross-platform CI design

## Assignment

Design a small CI workflow that exercises linting, type checking, unit tests, and
an offline smoke test on both Windows and Linux, without downloading experiment
data or requiring a GPU. This task deliberately does not add a workflow or
change source files; the coordinator can translate the design into the eventual
`.github/workflows/ci.yml` after the package and test layout are settled.

## Recommended workflow

Use one GitHub Actions workflow triggered by `push` and `pull_request`, with a
single `quality-and-tests` job on a two-entry matrix:

```yaml
strategy:
  fail-fast: false
  matrix:
    os: [ubuntu-24.04, windows-2022]
    python: ['3.12.10']
```

The job should use `runs-on: ${{ matrix.os }}`, check out the repository, set up
`${{ matrix.python }}`, enable pip caching, and install the project's pinned
development dependencies. Use reviewed SHA-pinned checkout/setup-python actions;
set `permissions: contents: read` at workflow level. Use push/PR concurrency keyed
by workflow and ref with `cancel-in-progress: true` to cancel superseded runs.
Do not use `pull_request_target` to execute untrusted PR code. Prefer the
eventual supported command (for example `python -m pip install -e ".[dev]"`)
over a second, CI-only dependency list. If PyTorch is a direct dependency,
install the CPU wheel explicitly in the bootstrap step, or provide a documented
CPU requirements/lockfile; an extra alone cannot choose the pip index. A portable
bootstrap contract for T12 to finalize is:

```text
python -m pip install --index-url https://download.pytorch.org/whl/cpu "torch==<T12-approved-version>"
python -m pip install -r <T12-approved-dev-lock> -e ".[dev]"
python -m pip check
python -c "import torch; assert torch.version.cuda is None; assert not torch.cuda.is_available()"
```

Use the CPU index only for that explicit torch installation, not for Ruff or
other packages. The dev lock must preserve the CPU build and must account for
Windows/Linux dependency differences using environment markers or OS-specific
locks. Cache keys should include OS, exact Python version, and lockfile hashes;
cache pip downloads, not a virtual environment. Dependency installation uses
the network; offline here describes test execution and experiment acquisition.

Set these job-level environment variables so the same commands work in both
shells:

```yaml
env:
  CUDA_VISIBLE_DEVICES: ''
  OMP_NUM_THREADS: '2'
  MKL_NUM_THREADS: '2'
  PYTHONHASHSEED: '0'
```

Use module invocations rather than OS-specific executables or shell syntax:

1. `python -m ruff check <source-root> tests`
2. `python -m ruff format --check <source-root> tests`
3. `python -m mypy <the-final-package-path>`
4. `python -m pytest -q --strict-markers --strict-config tests -m "not smoke and not slow and not gpu and not data" --junitxml=junit-unit.xml`
5. `python -m pytest -q --strict-markers --strict-config tests/test_smoke_synthetic.py -m "smoke and not slow and not gpu and not data" --junitxml=junit-smoke.xml`

Run each command as its own Actions step: PowerShell's last-exit-code behavior
must not hide an earlier failure in a multi-command block. Source/type paths
remain placeholders until packaging exists; T42 proposes the explicit smoke
filename above. Limit lint/type discovery to authored code so ignored
`.reference/`, environment folders, generated artifacts, and upstream code are
not checked. Put shared Ruff/mypy settings in project metadata, not duplicated
CLI-only configuration. Type-check the complete application package; start with
checked function definitions, unused-ignore reporting, and untyped-definition
reporting. Handle genuinely untyped third-party imports with narrow overrides
rather than globally ignoring errors or excluding hard modules.

Declare `slow`, `gpu`, `data`, and `smoke` markers in pytest configuration.
Require the T42 test to have `smoke` and neither `slow`, `gpu`, nor `data`.
Ordinary pytest excludes smoke so it is not run twice. Missing files, no tests
collected, collection/import errors, and failed checks fail the job; do not use
`continue-on-error` or blanket `importorskip` for required CPU dependencies.
The smoke receipt must show at least one **passed** smoke test: an all-skipped
JUnit report is not success, even though pytest exits zero. The coordinator can
check this with a tiny Python `xml.etree.ElementTree` assertion step on the
JUnit testcase elements (reject failures/errors and require a non-skipped case).

Use T42's exact tiny 32/12/12 synthetic split, CPU, one worker, zero dropout,
at most three epochs, and all three model paths with checkpoint restoration and
deterministic replay. Locally generated temporary checkpoints are necessary to
test round trips; downloaded or preexisting checkpoints are not. All artifacts
belong under `tmp_path` and retain `synthetic_smoke_v1` provenance. T24's leakage
tests remain ordinary offline unit tests. Smoke success is engineering evidence,
not real Churn measurements.

### CI resource and portability rules

- Keep the matrix to Ubuntu and Windows, Python 3.12, and one job per OS; do not
  add a GPU runner, service container, dataset cache, or scheduled benchmark.
- Use `timeout-minutes: 15` (or a similarly conservative limit) and cap test
  threads via the environment above. Do not use `pytest-xdist` in this job.
- Tests must not assume `/tmp`, POSIX paths, fork semantics, or a shell-specific
  environment assignment. Use `pathlib`, `tmp_path`, and Python APIs in source
  and tests.
- Keep data/download integration tests behind the `data` marker so ordinary PR
  CI never downloads experiment data. Marker selection does not prevent module
  imports during collection: no module import, fixture collection, or conftest
  may download data or initialize CUDA. Mock HTTP/acquisition in downloader unit
  tests, and patch the acquisition entrypoint to raise in T42's smoke fixture.
  There is no implemented `TABPACK_OFFLINE` contract to rely on. Keep CUDA-only
  tests behind `gpu` and skip them explicitly when CUDA is unavailable.
- The workflow should run from a clean checkout and should not depend on files
  generated by a prior job. Pip cache may speed installation but must not be a
  source of datasets or checkpoints.

## Integration advice

The coordinator should add the workflow only after the package metadata exposes
a reproducible dev extra (ruff, mypy, pytest, and the CPU-test dependencies),
then replace the placeholders above with the actual package and lock paths.
Before merging, run the exact five commands locally on Windows and Linux/WSL
where available, and verify that a fresh run performs zero data/checkpoint
downloads. Keep the smoke suite separate from the full pytest invocation so a
missing smoke gate cannot be hidden by a broad test glob.
