## Established facts

| Question | Evidence-backed answer |
| --- | --- |
| Dataset | **Churn Modelling**, identifier `churn`, upstream path `data/churn`; not IBM Telco Customer Churn. |
| Benchmark source | TabPack Table 5 cites TabM (2025). TabM v3 Appendix C inherits this task from Gorishniy et al. (2024). This citation chain does not by itself prove an original CSV publisher or license. |
| Split sizes | **6,400 train / 1,600 validation / 2,000 test**, total 10,000. Preserve published indices and order, not a newly generated 64/16/20 split. |
| Feature counts | Paper: **7 numeric, 3 binary, 1 categorical**, total 11 logical source features. T8's “11 categorical” is a transcription error: HTML math repeats the rendered `1` as `11`, just as `7` appears as `77`. These are not inspected NPY block widths or the one-hot output width. |
| Task and target | Binary classification. Current loader requires source `int64` labels exactly `{0,1}` and treats `1` as positive. Neither paper Table 5 nor the inspected config/report supplies the semantic label name or an original-column mapping; do not certify `Exited=1` from dataset-name familiarity. |
| Official Churn score | **Accuracy**, directly evidenced by the main report's `score == accuracy`; ROC-AUC is a separate report field. |
| Batch size conflict | Paper Table 5 says **128**; pinned Churn config says **256**, corroborated by report `epoch_size=25` for 6,400 rows. Keep both facts visible. |
| Evaluation | Paper conservative protocol selects configurations in a main run and retrains selected configurations for secondary seeds. The local full-workflow reruns use the paper's **optimistic** terminology. |
| Seed discrepancy | Table 14 caption says ten seeds; pinned Churn evaluation config says `n_seeds=5`. T6 reports that those five values reproduce the printed aggregates. State five artifact runs, not ten verified runs. |

The official main report gives validation accuracy **0.87625** versus ROC-AUC
**0.8643926187747397**, and test accuracy **0.857** versus ROC-AUC
**0.8585596382206551**. These are a single upstream main run, not local results
and not the conservative aggregate. Published plain TabPack Churn accuracy
**0.8575 ± 0.0014** in T6 cannot be compared directly with local test AUC.

The report also gives class supports: validation `(1274,326)` and test
`(1593,407)` for labels `(0,1)`. These are **upstream report observations**, not
counts measured from local archive bytes. Train class counts, actual feature
names, missingness and semantic target mapping remain unobserved by T54.

## Current implementation and integration

`tabpack/data.py` fixes the full archive identity, verifies that archive on each
load, compares local member bytes against it, and validates canonical split
counts, `int32` indices, disjoint complete coverage, and class support. Its
train-fitted median/normal-quantile and mode/one-hot preprocessing intentionally
differs from upstream noisy quantiles and all-split numeric-to-binary discovery.
It retains explicit `x_bin` as categorical but does not discover binary columns
inside `x_num`. Do not assume paper feature-type counts describe stored blocks.

`tabpack/core.py` implements validation ROC-AUC selection and probability means.
Decision 9 requires best singleton initialization, strict additions/outer
retention, joint homogeneous checkpointing, zero bias decay, and weights-only
inference checkpoints. The trainer must enforce the test-after-freeze boundary;
a pure metric or loader cannot establish that chronology alone.
