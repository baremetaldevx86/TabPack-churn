# T35 — Checkpoint design review

## Assignment

Design the checkpoint payload and resume semantics for the reduced, Churn-only
experiment. The contract must preserve the resolved configuration and
provenance, packed model and optimizer state, all relevant random state, and
the online greedy selection state. This note is a design review only; no
implementation or training was performed.

## Evidence and scope

The governing local protocol is in `swarm.md`, especially decisions 6–8:
three seeds (`0,1,2`), four base members, at most 100 epochs, patience 16,
independent training permutations, validation ROC-AUC for checkpoint/greedy
choices, and a candidate pool containing current-epoch members plus previous
selected checkpoint snapshots. The coordinator findings identify the pinned
reference revision but require independently authored code. Related notes
read: `docs/agents/T48.md` (run/attempt identity, canonical hashing, source
inventory), `docs/agents/T47.md` (ensemble early stopping, freeze-before-test,
validation-search accounting), and `docs/agents/T16.md` (selector API, trace,
and deterministic ordering). This is a proposed local design, not an audit
of upstream checkpoint behavior.

## Proposed checkpoint contract

Use one run per method/seed, matching T48; a campaign manifest lists the three
seed runs. Use a run-level checkpoint rather than serializing a Python model
object. Store tensor `state_dict`s and primitive metadata in a versioned payload
(for example, `tabpack.checkpoint/v1`) with an adjacent JSON manifest. Model
snapshots referenced by selection must be detached, cloned immutable CPU data,
not live views that training can mutate. Write artifacts on the destination
filesystem, flush/fsync and close them, rename to unique immutable names,
publish the manifest, and finally atomically replace a small `latest` pointer.
This ordering also matters on Windows, where open handles may prevent rename.
Hash actual payload bytes and the previous manifest; never embed a manifest's
own digest within itself. An incomplete transaction is ignored, never treated
as committed. Use a tensor/primitive-only format loadable with
`torch.load(weights_only=True)` or equivalent; do not serialize model classes
or a raw preprocessing object requiring arbitrary class reconstruction.

The top-level shape should be equivalent to:

```text
schema: "tabpack.checkpoint/v1"
run: {
  run_id, attempt_id, method, seed, checkpoint_id, parent_checkpoint_id,
  phase,                         # epoch_end | selection_end
  completed_epoch, next_epoch, global_step
}
config: { resolved, canonical_json_sha256 }
provenance: { ... }
members: [ ... ]                 # metadata and state-key/slice mapping
training_state: { ... }          # packed state once, or independent states
rng: { ... }
selection: { ... }
artifacts: { ... }
```

### `config`

`resolved` must be the fully materialized configuration, not only CLI
overrides. Include the dataset identity and split policy, preprocessing
choices, dtype/device policy, seed list, member count, member IDs and sampled
hyperparameters, architecture/layout (including pack dimension), optimizer,
epoch/batch/patience limits, checkpoint cadence, and selection/tie-breaking
policy. Use T48's `python-json-v1` canonical bytes/hash (finite JSON values,
sorted keys, compact separators, UTF-8, no trailing newline or machine paths).
A resume with a different config hash must fail by default;
the caller may explicitly fork a new run, but it must not append to the old
lineage.

### `provenance`

Record enough immutable identity to distinguish a reproducible continuation:

* local implementation revision, dirty status and T48's source-inventory hash
  covering executed untracked code too (or null with reason such as
  `unborn_repository`), Python/PyTorch/package versions, and deterministic-algorithm
  settings;
* dataset source URL or local source identifier, expected and observed file
  SHA-256, canonical train/validation/test split hashes, and the hash of the
  train-fitted preprocessing artifact (including feature schema/categories);
* sanitized invocation/config origin, run creation time, and requested device
  type. Never place API keys, credentials, or private environment dumps in the
  checkpoint.

Link an immutable input-provenance record, rather than hashing the mutable
running/final provenance manifest into its own checkpoint. The final T48
provenance manifest can then hash the committed checkpoint without a dependency
cycle. Exact resume requires the saved fitted transform or identical transformed
input bytes; its hash alone cannot reconstruct missing learned state. Code,
package, or device changes require a linked fork (see resume policy below).

### `members` and `training_state`

Each base member (one for the ordinary MLP; four for ensembles) gets a stable
member ID and metadata including its resolved architecture/hyperparameters,
initialization seed, and state-key/slice mapping. Store packed state **once**,
not a duplicate full packed optimizer inside each member. Independent models
store one model/optimizer pair per stable member ID. `training_state` includes:

```text
model_state_dict, optimizer_state_dict,
scheduler_state_dict (or null), grad_scaler_state_dict (or null),
training: {
  completed_epoch, global_step, samples_seen,
  stopping_scope, best_epoch, best_val_auc, bad_epochs, stopped,
  best_snapshot_ref, best_selection_refs, validation_evaluation_count
}
```

`model_state_dict` must preserve the packed representation with the pack
dimension first and no hidden sharing between members. The optimizer state
must include parameter names/order and groups, hyperparameters, per-parameter
moments, and step counters (per-member counters where applicable); restoring
only weights is not a valid resume. Preserve shapes, member ordering,
layer/depth/width masks, inactive-lane semantics and dtypes, and validate them
before loading. A map from parameter names to optimizer slots avoids silently
attaching moments to reordered same-shaped parameters.
Include scheduler/scaler state even though the reduced float32 protocol may
leave them null. The best validation snapshot is an immutable artifact or
inline state reference, because patience/selection must not be reconstructed
from a changed future model. The ensemble stopping counter is distinct from
optional diagnostic per-member bests. The ledger specifies no base pruning;
do not introduce per-member stopping via this schema. T47 identifies
ensemble-validation non-improvement as the stopping signal; the coordinator
must freeze each method's stopping scope/rule in config.

### `rng` and sampling state

Capture every source that can affect a continuation:

* Python `random` state;
* NumPy generator/global state when NumPy participates in preprocessing or
  sampling;
* PyTorch CPU state and all CUDA device states (when CUDA is used);
* explicit per-member initialization, permutation and dropout generators and
  their states, with the seed-stream derivation scheme/version;
* data-loader/sampler state, including independent permutation state for every
  member, worker seeding policy, and the epoch to which that state belongs.

For the reduced runner, prefer `num_workers=0` and independent named streams.
At the boundary, set `sampler.next_epoch` and `batch_cursor=0`, and capture each
generator **before** generating that next epoch's permutation. Generate it once
on continuation, exactly as in uninterrupted execution. If the implementation
already materializes future permutations, save their actual tensors and the
post-generation generator state with `permutation_materialized=true`; consume
them once without redrawing. Do not mix these two conventions. Restore all RNG
after model/optimizer construction (which may consume temporary initialization
randomness) but before any evaluation, iterator creation, or resumed training.
Record CUDA device-index mapping; CPU/CUDA state is not interchangeable.
Convert NumPy/Python RNG states into supported primitives or tensors, retaining
generator type, state version, integer widths and cached Gaussian values.

### `selection`

Selection is part of training state, not a post-processing detail. Persist:

```text
protocol_hash, candidate_pool_order,
pool_mode, initial_selection_policy, empty_selection_policy,
current_selected: [{candidate_id, member_id, source_epoch, source_checkpoint_id,
            val_auc, rank}],
best_selected: [...], best_selection_epoch, best_ensemble_val_auc,
pending_candidates,                         # if phase == epoch_end
validation_labels_hash,
candidate_validation_predictions (or immutable cache refs),
selected_ensemble_predictions (or cache ref),
last_accepted_auc, max_size, tie_break_rule, improvement_threshold,
ensemble_bad_epochs, validation_evaluation_count, candidate_counts_by_epoch,
selection_frozen, freeze_epoch, freeze_reason,
selection_trace_ref,                         # scores/winner/rejection by round
snapshot_refs: [{candidate_id, artifact, sha256}]
```

`candidate_id` is stable and includes run/method, member ID and source epoch,
not merely a filename. Preserve full-precision score values used for strict
improvement and the deterministic candidate order used for ties. Every
selected snapshot must remain available by content hash; retention must not
delete it while the run can resume. The current selection (next epoch's pool)
and best historical ensemble (eventual evaluation) must not be conflated.
Snapshots need inference weights/config/masks, not duplicate optimizers. Cache
finite validation probabilities, ordered by validation row and candidate ID,
with dtype, shape, split/order hash and probability-averaging accumulation
order. This avoids recomputing predictions, but identical selection still
requires the same metric implementation/environment. Test labels, test
predictions, or test metrics do not belong in a training checkpoint and must
not influence this state. Null values with explicit reasons represent metrics
not yet available; do not encode NaN/Infinity sentinels in JSON.

## Resume semantics

1. **Legal boundaries.** The simplest required implementation saves only
   `selection_end` checkpoints after the full epoch/validation/selection/early-
   stopping transaction; a crash replays work after the last committed boundary.
   An optional `epoch_end` phase can save selection work separately. Write
   checkpoints only after all members finish an
   epoch. `epoch_end` means model/optimizer/RNG state is complete and the
   current-epoch candidates and validation predictions are frozen, but greedy
   selection may still be pending. `selection_end` means selection has
   completed and selected snapshot refs are frozen. Do not claim exact resume
   from a batch-interrupted file; mid-epoch recovery would additionally need
   gradients, batch cursor, sampler cursor, and loader-worker state and is out
   of scope for the reduced protocol.
2. **Integrity and compatibility.** Resolve `latest` by its committed pointer,
   not file modification time. Check manifest, payload hash, parent identity,
   and referenced snapshot hashes. A corrupt explicitly requested checkpoint
   fails; recovery from an older committed checkpoint must be explicit and
   recorded rather than silently discarding progress.
   Require matching schema, run ID/lineage, config hash, dataset/split hashes,
   preprocessing hash, architecture, optimizer, and selection protocol. Refuse
   missing/corrupt artifacts. Each resume receives a fresh attempt ID with the
   same compatible run identity. A code/package/device/config mismatch requires
   an explicit linked fork with a new run/config/provenance identity. It is not
   an exact continuation. Never overwrite a completed run.
3. **Restore order.** Load metadata and validate it before allocating a new
   run. Construct the exact model/member layout, load model state, optimizer,
   scheduler, scaler, early-stopping state, then restore all RNG and sampler
   state before creating iterators. Move optimizer tensors to the active device
   according to the optimizer's device/counter rules, not by blindly casting
   every state tensor. Constructor initialization is discarded; saved states and
   RNG replace it. Never resample members or refit preprocessing on resume.
4. **Choose the next action.** For `selection_end`, begin exactly at
   `next_epoch`; never retrain `completed_epoch`. For `epoch_end`, replay the
   frozen pending greedy selection from cached predictions/snapshot refs, write
   a `selection_end` checkpoint, and then begin `next_epoch`. Replay must use
   the stored candidate order and strict-improvement rule rather than a newly
   evaluated test set or newly sampled candidates.
5. **Stopping and finalization.** Restore the declared run/ensemble patience
   and best snapshot state. Maximum ensemble size caps a greedy pass; reaching
   four selected candidates does **not** stop epoch training. At the declared
   patience or epoch limit, freeze the chosen best ensemble, save its hashes and
   stopping reason, then evaluate test data and emit a separate immutable result
   linked to that checkpoint. For a frozen/stopped checkpoint, do not train a
   further epoch. A crash may retry that read-only final evaluation using the
   same frozen selection; if a valid final result already exists, reuse it.
   This is logical test-once finalization, not a promise of physical exactly-once
   computation across crashes.

Exact numerical continuation is a tested property of a pinned deterministic
environment, not guaranteed solely by saving RNG. Checkpoints also record
per-attempt elapsed durations, completed batches, and validation counts. A
resumed run's active time excludes downtime and records replayed work; retain
separate attempt durations and do not use it as an uninterrupted speed benchmark.

## Integration advice

The implementation owner should expose a small schema/validation function and
make checkpoint paths relative to the run directory. The results aggregator
should include checkpoint ID, parent ID, config hash, provenance hashes, and
reproducibility level in every row. The provenance owner (T48) should include
the checkpoint schema/hash and selected-snapshot lineage in its artifact
specification; otherwise a valid-looking result can lose its exact selection
history. The selection owner (T16) should use the stable candidate IDs and
prediction caches above. The RNG owner (T34) should confirm that explicit
per-member generator and next-permutation state is sufficient for the chosen
DataLoader implementation.

## Tests run

Not run; this documentation-only task has no checkpoint implementation to
execute. Read back the note and cross-checked its contract against T16/T47/T48.

Required integration acceptance cases (tiny synthetic data, no download):

1. In a fresh process, compare uninterrupted four-epoch training with a two-
   epoch checkpoint plus two resumed epochs for all three methods. Include
   nonzero dropout, independent permutations and nonzero AdamW moments. Under
   the pinned deterministic CPU setup require identical final model/optimizer
   tensors, counters, RNG states, predictions and selection IDs/traces, then
   the same next random draw. Run an analogous short CUDA check if supported;
   record any nondeterminism rather than assuming parity across devices.
2. Interrupt each publication stage: incomplete payload, missing snapshot,
   published manifest but old pointer, and completed pointer. Only a committed
   artifact is resumable; explicit corrupted/mismatched resumes fail with no
   weights or outputs overwritten.
3. Resume just before patience exhaustion and from a frozen checkpoint; verify
   the same stopping epoch and no extra training or adaptive test access. Check
   two snapshots of one member remain distinct and unchanged after further
   optimizer steps.
4. If optional `epoch_end` recovery exists, replay selection once from frozen
   caches and compare its full result with uninterrupted selection. Change
   config, split order, preprocessing hash or parameter/member mapping and
   assert incompatibility; directory relocation alone must be accepted.

  canonical JSON and source inventory contracts. Checkpoint metadata carries
  config/data/source identities and selected member+epoch+snapshot hashes, as
  requested. Please link the final manifest to checkpoint bytes and link the
  checkpoint to immutable input provenance, avoiding a circular final-manifest

* **T47:** read and adopted your freeze-before-test rule, all-prespecified-seeds

  preserve these counters and cannot turn test evaluation into selection.
* **T16/T3/coordinator:** read T16's trace/ordering contract and added its
  per-round trace, counts and stop reason. One integration discrepancy needs
  resolution: T16 describes prior selected snapshots as locked
  `initial_selected`, whereas decision 8 defines them as candidates in the
  next epoch's union pool. Locking a full size-four selection prevents all
  future replacement. Default the online caller to rebuild the union pool and
  reselect; reserve nonempty `initial_selected` for resuming a partial pass, if
  supported. Freeze the agreed pool/initial/empty-selection policy in config
  and checkpoint protocol identity before implementation. The checkpoint
  should not silently choose a different algorithm on resume.
* **T34:** please confirm the chosen runner uses independent named generators
  and checkpoint capture before next-permutation generation, or explicitly
  signals a materialized permutation with its post-generation state.
