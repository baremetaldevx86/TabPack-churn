## Churn-only meaning and implemented trust boundary

The published artifact is a multi-dataset gzip/tar archive. Current T52 code
chooses the **full verified archive, Churn-only extraction** route: network bytes
include the whole archive; only Churn files are published as the dataset. A
range/prefix read cannot verify the full archive hash. There is no verified
Churn-only transport endpoint or separately pinned member-hash route established
by this audit. T28's suggestion that the archive need not be retained does not
describe the implemented loader; T38/T49 correctly distinguish the two routes.

Production APIs are `download_churn_archive`, `extract_churn_archive`,
`acquire_churn`, and offline `load_churn` in `tabpack/data.py`. The default
retained archive is adjacent to the Churn directory. Every load verifies the
whole archive into a private snapshot, derives its member bytes/hashes, and
compares the local directory's exact file inventory and bytes against them.
An editable receipt or `docs/data-source.json` cannot authorize arbitrary bytes.
The compiled constants are the trust anchor. Modifying runtime code changes
that trust anchor and therefore changes source provenance.

Allowed relative Churn payload names:

```text
info.json
y.npy
x_num.npy                    # feature block, if present in verified archive
x_cat.npy                    # feature block, if present in verified archive
x_bin.npy                    # feature block, if present in verified archive
splits/default/train.npy
splits/default/val.npy
splits/default/test.npy
```

The archive prefix is `data/churn/`. This is the implementation's allowlist,
**not an observed archive inventory**. Required metadata/target/split files must
exist and at least one feature block must exist. Concrete shapes, block presence,
member byte sizes/digests, and original feature names remain unobserved.
Canonical acceptance also requires the paper's 6400/1600/2000 split counts,
int32 disjoint complete ordered indices, binary int64 target and both classes.

Implemented limits: 20,000 archive members; 512-byte member names; 512 MiB per
regular member; 64 KiB extended headers; 2 GiB total decompressed stream; ratio
200; 64 MiB retained Churn bytes; 120-second parse deadline. These are configured
safety ceilings, not measured archive characteristics. T52 has fixture evidence
for bounded skipped payloads, sparse/link/path rejection and safe NPY loading;
actual archive compatibility still needs the coordinator's acquisition receipt.
