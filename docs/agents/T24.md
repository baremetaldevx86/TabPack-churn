# T24 — Data leakage and preprocessing tests

## Assignment

Design small, deterministic tests that fail if split-specific preprocessing is
fit on validation/test rows, if a split is contaminated, or if categories are
encoded inconsistently. This note is a test/coordination specification only;
no implementation source or test file was changed because the repository does
not yet contain the preprocessing implementation.

## Test fixture

Use one fixture with an explicit `row_id`, two numeric columns, two categorical
columns, and a binary target. Keep `row_id` and target outside the feature
matrix passed to the preprocessor:

`NA` denotes numeric NaN or the loader's documented categorical missing marker.
The ID is synthetic source lineage, assigned before splitting.

| Split | row_id | age | income | plan | region | y |
| --- | --- | ---: | ---: | --- | --- | ---: |
| train | tr-0 | 20 | 10 | basic | north | 0 |
| train | tr-1 | 30 | 20 | basic | north | 1 |
| train | tr-2 | 40 | 30 | basic | south | 0 |
| train | tr-3 | 50 | 40 | plus | north | 1 |
| train | tr-4 | 60 | 50 | plus | south | 0 |
| train | tr-5 | NA | 60 | NA | NA | 1 |
| validation | va-0 | 10000 | -10000 | validation_only | north | 1 |
| validation | va-1 | 10001 | -10001 | basic | south | 0 |
| validation | va-2 | NA | NA | NA | NA | 1 |
| test | te-0 | 20000 | -20000 | test_only | south | 0 |
| test | te-1 | 20001 | -20001 | plus | north | 1 |
| test | te-2 | NA | NA | NA | NA | 0 |

The train medians are exactly `[40, 35]`; categorical modes are uniquely
`[basic, north]`; learned category sets are `{basic, plus}` and `{north, south}`.
With full one-hot blocks and no added indicators the width is six. Derive
block indices from metadata rather than assume column ordering. Every split
contains both classes; labels are never used to construct preprocessing.

The extreme holdout values must not be clipped or replaced in the fixture:
they are sentinels for detecting fitted statistics and learned category
vocabularies. A second copy of validation/test should replace only the
sentinel feature values and categories; train rows must be byte-for-byte
unchanged. Also make a mode-flip variant by setting every observed holdout
category to `plus`/`south`; a concatenated fit would then change both modes.
Fix preprocessing RNG and cap quantiles at train size for this tiny fixture.

## Required tests

### 1. Split IDs are disjoint

`test_split_row_ids_are_disjoint` should assert pairwise disjoint sets of
`row_id` for train, validation, and test, and that their union has the expected
number of rows; require no repeated ID within each split. Check returned IDs,
feature rows, and labels against the fixture's original ordered triples. Add a
negative fixture that copies `tr-0` into validation preserving its source ID;
validation must reject it before preprocessing. IDs must not be regenerated
from `(destination_split, offset)` after copying, which hides contamination.

Canonical arrays may lack global source IDs. In that case verify canonical
file identities, roles, row order, and counts instead, and report that source
entity overlap is unverified. Equal feature rows can be legitimate independent
observations: report exact cross-split duplicates diagnostically rather than
automatically deleting them or claiming row hashes prove entity disjointness.

### 2. Fitted state is train-only

`test_preprocessor_fit_state_ignores_holdout_rows` must invoke the production
data-preparation entrypoint accepting all three splits, then record its learned
state: numeric imputer statistics, numeric transform quantiles/scales, categorical imputer
statistics, learned category lists, output feature names, and output width.
Invoke that same entrypoint afresh with the same train rows while replacing
validation only, test only, and both splits in separate cases. The train state and
`transform(X_train)` must be identical. The test must fail for an
implementation that fits on `concat(train, val, test)` or fits one pipeline
per split. Compare every returned split to an independent reference transform
fit on train only. Spy on the preprocessing fit boundary to assert exactly the
six train rows are supplied and no holdout-specific fit occurs; fitting only a
standalone estimator in this test would miss leakage in orchestration.

Where the implementation intentionally hides estimator internals, compare a
stable preprocessing fingerprint (serialized learned state or feature names
plus transformed train and shared probe values) exposed by the data-preparation
result. Probe every fitted transformer with identical raw inputs, including
missing values and known categories, to catch separate per-split scaling even
when widths agree. Compare canonical learned parameters, not serialized object
bytes containing run IDs or timestamps. Do not assert exact quantile
interpolation details; assert independence from holdout-only changes.

### 3. Train statistics, not holdout statistics, fill missing values

`test_missing_values_use_train_statistics` should verify that a missing
numeric value in validation/test is transformed using the train-fitted median
(and then the train-fitted quantile transform), never a median calculated from
the destination split. A missing categorical value must resolve to the
train-fitted most-frequent category. Assert exact medians `[40, 35]` and modes
`[basic, north]`. For an all-missing probe, compare numeric output against a
probe explicitly filled with those medians and category output against the
explicit modes. Prefer checking the learned imputer
statistics and the transformed value relative to an independently transformed
train row rather than relying on a particular transformer class.

### 4. Unknown categories are ignored with a stable schema

`test_holdout_unknown_categories_do_not_expand_or_reorder_schema` should fit
the categorical encoder on train categories only and transform validation/test
containing `validation_only` and `test_only`. Expected invariants:

* transform does not raise;
* validation and test output widths equal train output width;
* feature names/category columns contain no holdout-only category;
* an unknown category contributes an all-zero vector in its categorical
  one-hot block (while a missing value is represented by the train-mode
  imputation category);
* known categories retain the same column/order and encoding in every split.

This is the concrete contract for the project decision that one-hot encoding
uses unknown-category handling equivalent to `handle_unknown="ignore"`.

### 5. Transforming holdouts cannot mutate fitted state

`test_transform_holdouts_does_not_mutate_preprocessor` should fingerprint the
fitted preprocessor, transform validation and test in both orders, and assert
that the fingerprint, output names, and width remain unchanged. This catches
accidental `fit_transform` calls on holdouts and encoders that extend their
vocabulary during `transform`.

### 6. Split-specific outputs share one schema

`test_all_splits_use_train_schema` should assert that train, validation, and
test transformed matrices have the same column count and the same ordered
feature names, and that each split preserves its own row count and row order.
Require finite float32 features under the current project contract. Fitting a
separate scaler/encoder per split should fail this test or the state-invariance
test above.

### 7. Labels cannot affect preprocessing

`test_preprocessing_does_not_fit_from_holdout_labels` should transform the
same feature splits twice while changing only validation/test labels, and
assert the fitted state and all transformed features are unchanged. This is a
small guard against target encoding or accidental use of all labels during
preprocessing. Repeat with train labels flipped as well: the specified median,
quantile, mode, and one-hot transforms are unsupervised, so they must remain
unchanged. No holdout labels may be supplied to fit. Assert target and row-ID
columns are absent from fitted feature names and model inputs.

### 8. Holdout sentinels never enter train-fitted metadata

`test_holdout_sentinels_absent_from_train_metadata` should inspect exported
preprocessing metadata (if produced by the pipeline) and assert that
`validation_only`, `test_only`, and holdout numeric sentinel values are absent
from learned category lists, imputer statistics, quantile breakpoints, and
feature names. This is an additional diagnostic with a clear failure message;
it complements behavioral tests and should not be the sole leakage check.

## Split contamination and evaluation guardrails

The data-preparation result should retain split row IDs or equivalent lineage
metadata. Assert that no ID appears in more than one split after loading,
filtering, imputation, or batching. If cached/preprocessed artifacts are
supported, use a temporary cache key and assert that rebuilding with changed
holdout sentinels yields the same learned train state, without appending holdout
rows to the train artifact. To require changed holdout output, replace an
extreme value with an interior train-range value and an unknown category with
`basic`; two more-extreme values may legitimately quantile-clip to the same
output, and two different unknown categories both encode to zero. Changing
train values must invalidate the fitted-state cache. Full data/provenance hashes
should change with holdout input bytes even when train state stays identical.

Add an all-missing-train numeric/categorical column with observed holdout values
as a separate edge fixture. Agree a train-only policy with T18 (reject clearly,
drop based on train, or documented constant/empty-vocabulary handling); whatever
policy is chosen, it must not infer a median, mode, or vocabulary from holdouts.

Calibrate assertions against deliberate local test doubles: fit on concatenated
splits, fit a transformer per split, expand category vocabulary on transform,
and inject a copied train source row. Each applicable assertion must fail.
These are short CPU-only test-double checks, not edits to production code.

The test suite should never use the test labels to select a checkpoint, fit a
transformer, tune a threshold, or choose a greedy ensemble member. A small
integration-level assertion can run preprocessing plus selection on a fixture
where validation and test labels disagree, then verify that selection inputs
contain validation labels only and that test labels are used for scoring only
by the final metric call. Initial label-schema validation is allowed. If
selection APIs are not yet present, leave this as a
follow-up owned by the selection-test agent rather than duplicating it here.

## Suggested pytest organization

Place these tests in the preprocessing/data-validation test module owned by
T24 (for example, `tests/test_preprocessing_leakage.py`) once T18 exposes its
public data-preparation API. Keep the fixture local and dependency-light;
there is no need to download Churn data or train a model. Use deterministic
values and a small temporary directory only for cache tests. Mark any API
adapter needed during integration with a concise comment rather than silently
weakening an assertion.

## Integration advice

Run this suite before any model/evaluation integration. A failure reporting a
holdout sentinel in fitted metadata should be treated as a release blocker,
not fixed by changing expected values. The fixture is synthetic and test-only;
it does not replace validation against the canonical Churn train/validation/
test files.
