# T20 — Results schema and aggregation/reporting design

## Assignment and evidence

Agent: `agent-20`. Deliver a documentation-only contract for per-seed/per-model ROC-AUC, log-loss, timing, selected snapshots, and environment provenance. The coordinator owns implementation/integration.

Sources read: `swarm.md`, particularly decisions 6–8 (provisional reduced budget, fixed Churn splits, validation-driven selection, checkpoint identity); `.gitignore` (raw `runs/`, data, and checkpoint files are ignored). There was no implementation to audit at initial inspection. This is an independent proposed schema, not a claim about upstream output formats or measured results.

## 1. Authoritative artifacts

- `runs/<experiment_id>/manifest.json`: versioned experiment manifest, expected seeds/methods, resolved common protocol, data/split identity, and referenced environment records.
- `runs/<experiment_id>/<run_id>/result.json`: one immutable result attempt for one seed and one method, written atomically after validation. Preserve failed attempts as explicit failures.
- `runs/<experiment_id>/<run_id>/members.json`: resolved settings for every trained base member, indexed by stable member ID; use a content hash in `result.json`.
- Derived `runs.csv`, `selected_members.csv`, `summary.csv`, and `report.md`: regenerated from validated JSON, never treated as independent measurement sources.
- A committed, secret-free small report/provenance bundle is needed if final evidence should survive cloning: the current ignore rules omit `runs/`. Coordinator chooses that destination, for example `reports/<experiment_id>/`.

Use UTF-8, strict JSON with finite numbers only (`allow_nan=False`), explicit `null` for unavailable values, and a positive integer `schema_version` initially `1`. Reject unknown schema versions instead of guessing. Serialize sorted keys for deterministic artifacts; store unrounded float values and round only presentation. Hashes use SHA-256 of canonical serialized content or exact file bytes, with the rule recorded. Avoid hashing an object including its own digest. Atomic write means a temporary sibling file followed by replacement; the aggregator ignores temporary files.

## 2. Result contract

Paths below denote nested JSON fields. All times are nonnegative seconds, epochs are zero-based, and seeds are integers. `method` is one of `mlp`, `independent_mlp_ensemble`, `packed_heterogeneous_ensemble`; human-readable labels are presentation only.

| Fields | Required meaning |
| --- | --- |
| `schema_version`, `experiment_id`, `run_id`, `attempt` | Version plus unique experiment/run IDs and nonnegative retry number. A run ID identifies one attempt, not merely a seed. |
| `seed`, `method`, `status` | Status: `complete`, `failed`, or `cancelled`. In-progress artifacts use a separate progress file. |
| `protocol_id`, `comparison_hash`, `method_config_hash`, `resolved_config_sha256` | Explicit protocol label and hashes described below. |
| `data.dataset_id`, `data.role`, `data.manifest_sha256`, `data.split_sha256`, `data.preprocessing_sha256` | Dataset identity, `real` or `synthetic_test_only`, and exact input/split/preprocessing provenance. Include class encoding and train/validation/test row counts in the referenced manifest. |
| `source.commit`, `source.dirty`, `source.diff_sha256`, `source.bundle_sha256` | Local revision; nullable commit for an unborn repository. Dirty-tree/uncommitted source requires an exported source/diff artifact digest for exact recovery. No invented commit. |
| `environment_id`, `environment_sha256`, `timing_protocol_id` | Link to the environment record and precise timing method. |
| `provenance_path`, `provenance_sha256` | Relative finalized T48 provenance path and byte digest; provenance does not hash this result back. |
| `started_at_utc`, `finished_at_utc` | ISO-8601 UTC timestamps for provenance; elapsed measurements use a monotonic clock. |
| `metrics.validation`, `metrics.test` | Each split contains `n`, `n_positive`, `roc_auc`, `log_loss`, and metric definitions/version. Validate `0 <= AUC <= 1`, finite nonnegative log-loss, and split counts against the manifest. |
| `selection` | Frozen selection contract below. Validation metrics here describe the final frozen predictor, not the best scalar from a different epoch/model. |
| `training.epochs_completed`, `training.stop_reason`, `training.base_member_count`, `training.member_manifest_sha256` | Actual work, e.g. `patience`, `max_epochs`, or failure. Record per-member epochs/stopping where execution differs. |
| `timing` | Phase boundaries and timings below. Missing phases are `null`, not zero unless measured zero. |
| `artifacts` | Workspace/bundle-relative paths and hashes for config, member manifest, checkpoint, predictions if retained, and provenance. |
| `error` | `null` on success; otherwise stable error code, phase, and short sanitized explanation. |

Metric definitions include positive label, probability interpretation, numerical dtype, log-loss clipping epsilon, and metric implementation/version. Metrics use final probability averages, not averages of member AUCs/losses. Canonical binary test/validation splits must contain both classes for a `complete` comparison result. An undefined AUC is `null` plus a diagnostic and makes the run ineligible for the primary complete comparison; do not encode it as 0, 0.5, or NaN. Failed/cancelled runs may retain partial metrics but are excluded from primary summaries.

### Hashes and grouping

`comparison_hash` identifies the common experimental plan: dataset/splits, preprocessing policy, expected seeds, all compared method configurations, evaluation/selection definitions, numerical policy, and budget. It excludes timestamps, attempt IDs, environment paths, and the currently executing seed. `method_config_hash` identifies one method's fixed settings and member-sampling distribution with the current seed and its realized random draws excluded. `resolved_config_sha256` covers the exact per-run config, including seed and sampled member settings. These distinctions prevent accidentally creating one summary group per seed or merging different scientific protocols.

Quality summaries group by `(comparison_hash, method, method_config_hash, source_identity, numerical_environment_group)`. Runtime/resource summaries additionally require matching hardware and timing protocol. Environment group is an explicit manifest field derived from software/backend/dtype/determinism settings, not an arbitrary hostname. Mixing hardware even for quality needs an explicitly labeled analysis; default reporting keeps environments separate.

## 3. Selected-member identity

`selection` contains `policy`, `metric: "roc_auc"`, `split: "validation"`, `direction: "maximize"`, `frozen: true`, `frozen_at_utc`, `selected_snapshot_count`, `selected_unique_member_count`, and ordered `members`. Each selected entry contains:

```json
{
  "rank": 0,
  "snapshot_id": "member-0002@epoch-0017",
  "member_id": "member-0002",
  "epoch": 17,
  "weight": 0.5
}
```

This is a fragment illustrating identity, not a measured result or a full selection. A two-snapshot equal-weight ensemble assigns weight `0.5` to each. Every snapshot references its base-member configuration and a checkpoint artifact hash. Snapshot IDs must be unique within a selection; base-member IDs may repeat across epochs. Do not deduplicate on `member_id`: the online pool can retain earlier snapshots of the same member. Equal probability averaging requires nonnegative equal weights summing to one; selection order is retained even though prediction averaging is order invariant. `selected_unique_member_count` can be smaller than snapshot count.

For an ordinary MLP, record its chosen checkpoint as a one-entry selection with weight 1. For an all-member independent ensemble, record the actual chosen checkpoints and an explicit `all_members` policy; do not imply greedy selection unless it happened. A `complete` ensemble cannot have an empty selection. Member metrics and individual greedy-candidate scores are optional diagnostics and must not appear as extra independent seed results. Test evaluation occurs only after selection is frozen.

## 4. Timing and provenance

Keep one phase timing tree so users cannot accidentally add nested measurements twice:

- `timing.fit_wall_s`: training loop including validation, checkpoint/early-stopping decisions, and online selection; excludes dataset download and preprocessing.
- `timing.validation_wall_s` and `timing.selection_wall_s`: diagnostic sub-times inside `fit_wall_s`; never add them again to fit time. If measured separately, selection excludes validation prediction generation.
- `timing.final_test_predict_wall_s`: frozen predictor forward pass on the test set, including probability averaging, with batch size, repetitions, warmup rule, and transfer boundary recorded.
- `timing.final_test_metrics_wall_s`: ROC-AUC/log-loss calculation after prediction, distinct from model inference.
- `timing.preprocess_wall_s`, `timing.setup_wall_s`, `timing.artifact_write_wall_s`, `timing.run_wall_s`: explicitly bounded enclosing stages; report shared preprocessing once at experiment level rather than charging it selectively to methods. Run wall is independently measured, not asserted to equal a sum of rounded stages.
- Record CPU monotonic-clock timing, CUDA synchronization before/after wall-clock intervals when applicable, device, execution order, CPU thread counts, and any concurrent load. Optional CUDA-event timings are additional device-only measurements, not substitutes for wall time.
- A homogeneous ensemble's elapsed training time is its measured total execution path. Do not divide by member count or sum overlapping member wall clocks. Record serial/parallel execution policy.
- On resume, record invocation timing segments and `resumed_from`; report total work across all attempts needed to produce the final run. Otherwise exclude resumed timings from clean-run runtime comparisons and label them. Never silently present only the final invocation as total fit cost.

The environment record should include Python/platform/OS version and architecture; package versions for NumPy, SciPy, scikit-learn, PyTorch and CUDA runtime/cuDNN where used; accelerator name/driver and available memory; CPU model/logical count/thread settings; requested and effective dtype/device; deterministic algorithms, cuDNN benchmark/deterministic settings and TF32 controls; and seed-stream policy. Record collection failures as unknown. Hardware information previously stated in the ledger is provisional context, not a substitute for collection at measurement time. Use an allowlist: do not copy all environment variables, credentials, usernames, hostnames, absolute home paths, or unrelated system logs.

## 5. Aggregation and CSV exports

1. Load only manifest-declared result artifacts; validate schema, identity, finite values, checksums, selection consistency, and artifact status. Reject booleans/numeric strings in JSON metric fields and duplicate JSON keys. Report unexpected files separately. Empty input without an expected manifest is an error; with a manifest, emit declared zero-success groups and fail the strict completion gate. Malformed results are errors, not missing observations. Progress artifacts may explain pending runs but cannot contribute metrics.
2. Match exactly the manifest's expected `(seed, method)` matrix. The provisional 3-seed/3-method plan expects 9 eligible runs; read the final manifest rather than hard-coding 9. Missing, failed, cancelled, duplicate, and incompatible runs appear in an explicit diagnostics table.
3. Never choose the best test score among retries. Multiple complete attempts for the same logical key require an explicit manifest `accepted_run_id` with reason or cause an ambiguity error. Failed attempts remain visible. A resume chain is one logical run, not extra seed observations.
4. For each model/split/metric compute unweighted seed mean and sample standard deviation, `sqrt(sum((x - mean)^2)/(n - 1))`. For `n=1`, standard deviation is `null`; for `n=0`, both mean and standard deviation are `null` and the group is incomplete. Report `n_expected`, `n_complete`, per-field `n_observed`, and the included seed list. Optional missing timings reduce only their own observed count; required final quality metrics missing from a claimed complete run are validation errors. Do not weight by split row count or pool cross-seed predictions. Sort observations by numeric seed before reductions and use stable summation/two-pass variance rather than subtracting large raw moments.
5. Default scientific report requires the full matrix. A diagnostic partial report may calculate available-run summaries but must be marked incomplete and cannot silently compare models on different seeds. Pairwise deltas use only the explicitly listed seed intersection; include excluded seeds.
6. For AUC compare `candidate - baseline`; for log-loss also retain `candidate - baseline` with “negative is better.” Compute mean/sample SD of paired deltas, not a difference of independent standard errors. Timing speedup is `baseline_seconds / candidate_seconds` on matched conditions; zero/missing denominators yield unavailable speedup. Distinguish mean per-seed ratios from ratio of means.
7. Keep validation and test rows separate; label validation estimates selection-optimistic. Do not pick the reported model or alter configuration based on the test table. With only three seeds, report descriptive dispersion, no automatic significance/star labels or claims of split-population uncertainty.

Suggested CSV columns (UTF-8, stable header order, standard CSV quoting, LF or documented line ending):

```text
runs.csv:
experiment_id,run_id,attempt,comparison_hash,seed,method,status,environment_id,validation_roc_auc,validation_log_loss,test_roc_auc,test_log_loss,fit_wall_s,final_test_predict_wall_s,run_wall_s,base_member_count,selected_snapshot_count,selected_unique_member_count,result_path

selected_members.csv:
experiment_id,run_id,seed,method,rank,snapshot_id,member_id,epoch,weight,member_config_sha256,checkpoint_sha256

summary.csv:
comparison_hash,method,method_config_hash,source_identity,environment_group,timing_protocol_id,split,metric,unit,n_expected,n_complete,n_observed,seeds,mean,sample_std,complete
```

CSV stores numbers as numeric strings, booleans as `true`/`false`, null as an empty field, and seed lists as a compact JSON array inside a quoted CSV cell. Do not write `nan`, `None`, or a zero sentinel. Keep nested lists out of `runs.csv`; selection details belong in the normalized member table. Restrict free-form text columns to known identifiers/relative paths and neutralize spreadsheet formulas if exporting untrusted error text; retain exact text only in JSON. Sort run rows by declared method order, numeric seed, attempt, run ID; selection rows additionally by rank; summaries by method, split, metric. Normalize exported paths to relative forward-slash paths.

The Markdown report starts with protocol/reduction label, data identity, expected/completed runs, and environment. Then show every seed/model's test AUC, test log-loss, fit seconds, inference seconds, selected snapshots, plus seed mean ± sample SD; link the separate validation table, selection table, manifest, and failures. Metric units are AUC in `[0,1]`, log-loss in natural-log units/example, and timing in seconds. Display AUC/log-loss to four decimals and seconds with suitable precision, but never round before aggregation.

## 6. Verification status and proposed acceptance cases

No source implementation, runtime tests, dependency installation, training, or measurements were performed for T20. This note is a design artifact; all acceptance cases below are pending implementation.

- Three AUC values `[0.70, 0.80, 0.90]` produce mean `0.80` and sample SD `0.10`; singleton SD is null. Use tolerance for binary floating-point values.
- Shuffled input order produces the same sorted JSON/CSV summaries. Different methods or comparison hashes never merge; seeds differing only in the current run seed aggregate correctly.
- Duplicate logical runs error unless manifest resolution is explicit; missing/failed runs produce diagnostics and incomplete status; no seed silently disappears.
- Repeated member ID at different epochs survives JSON/CSV round-trip as distinct snapshots; repeated identical snapshot ID is rejected. Empty successful ensemble is rejected.
- Missing timing remains null; literal NaN/Infinity, negative timings, out-of-range AUC and infinite log-loss are rejected; undefined AUC is diagnosed without fabrication.
- Paired comparison aligns seed IDs rather than row positions and reports missing pair members. Aggregation averages per-seed AUC, never pooled predictions/member metrics.
- Header order, JSON quoting inside CSV, non-ASCII relative paths, and empty nullable cells round-trip correctly. JSON output is strict and atomic; partial temp files are ignored.
- Resumed segments cannot be double-counted as independent runs; nested timing fields are not added into fit time; incompatible timing environments do not produce a speedup.
