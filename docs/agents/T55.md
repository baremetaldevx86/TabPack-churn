## Reconciliations

- T49's older proposed config/lock/data-root flags are superseded here by the
  task's concrete `--data-dir`, `--output`, and report `--run-dir` interface.
  No nonexistent YAML config, hashed lock, `--resume`, or `--device auto` is
  advertised. The existing base requirements are version pins, not a complete
  transitive hash lock. PowerShell checks native exit codes and directly invokes
  `.venv\Scripts\python.exe`, without activation-policy changes.
- T31's larger proposed mypy/format/special-smoke workflow is narrowed to the
  assigned installed-tool contract. No type checker, extra marker set, separate
  test filename, or environment offline flag is invented. Current GPU tests
  have `gpu` markers and download tests replace transport with fixtures.
- T52's retained full-archive trust anchor is explained explicitly: default
  offline loading requires `data/tabpack-data.tar.gz`, not just extracted
  `data/churn`. Existing destinations are not overwritten; an existing valid
  dataset should go straight to dry-run. No real acquisition success is claimed.
- T53's actual stable pool order is adopted: prior selected snapshots then
  current members. Best singleton always, strict inner improvement, strict outer
  incumbent retention, and snapshot-ID rather than member-ID replacement.
- T51's model/optimizer state-round-trip primitives do not become an experiment
  resume promise. All final checkpoint guidance uses `weights_only=True` and
  reconstruction metadata; prediction files remain local.
- T4/T29/T32's official accuracy versus local AUC, optimistic/conservative,
  train-only fitting, adaptive validation reuse, unequal compute/capacity,
  all-seed sample-SD reporting, and descriptive/no-significance limits are kept
  prominent. No embeddings, Muon, or pruning are added.
