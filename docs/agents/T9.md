## What the pinned official implementation actually does

### Hybrid default

- `main` creates Muon groups only for each backbone block's `linear.weight`. The output head, biases, and feature embeddings use the AdamW branch. This is not Muon on every matrix or plain AdamW everywhere.
- AdamW defaults are beta1 `0.9`, beta2 `0.999`, epsilon `1e-8`. Muon defaults are momentum `0.95`, five Newton–Schulz iterations, Nesterov enabled. `muon_lr` and AdamW `lr` are independently sampled.
- Decay is decoupled: multiply parameters by `1 - lr * weight_decay`, using the learning rate of that branch. The same sampled decay coefficient therefore produces different shrinkage rates in the Muon and AdamW groups.
- Biases get decay zero. Backbone weights and output weights ordinarily receive sampled decay; normalization/embedding exceptions matter if those layers are later introduced.
- Group tensors are broadcast across non-member axes. Moments and momentum buffers have the full packed parameter shape; no mean over members enters optimizer state.
- Both optimizer classes skip an entire parameter when its gradient is `None`; dense zero gradients still trigger moment/step/decay updates. Sparse gradients are unsupported.
- AdamW step state belongs to each packed parameter. With `shared_step=True`, that state is a Python integer shared by its synchronous members, not one global counter for all optimizer parameters. Otherwise it is an int64 vector along the member axis.
- The AdamW branch has a `follow_pytorch=True` arithmetic path; algebraic equivalence does not imply bitwise agreement for every tensor/scalar path.
- Member pruning slices parameter groups, all tensor states, and parameter identities together. It is outside the reduced protocol and should not be partially emulated by masking gradients alone.
- Training averages each member's unreduced loss over samples and sums member losses before backward. The inspected training loop has no clipping or scheduler call. `tabpack-cosine` means cosine feature embeddings, not a cosine LR schedule.

### Pinned-source issues relevant to reuse

1. **Muon scale key mismatch (static finding).** `tabpack.py` passes `muon_scale` in custom groups; `MuonAdamWPack` reads `muon_update_scale`. The latter remains `None`, so the fallback scales from padded matrix dimensions. This appears to defeat the intended actual-shape correction for heterogeneous padded matrices. The paper §5.1 explicitly says varying widths requires patching public Muon implementations. The plain fixed-width/no-embedding Churn config does not itself demonstrate a wrong result from this mismatch. No numerical reproduction of the issue was run.
2. **Scalar validation is not enforced consistently.** For scalar hyperparameters the constructors call the predicate but do not assert its return value; list paths assert it. A local implementation should independently reject nonfinite/negative LR and decay, invalid betas, epsilon <= 0, and wrong vector lengths with explicit exceptions.
3. **Closure semantics differ from stock expectations.** Packed `step` is decorated with `no_grad` and calls the closure without an inner `enable_grad`. The official training path does not use closures. A reduced optimizer can simply omit closure support or implement/test it deliberately.

These are reasons to use upstream as evidence, not to copy its optimizer implementation or claim it is a tested oracle.

## Safe reduced implementation contract

### Elementwise AdamW semantics

For active member `i` and parameter tensor slice `theta_i`, maintain separate `m_i`, `v_i`, and update count `t_i`. For dense gradient `g_i`:

```text
m_i = beta1 * m_i + (1 - beta1) * g_i
v_i = beta2 * v_i + (1 - beta2) * g_i**2
theta_i = (1 - lr_i * wd_i) * theta_i
theta_i -= lr_i * (m_i / (1 - beta1**t_i)) /
           (sqrt(v_i / (1 - beta2**t_i)) + eps)
```

The gradient is computed at the pre-update parameter; increment the relevant counter once per real update before bias correction. Decay must not be added into `g_i` or the moments. Broadcast member LR/decay as `[M,1,...,1]`, never along a layer's output-feature axis.

- Use fixed common betas `(0.9,0.999)` and epsilon `1e-8` initially; per-member LR/decay provide the required optimizer diversity. Record these values explicitly.
- Use stock `torch.optim.AdamW` for ordinary/separate models. For packed parameters, independently implement the elementwise equations with ordinary PyTorch tensor operations. A stock optimizer's tensor-LR option is not a promised vector-of-members interface.
- Choose the same decay-group policy for all three methods. Recommended minimal policy matching upstream's plain MLP grouping: decay weight matrices, including the output head; decay biases at zero. If the coordinator instead chooses decay on all parameters, label that as another explicit reduction and use it consistently in the oracle.
- Keep constant LR, float32 model/gradient/moment state, no AMP/scaler, no Muon and no member pruning. The agreed local LR/decay ranges are new experiment choices, not the paper's ranges.
- A counter shared across members of one packed parameter is sufficient only while those members are updated synchronously from the start. An entire `grad=None` parameter must not advance. Truly paused/restarted members need per-member counters and full-state update masks.
- Structural padding should never influence real coordinates. Permanently unused slots may be held at zero with matching state masks; do not conflate these slots with temporarily paused real parameters. A zero gradient alone does not freeze AdamW weights with existing momentum or decay.
- Do not use a whole-pack gradient norm for clipping; that couples otherwise independent members. No clipping is needed for the agreed initial protocol.
- Keep the sample-mean/member-sum loss. AdamW's approximate scale invariance does not justify averaging over members: epsilon breaks exact invariance and gradients/oracle checks still differ.

### Windows compatibility and numerical risks

| Choice | Assessment for this reduction |
| --- | --- |
| Eager float32 tensor AdamW on CPU | Lowest-complexity target; no custom compiler, distributed process group, or external optimizer dependency required. Still requires local equivalence tests. |
| Same eager operations on CUDA | Reasonable supported design; actual wheel/device execution and finite-update smoke must be checked by T11/coordinator. Installed-version metadata alone does not establish compatibility. |
| `foreach=False, fused=False` on stock oracle | Explicit stable comparison path; avoids silent CUDA foreach selection and extra tensor-list peak memory. If performance runs choose another backend, report it rather than assuming identical timing/numerics. |
| Muon | Unnecessary complexity here: bfloat16 Newton–Schulz matmuls even when outer AMP is off, shape-dependent scaling, extra momentum state, and different parameter groups. Not proven impossible on Windows; simply unverified and out of reduced scope. |
| `torch.compile`, distributed Muon, custom kernels | Not needed to establish packed semantics. The actual official pack calls only the vendor orthogonalization helper; its presence does not mean distributed execution is required. |
| Exact CPU/CUDA identity | Do not promise it. Batched GEMM and rounding may differ; test numerical closeness on each device and record dtype/backend. |

## Tests status and proposed acceptance evidence

**Executed:** read-only paper/config/source inspection and cross-checks. **Not executed:** optimizer unit tests, Windows/CUDA runtime tests, official code, training, installs, or benchmarks. No implementation-level pass is claimed.

T22/coordinator should establish these bounded checks after implementation:

1. Compare several steps with changing signed/zero gradients against independent stock AdamW instances (`foreach=False`, `fused=False`), inspecting weights, moments and counters. Include unequal LR/decay, weights and bias groups, pack size one and multiple members.
2. Isolate decay with a zero gradient and initially zero moments; distinguish `grad=None` from zero after a nonzero-gradient step. Include LR zero, decay zero, and invalid hyperparameter rejection.
3. Compare one member trained alone against the identical member in a larger pack, with identical initial tensors/batches. Adding other members must not change its active gradient or update.
4. Include heterogeneous widths/depths, structural masks, and padding perturbations; verify active regions against separate models. Dropout off or supply identical masks for this oracle.
5. Serialize/reload optimizer state and compare the next step against uninterrupted execution, checking parameter order, device/dtype, member LR/decay and counters.
6. Test CPU float64 as a sensitive arithmetic diagnostic (if supported by the implementation), then float32 CPU; a tiny float32 CUDA check is conditional on verified device availability. Use justified tolerances, not bitwise equality or arbitrary tolerance inflation.
