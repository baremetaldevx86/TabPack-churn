# T38 — Secure dataset download and extraction design review

## Assignment

Review the Churn-only data acquisition path for HTTPS transport, content
integrity, archive/path safety, resource exhaustion, and fail-closed dataset
identity. This is a design review only. No source code, dependency
installation, commit, or training was performed.

## Required secure acquisition contract

### 1. Resolve an allowlisted, immutable source

The downloader should accept a dataset identifier such as `churn`, not an
arbitrary URL in the measured-run path. Its catalog entry should contain:

```text
source_url: https://huggingface.co/datasets/Yura52/tabpack-data/resolve/<revision>/tabpack-data.tar.gz
source_revision: <immutable dataset revision>
expected_archive_sha256: <lowercase 64-hex SHA-256>
expected_archive_size: <integer bytes>
archive_format: tar.gz
```

The candidate values observed above can be used only after T7 confirms the
Churn contents and the meaning of the published LFS digest. Record the source
revision and expected digest as source-published metadata; hash the bytes
actually downloaded independently. A mutable `resolve/main` URL, an ETag, or a
filename is not a substitute for a content digest.

For every request:

* require `https`, certificate/hostname verification, and an exact approved
  host/path (no URL userinfo, fragments, credentials, or unapproved query
  parameters);
* validate **each redirect before following it**, requiring HTTPS and an
  explicitly approved host, with a small hop limit (for example, five). Hugging
  Face can use signed CDN redirect URLs: allow only reviewed HTTPS delivery
  hosts, do not forward credentials across hosts, and never retain signed query
  strings in logs/provenance. Checking only the final URL is too late;
* use finite connect/read/overall timeouts and stream the response to a partial
  file under the cache directory;
* enforce a configured maximum compressed archive size while streaming. A
  `Content-Length` is an early check only, not an integrity proof; chunked
  responses must still be bounded;
* compute SHA-256 and byte count over the received file, then require exact
  equality with the expected digest and size before making it available; and
* write the verified file by atomic rename. Delete a partial or mismatching
  file and fail with a structured error. Do not reuse an existing file merely
  because its name matches.

An unavailable source, missing expected digest, redirect policy violation, or
checksum/size mismatch is a hard acquisition failure. Retrying the same pinned
URL may be reasonable; trying a different dataset, revision, mirror, or local
cache entry without an explicit new source identity is not.

**Full versus partial verification:** verifying the published archive SHA-256
requires all archive bytes. Finding Churn early in a gzip/tar stream, using a
Range response, or stopping after expected members does not verify that hash.
A Churn-only partial acquisition is acceptable only if every consumed member
has a separately reviewed, pinned expected hash/size and exact path, with the
receipt explicitly marking `archive_digest_verified=false`. Otherwise finish
the bounded full download and verify it before parsing, or stop as unverified.
Do not automatically fetch an entire multi-dataset bundle if the chosen
acquisition policy requires downloading only Churn bytes; T7/coordinator must
choose the supported route explicitly.

### 2. Inspect before extraction

The current source is a `tar.gz`; do not auto-detect and execute arbitrary
archive formats. Open it in read-only mode and inspect member headers before
writing any final data. The limits must be explicit configuration and must be
checked both against declared metadata and during extraction:

* compressed archive bytes;
* maximum member count;
* maximum filename and link-target length;
* maximum uncompressed bytes per member;
* maximum total uncompressed bytes;
* maximum permitted compression ratio; and
* nested archive count/depth (zero unless the dataset manifest explicitly
  requires nesting); and
* total decompressed stream bytes and an overall processing deadline, including
  skipped non-Churn payloads and PAX/GNU extended headers.

Use a bounded member iterator rather than unconditionally materializing an
untrusted, unbounded member list. Reject malformed/negative/impossibly large
sizes. A declared total that fits the limit does not remove the need to count
bytes actually written. If any limit is exceeded, abort and remove the entire
temporary extraction tree.

The compressed size has an observed expectation of 189856645 bytes; exact
uncompressed/member limits remain an integration prerequisite pending T7's
inventory. Store concrete ceilings in the approved source lock instead of
shipping unlimited defaults. A compression-ratio check is supplementary: an
absolute decompressed-byte ceiling is the primary bound. Counting only copied
Churn files would leave skipped payloads and extended-header allocations
unbounded; bound the decompressor beneath the tar parser as well.

### 3. Enforce a destination and member policy

Extract only into a newly created temporary directory on the same filesystem as
the eventual data directory. Before extraction, reject or explicitly allowlist
every member name:

* reject absolute POSIX paths, drive-qualified paths (`C:`), UNC paths, leading
  separators, `..` components, backslashes used as alternate separators, NULs,
  control characters, and names that normalize outside the extraction root;
* reject duplicate names and case-folding collisions because the target can be
  Windows and case-insensitive. Reject Windows device basenames, trailing
  dots/spaces, alternate data streams (`:`), and file/directory collisions;
* allow only regular files and necessary directories. Reject symbolic links,
  hard links, FIFOs, devices, and other special members. Link rejection is
  simpler and safer than trying to reason about link order.

Prefer exact allowlisted source-member names mapped to fixed destination
filenames, using bounded `extractfile` copies of regular files only; this avoids
applying archive paths, ownership, permissions, and links to disk. Never call
`extractfile` on a link. If filesystem extraction APIs are used instead, use
`filter="data"` **in addition to** the explicit policy above, with fatal error
handling, and select only reviewed Churn members. Do not use the fully-trusted
filter or `errorlevel=0`, and do not rely on a runtime's default filter.
Never extract directly into a pre-existing data directory: a fresh directory
prevents pre-existing links from affecting path checks and isolates cleanup.
Resolve containment component-wise, never with a string-prefix test; reject
symlink/junction/reparse destinations and keep the staging parent application
controlled. The final promotion should occur only after validation; a failed or
interrupted extraction must not leave a directory that a later run mistakes
for verified data.

Only the approved Churn payload enters the staging tree; known other-dataset
members in the bundle are skipped, with scan limits still enforced. After
extraction, require the exact manifest expected for the Churn source.
Reject missing, extra, duplicate, or ambiguous candidate files rather than
selecting the first filename that happens to match. Hash and size every
consumed split/schema file after extraction. The archive transport digest and
the consumed-file inventory are separate identities: the former proves which
bytes arrived, while the latter proves which data entered preprocessing.

For NumPy arrays use
[`np.load(..., allow_pickle=False)`](https://numpy.org/doc/stable/reference/generated/numpy.load.html)
with bounded headers and checked shapes/dtypes/payload lengths; refuse object
arrays rather than enabling pickle. T18 specifies full arrays plus split-index
files, not necessarily separate train/val/test feature files. Hash the verified
buffers actually handed to the loader, avoiding a hash-then-reopen race. Do not
execute files discovered in an archive.

### 4. Fail closed on dataset identity

The validator must establish all of the following before training:

1. the source URL/revision and applicable archive/member verification route
   match the approved dataset entry;
2. the extracted file inventory and expected Churn split roles are exact;
3. required columns, target mapping, row counts, and split IDs/schema pass
   validation; and
4. the train/validation/test file hashes are recorded for provenance.

If the archive is missing Churn, has a malformed or conflicting split, has an
unexpected digest, or cannot be fully validated, stop with an actionable error
and no usable data artifact. Never fall back to IBM Telco, synthetic data, a
newer `main` archive, a stale cache, or a different file with a similar name.
Synthetic data may be used only by an explicit test-only fixture path and must
be labeled as such; it must never satisfy a real `dataset=churn` request.

A manually supplied local directory should still be checked against the same
canonical file/schema/split manifest and per-file hashes. An unverified local
directory can be diagnosed, but must not be accepted as measured-run evidence
by silently disabling checksum or identity checks.

## Acceptance tests for integration

The downloader/extractor should have small fixture tests for:

* rejecting `http`, unapproved hosts, credentials, invalid redirects, and
  missing expected digest;
* accepting a correct fixture only after exact SHA-256/size verification,
  deleting partial files on a wrong digest, never trusting ETag alone, and
  never marking a prefix/Range response as whole-archive verified;
* rejecting `../escape`, absolute, drive/UNC, backslash, control-character,
  symlink, hard-link, device, duplicate, and case-collision archive members;
* rejecting member-count, per-member, total-size, ratio, and nested-archive
  limit violations, including a small decompression-bomb fixture;
* leaving no final data directory after a mid-extraction failure; and
* refusing an archive with no exact Churn manifest and proving that no IBM
  Telco/synthetic fallback path is invoked.

Tests were not run: the checkout has no implementation or dependency files yet.
These are release-blocking security/provenance checks once the downloader is
implemented.
