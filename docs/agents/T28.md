## Assignment

Draft an end-to-end outline for reproducing the independent Churn-only comparison:
ordinary MLP, homogeneous independent MLP ensemble, and reduced heterogeneous

coordinator lands the final package name, CLI, and output schema.

## Reproduction workflow

### 1. Preflight

1. Start from a clean checkout of the repository and record the commit:

   ```powershell
   git rev-parse HEAD
   git status --short
   ```

   The working tree should be clean before a measured run. Do not include API
   keys, private paths, or local logs in a report.

2. Confirm the host has Python 3.12 (or the version pinned by the eventual
   lock/requirements file), enough disk space for the dataset/cache and run
   artifacts, and a usable CPU. CUDA is optional; first reproduce on CPU or
   explicitly record the selected CUDA device.

3. After environment installation, run the project's safe diagnostic/preflight
   command (proposed shape: `python -m tabpack.cli preflight --config configs/churn_reduced.yaml --data-root data/churn --device cpu`). It should
   report Python, PyTorch/device availability, writable artifact/cache paths,
   and dataset presence without downloading data or starting training.

4. Before acquisition, a missing dataset is an expected diagnostic. After
   acquisition, require the data-validation gate to pass before training.
   Verify canonical official Churn identity and preserved train/validation/test
   splits; missing, malformed, or unverified data must not trigger silent
   substitution with IBM Telco or synthetic data.

5. Capture the experiment inputs: commit SHA, platform, Python/PyTorch versions,
   device, dataset identifier/hash, configuration file, and the seed list.

### 2. Environment installation

Create an isolated environment; do not rely on globally installed packages.
The coordinator must name the actual pinned dependency file, package module,
and supported CPU/CUDA PyTorch wheel source. Use the venv interpreter directly;
activation is optional and unnecessary for these examples.

```powershell
py -3.12 -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install -r "<PINNED_REQUIREMENTS_FILE>"
& ".\.venv\Scripts\python.exe" -m pip install --no-deps -e .
& ".\.venv\Scripts\python.exe" -m pip check
& ".\.venv\Scripts\python.exe" -m tabpack.cli --help
```

The editable-install command presumes packaging support and a separately
installed complete pinned environment; replace it with the actual supported
installation path if different. Install a CUDA-enabled PyTorch build only
using the tested project instructions. Confirm CUDA with an actual small
tensor operation, not availability detection alone. T12/T11 must supply the
verified versions/wheel source before publication.

For the remaining templates, `python` means this same isolated interpreter.
The run manifest should collect dependency names and versions from the active
interpreter using structured metadata, following T48. Avoid publishing raw
`pip freeze` output, which can include editable local paths or direct URLs.

### 3. Data acquisition and validation

1. Create a dedicated data directory outside source control, for example
   `data\churn`.
2. Use the project's explicit Churn-only downloader once its command is
   finalized; T41 intentionally keeps acquisition separate from `run`. Prefer
   HTTPS and verify the documented checksum or manifest. No acquisition CLI has
   been established in the notes reviewed, so supply it here during integration.
3. If the dataset is supplied manually, place only the documented files in the
   data directory and pass an explicit path. Record public source/revision and
   hashes of every consumed file. Retain an archive hash if an archive was used;
   do not require the whole multi-dataset archive for a Churn-only run. Label a
   locally observed digest separately from an independently published checksum.
4. Rerun the proposed `preflight` command after acquisition.
   Confirm required columns, binary target encoding, row counts, duplicate or
   malformed-row policy, and the canonical split identity.
5. Confirm preprocessing is fit on the training split only: numeric median
   imputation plus quantile-normal transformation, and categorical most-frequent
   imputation plus one-hot encoding with unknown categories ignored. Save the
   resulting data manifest/preprocessing summary with the run.

### 4. Dry run

T41 defines `dry-run` as nontraining execution-plan resolution. Inspect its
data fingerprint, planned methods/seeds/members, resolved device, budgets,
and expected artifacts:

```powershell
python -m tabpack.cli dry-run `
  --config "configs\churn_reduced.yaml" --data-root "data\churn" --device cpu
```

Then run the offline all-path synthetic smoke test described by T42 after its
implementation exists. It uses tiny canonical fixture splits and the real
orchestration; its manifest must say `synthetic_smoke_v1`/test-only. Synthetic
success confirms pipeline wiring and checkpoint replay, not a Churn result.
Publish its exact pytest command only after the test file is integrated.

Then perform a short real-Churn readiness run using the same loader, model
paths, metrics, checkpoint logic, and result writer as the full run. T41
proposes `run --smoke` for this training diagnostic; its effective short budget
must be explicit in the manifest and keep original splits intact:

```powershell
python -m tabpack.cli run `
  --config "configs\churn_reduced.yaml" --data-root "data\churn" `
  --run-dir "runs\churn-readiness" --seeds "0" --device cpu `
  --smoke --allow-noncanonical
```

Keep this readiness run out of the measured reduced-run aggregate. Inspect
the following visible outputs; use the dedicated model/optimizer/RNG tests for
internal properties that a log or trace alone cannot establish:

- all three model families construct and execute;
- validation ROC-AUC drives checkpoint and greedy choices;
- probability averaging and strict no-replacement selection execute;
- test metrics are emitted only after selection is frozen; and
- JSON/CSV/manifest artifacts are readable and contain no secrets.

Before claiming correctness, the integrated test suite must also confirm
member-first packing, no parameter sharing, sample-mean/member-sum loss,
independent reproducible member permutations, and train-only preprocessing.
An unimplemented/skipped check is pending, not a pass.

Treat a dry-run failure as a setup failure. Do not interpret its metrics as a
scientific result.

### 5. Full reduced run

After the dry run succeeds, use a fresh output directory and the provisional
reduced protocol from `swarm.md`:

- seeds: `0,1,2`;
- one ordinary MLP, four homogeneous ensemble members, and four heterogeneous
  packed members with maximum selected ensemble size four;
- maximum 100 epochs, patience 16, batch size 256, float32;
- baseline MLP: depth 2, width 64, dropout 0.1, AdamW learning rate 0.001,
  weight decay 0.0001;
- heterogeneous candidates: depths `[1,2,3]`, widths `[32,64,96]`, dropout
  `[0,0.1,0.2]`, log-uniform learning rate `[0.0003,0.003]`, and log-uniform weight decay
  `[0.000001,0.001]`;
- no periodic feature embeddings, Muon optimizer, base pruning, or tuning.

Proposed T41 invocation, with the complete budget in the versioned config:

```powershell
python -m tabpack.cli run `
  --config "configs\churn_reduced.yaml" --data-root "data\churn" `
  --run-dir "runs\<NEW_RUN_ID>" --seeds "0,1,2" --device cpu
```

Run each configuration in a fresh output directory. Preserve the exact
resolved configuration, seed/member assignments, epoch/checkpoint metadata,
validation-selection trace, test predictions or approved summaries, timing,
and environment manifest. Let the run finish all requested seeds before
comparing families. Report this as a reduced TabPack-style optimistic
evaluation; it is not paper-equivalent and should not be described as a full
replication of the paper's compute or results.

The command must also resolve every architecture, sampling, optimizer, and
selection setting listed above through a versioned config/default. Verify the
resolved config rather than assuming the abbreviated example encodes them.
Choose CPU or tested CUDA explicitly and use the same device/timing scope for
all three methods. This provisional budget remains subject to the
coordinator's final decision; measured results must name the effective budget.

### 6. Result inspection

Inspect artifacts in this order:

1. **Manifest/config:** verify commit, dataset hash/split, preprocessing fit
   scope, device/dtype, seeds, member count, budget, and resolved sampled
   hyperparameters.
2. **Run status:** ensure every requested seed and model family completed;
   the provisional plan expects nine eligible `(seed, method)` records.
   Distinguish completed, failed, interrupted, and ambiguous duplicate attempts.
3. **Selection trace:** check validation ROC-AUC, candidate IDs/epochs,
   no-replacement behavior, strict improvement, and that selected snapshots
   are frozen before test evaluation.
4. **Metrics:** compare per-seed ROC-AUC and log-loss for the frozen predictors.
   Ensemble metrics are computed from averaged member probabilities, not
   averaged member scores. Across seeds report the mean and sample standard
   deviation (`ddof=1`), completed/expected counts, and paired-seed differences.
   Three seeds support descriptive dispersion, not broad significance claims.
5. **Resource accounting:** record wall time, peak memory when available, and
   parameter/member counts using the same accounting convention for all model
   families.
6. **Reproducibility:** rerun one seed from the same commit/config and check
   that selected snapshots and predictions/metrics match within the documented
   same-environment tolerance. Timing, run IDs, and timestamps will differ.

Example inspection shapes:

```powershell
Get-Content -LiteralPath "runs\<RUN_ID>\manifest.json"
Import-Csv -LiteralPath "runs\<RUN_ID>\runs.csv" | Format-Table
Import-Csv -LiteralPath "runs\<RUN_ID>\summary.csv" | Format-Table
Import-Csv -LiteralPath "runs\<RUN_ID>\selected_members.csv" | Format-Table
```

T41 proposes the following report command. Do not hand-edit raw artifacts
before reporting; keep test results separate from validation selection records:

```powershell
python -m tabpack.cli report --run-dir "runs\<RUN_ID>" --format markdown --strict
```

T20 proposes authoritative per-run JSON and derived CSV/report files. T48
proposes per-run provenance. The coordinator must reconcile their final paths
and status/schema names before publication. Raw `runs/` artifacts are ignored
by Git; link the eventual retained, sanitized report bundle so a fresh clone
can inspect the reported evidence. Synthetic/readiness/partial/incompatible
runs must not be merged into the full Churn comparison.

### 7. Troubleshooting

| Symptom | Checks and recovery |
| --- | --- |
| `python`/module not found | Activate `.venv`, or call `.venv\Scripts\python.exe`; verify `python -m pip show <package>` and rerun installation. |
| Preflight says dataset missing or invalid | Check the explicit `--data-root`, rerun the documented downloader/validator, and verify checksum/split metadata. Do not substitute another dataset. |
| Download fails or checksum differs | Check HTTPS/network access and the documented source; retain the error and checksum evidence, then stop rather than using an unverified file. |
| Access denied on Windows | Move data/output to a writable user directory, close files held by another process, and avoid protected folders. |
| PowerShell blocks activation | Call the venv interpreter directly, e.g. `.venv\Scripts\python.exe -m <package> ...`. |
| CUDA unavailable/out of memory | Rerun with `--device cpu` or a smaller explicitly documented dry-run override; never compare a partial run to the full protocol. Record the device change. |
| Non-deterministic rerun | Confirm the seed is passed to every RNG, member permutations are independent but reproducible, worker settings are documented, and no stale checkpoint/output directory is being reused. |
| ROC-AUC or metric is undefined | Inspect validation/test labels for both classes and confirm the split/loader was not accidentally filtered or truncated. Preserve the failure in the run log. |
| Selection trace includes duplicate/declining candidates | Treat as an implementation failure: verify candidate identity includes member and epoch, greedy selection is without replacement, and additions require strict validation improvement. |
| Test score appears before selection completes | Mark the affected run invalid and retain it for diagnosis; fix the execution path and rerun into a fresh directory. |
| Run interrupted | Resume only if the CLI's checkpoint/resume semantics are documented and preserve the original manifest; otherwise start a fresh run and mark the interrupted run incomplete. |
