# T32 — Statistical reporting review

## Assignment and scope

Review the reduced Churn experiment's reporting contract for random seeds,
mean/standard deviation/confidence intervals, paired method comparisons, time
measurement, and claim boundaries. This is a research/design note only; no
implementation, installation, training, or long run was performed.

## 1. Observation unit and seed protocol

1. The independent reporting observation is one **complete method × seed run**.
   Members, snapshots, epochs, batches, and validation candidates are nested
   observations and must never be treated as extra replicates. Aggregate
   final predictions on the test split, not member-level AUCs/losses.
2. Freeze the seed list before execution (`[0, 1, 2]` under the current
   protocol), map each seed to every method, and retain the same train/val/test
   split, preprocessing fit, declared method-specific budgets, and metric definitions. Record the
   actual seed list in each result and the expected list in the manifest.
3. Report every prespecified seed's final test ROC-AUC, test log-loss, fit wall
   time, final frozen-predict time, selected snapshot count, and relevant
   stopping/selection metadata. Never report only the best seed, best epoch,
   or best test score.
4. A missing, failed, or cancelled seed is not a zero and does not disappear.
   Show expected, complete, failed, cancelled, and absent counts plus the
   included seed IDs. A primary comparison requires the full declared matrix;
   any partial table is explicitly descriptive/incomplete.
5. A retry is not a new seed observation. Keep all attempts visible and use a
   predeclared, auditable accepted-attempt rule; never select a retry because
   its test metric is favorable. A resumed run is one logical run with total
   work across its segments.
6. Record separate RNG roles: preprocessing, member hyperparameter sampling,
   initialization, dropout, and batch permutations. Fix any stochastic
   preprocessing seed across methods/runs if the intended estimand is training
   variability. Under the optimistic protocol, redraw packed member settings
   independently for each root seed: the resulting dispersion includes both
   hyperparameter-sampling and training/selection variation. If settings are
   instead fixed across seeds, label that different conditional estimand.
   A deterministic seed hierarchy does not imply identical random streams
   across architectures or bitwise portability across devices/versions.

## 2. Per-method summaries: mean, sample SD, and CI

For a method and fixed metric, let `x_i` be the final value from complete seed
`i`, with `n` complete seeds:

```text
mean = (1/n) * sum_i x_i
sample_sd = sqrt(sum_i (x_i - mean)^2 / (n - 1))
```

Use `ddof=1`, preserve full-precision values in artifacts, and round only in
the display report. Report `n_expected`, `n_complete`, and seed IDs alongside
each aggregate. For `n=1`, standard deviation and CI are `null`; for `n=0`,
mean, standard deviation, and CI are `null`. A genuine zero SD is `0.0`.
Never pool test rows, average member metrics, weight seeds by dataset size, or
replace missing measurements with zeros.

The primary compact display should be `mean ± sample SD` for each method and
metric, with all per-seed values in a companion table. A 95% t interval may be
shown as a supplementary descriptive interval:

```text
mean ± t_(0.975, n-1) * sample_sd / sqrt(n)
```

For the current `n=3`, `t_(0.975, 2) ≈ 4.303`, giving a half-width of about
`2.484 * sample_sd`. Exact t coverage assumes independent, normally distributed
run values (or paired deltas); three observations cannot establish that
assumption, especially for skewed runtimes. These intervals concern the mean
over the declared seed-generation procedure under one fixed split/protocol;
they do **not** quantify uncertainty over datasets, alternate splits, future
populations, or hardware, and do not correct validation-selection optimism.
Across-seed dispersion does include variation induced by the stochastic
selection procedure. Do not use a confidence interval crossing (or
not crossing) as an automatic significance rule. With three seeds, omit
p-values/stars and call the result preliminary/descriptive. Bootstrap intervals
are not recommended as a default for only three observations; if ever used,
name the bootstrap method and keep it exploratory.

ROC-AUC is bounded in `[0, 1]`, whereas an untruncated t interval can extend
outside that range. Preserve the calculated interval and label the method if
display clipping is used; do not silently clip values in the artifact. Log-loss
is in natural-log units and is unbounded above, subject to the evaluator's
finite/clipping policy.

## 3. Paired comparisons

Comparisons are paired by the same prespecified seed ID, not by row position or
by independently chosen successful subsets. For candidate `C` and baseline
`B`, use the shared seed intersection `I` and calculate per seed:

```text
d_auc_i      = auc_C_i      - auc_B_i       # positive favors C
d_logloss_i  = logloss_C_i  - logloss_B_i   # negative favors C
d_time_i     = time_C_i     - time_B_i      # negative means C is faster
```

Report each `d_i`, the paired mean delta and paired sample SD over `I`, and
`n_paired = len(I)` plus excluded/missing seeds. For an optional 95% paired t
interval, apply the same formula to the deltas with `df=n_paired-1`. A paired
analysis retains the actual covariance between matched outcomes; estimating
the SD of the deltas is preferable to inferring it from separate model SDs.
Identical seed integers alone do not guarantee positive covariance or common
random draws, so pairing does not automatically reduce uncertainty. It remains a descriptive comparison of
three stochastic runs, not proof of a population-level effect.

The primary headline should use the declared metric direction: “higher mean
test ROC-AUC” or “lower mean test log-loss,” with the paired delta and all seed
values visible. Say “outperformed on all three prespecified seeds” only when
all three paired deltas have the favorable sign and the exact metric/tie rule
is stated. Otherwise use neutral wording such as “had a higher/lower mean in
this reduced run.” Do not infer superiority from a validation score: repeated
validation checkpointing, stopping, and greedy candidate search make that
score selection-optimistic (`T47`).

If one method has only a subset of seeds, a paired diagnostic may use the
explicit intersection, but it must not be the primary full-matrix claim. Do
not compare methods with different split identities, preprocessing fits,
or incompatible protocol IDs under one paired summary. One MLP versus four
ensemble members is deliberately unequal compute/capacity: preserve each
method's declared budget, disclose actual epochs/member work, and describe
this as a workflow comparison, not an equal-compute ablation. A packing-only
speed claim needs a separate matched-member, matched-work independent oracle.

If future larger runs add hypothesis tests, predeclare the primary metric and
comparisons and account for multiple comparisons. More test rows or inference
repetitions cannot substitute for additional independent training seeds. A
test-row bootstrap would address a different, conditional sampling question;
it must preserve paired predictions and be separately labeled, not pooled
with seed SD or treated as a correction for model-selection bias.

## 4. Time measurement and runtime reporting

Record raw per-seed phase times as nonnegative seconds. Use a monotonic host
clock (`time.perf_counter` or equivalent). For CUDA wall time, use the exact
order `synchronize -> start clock -> measured work -> synchronize -> end clock`;
an optional CUDA-event measurement is device-timeline supplementary
data, not a replacement for elapsed wall time. Record device, dtype, CPU model,
thread count, CUDA/runtime/driver, deterministic/TF32 settings, execution
order, and notable concurrent load.

Use a timing tree with disjoint sibling phases and explicit nested children,
consistent with `T20`:

- `fit_wall_s`: training plus validation, checkpointing, early stopping, and
  online selection; exclude download and preprocessing.
- `validation_wall_s` and `selection_wall_s`: diagnostic children of fit;
  never add them to fit again.
- `final_test_predict_wall_s`: frozen final predictor and probability
  averaging on test, with batch size, transfer boundary, warm-up, and
  repetition count recorded.
- `final_test_metrics_wall_s`: ROC-AUC/log-loss computation after prediction.
- `preprocess_wall_s`, `setup_wall_s`, `artifact_write_wall_s`, and enclosing
  `run_wall_s`: separate explicitly bounded phases. Shared preprocessing is
  reported once at experiment level or charged identically by a declared
  policy.

For inference microbenchmarks, perform a declared warm-up before measured
repetitions and report the repetition statistic. For end-to-end fit, include
the normal one-time setup incurred by a real run only when the timing boundary
says so; do not silently omit compilation/library initialization. Never divide
packed or parallel wall time by member count and never sum overlapping member
clocks. Report the actual measured execution path.

`T37` proposes no discarded training warmup and a frozen-inference protocol of
10 complete warmups and 30 measured passes in five blocks. Those repetitions
estimate timing jitter for one fixed fitted predictor; they are not 30 model
seeds. Reduce per-pass/block timings to one declared per-seed summary first,
then aggregate across seeds. Keep metric calculation on the designated frozen
predictions outside the timing blocks; repeated inference does not authorize
repeated test-guided selection. Record execution order; T37's counterbalanced
method order helps limit cache/thermal drift but does not make three timings
a hardware-general experiment.

Runtime summaries use the same seed aggregation convention (mean ± sample SD)
and should additionally expose median when timing jitter is material. Runtime
speedup is only meaningful on matched hardware/software/device/dtype/budget
and timing protocol. For candidate `C` versus baseline `B`, retain both:

```text
per_seed_speedup_i = fit_time_B_i / fit_time_C_i
ratio_of_means     = mean(fit_time_B_i) / mean(fit_time_C_i)
```

Label these separately; they are not generally equal. A zero or missing
candidate denominator gives unavailable speedup. The primary prose should say
“ratio of mean fit wall times” or “mean per-seed speedup,” never an unqualified
“X× faster.” Include paired time deltas when runtime variability is relevant.
Fit time can differ because of architecture, epochs, or selection overhead;
the comparison does not isolate packing alone. CUDA events record elapsed
device-timeline intervals that can include gaps; do not label event duration
as GPU utilization or active kernel time without profiler evidence.
Do not compare training time for one method with inference time for another,
or runtime from unlike hardware as if it were an algorithmic result.

## 5. Claims justified by this experiment

### Justified when the artifacts support them

- “On the fixed canonical Churn split and this declared reduced protocol,
  method C had mean test ROC-AUC `...` across the three prespecified seeds,”
  with per-seed values and sample SD shown.
- “C's paired mean test-AUC delta versus B was `...` over shared seeds,” or the
  equivalent log-loss statement with its direction explicitly stated.
- “Under matched environment and timing boundaries, C's ratio of mean fit wall
  times was `...`,” with raw times and environment provenance available.
- “The final test score was measured after validation-based selection was
  frozen.” This is an evaluation-procedure claim, not a generalization claim.

### Not justified by three reduced seeds alone

- Statistical significance, a reliable population-level superiority claim,
  guaranteed improvement on other splits/datasets, or a causal explanation
  that heterogeneous packing caused the observed difference.
- “State of the art,” “paper reproduction,” or paper-equivalent performance:
  the reduced run uses four members and three seeds, omits several official
  components, and is explicitly labeled reduced TabPack-style.
- Hardware-independent speedup, energy/resource superiority, or a claim that
  packed training is faster merely because it has fewer reported parameters.
- An unbiased validation estimate: validation is adaptively searched and is
  selection-optimistic. Test scores must remain untouched until freeze.
- Choosing the best seed, best checkpoint, best retry, or best test run as the
  headline; these are selection on the reported outcome.

Recommended result sentence:

> Reduced Churn results are a three-seed, validation-selected evaluation. We
> report every prespecified seed and mean ± sample SD; paired deltas use shared
> seeds. The test split is evaluated once after selection is frozen. Runtime is
> matched wall-clock fit time with CUDA synchronization where applicable. The
> findings are descriptive and preliminary, and are not paper-equivalent.
