## Proposed test boundary

Future coordinator-owned tests: `tests/test_config.py` and `tests/test_sampling.py`, adapted to T13's final module names. Use pure CPU, tiny in-memory dictionaries, a temporary config file only for parser tests, and stdlib/pytest facilities already selected by the project. No dataset, network, GPU, model training, or distribution hypothesis tests are needed.

Test public loading/validation and sampling entry points separately. Invalid inputs must fail before model allocation, data loading, or creation of run artifacts. Errors should identify the field and violated condition; assert useful substrings rather than entire exception text. Recommend `ValueError` for a semantically invalid configuration and a documented parser exception for malformed serialization.

## Small reference fixtures

1. **Reduced default:** seeds `[0, 1, 2]`; members `4`; selection limit `4`; epochs `100`; patience `16`; batch size `256`; dtype `float32`; baseline depth `2`, width `64`, dropout `0.1`, learning rate `0.001`, weight decay `0.0001`; heterogeneous depths `[1, 2, 3]`, widths `[32, 64, 96]`, dropouts `[0, 0.1, 0.2]`, learning-rate range `[0.0003, 0.003]`, weight-decay range `[0.000001, 0.001]`.
2. **Minimum:** one seed `0`, one member, one epoch, patience `1`, batch size `1`, depth `1`, width `1`, dropout `0`, fixed baseline weight decay `0`. Keep sampled log ranges strictly positive.
3. **Degenerate legal search space:** one depth/width/dropout choice; equal positive range endpoints. Expected sampling is a deterministic constant hyperparameter vector, while member identities remain distinct. Equal endpoint support is a recommended contract requiring T13 confirmation.
4. **Single-field invalid variants:** copy the valid fixture and alter exactly one field. This prevents an unrelated failure from satisfying an assertion.

Use direct in-memory `float("nan")` cases even when the selected config parser already disallows nonstandard JSON numbers. Apply numeric/type cases to each independently validated field, not just the first representative.

## Deterministic sampling matrix

| ID | Cases | Expected oracle |
| --- | --- | --- |
| S01 | Sample the same config and seed twice, with unrelated RNG draws between calls | Entire ordered member records match, including identities, hyperparameters, and derived seeds. Sampling must not depend on call history. |
| S02 | Sample seed `0`; sample seed `1`; repeat each | Each seed reproduces itself. Assert selected nondegenerate known vectors differ after the algorithm is fixed; do not require every field or every member to differ. |
| S03 | Capture/perturb Python and, if used, NumPy/Torch global RNG states around sampling | Global states are unchanged by a local-generator sampler, and externally seeded global RNG changes do not affect its output. Avoid introducing Torch as a pure-config dependency solely for this check. |
| S04 | Run a tiny sampling subprocess under two `PYTHONHASHSEED` values using the same config | Canonical output records are identical. Detect built-in `hash()` or unordered-container dependence in stream derivation. This test needs only installed runtime dependencies. |
| S05 | Equivalent config dictionaries with reordered keys; repeated canonical serialization | Same samples and resolved representation/hash under documented canonicalization. Sequence order is not dictionary order: do not require reordered choice lists to sample identically without an explicit policy. |
| S06 | Sample count `1` then `4` with the same seed | Recommend first-member/prefix stability via per-member streams. Freeze this expectation only if T13/T34 adopt it; reproducibility at a fixed configuration is mandatory regardless. |
| S07 | Seed schedule `[0, 1, 2]` executed forwards, backwards, and individually | Each run seed maps to the same member records independent of experiment execution order. |
| S08 | Heterogeneous sampling over a modest fixed set of seed/member IDs | Exact output count; unique stable member IDs; depths/widths/dropouts belong to declared choices; all learning rates/weight decays finite and within bounds, allowing only documented floating-point tolerance. Repeated hyperparameter vectors are legal. |
| S09 | Singleton discrete choices and degenerate legal continuous ranges | Every hyperparameter equals its declared constant; no assertion of sample diversity. Independently trained members must still receive distinct logical stream identities. |
| S10 | Homogeneous ensemble construction | All members match baseline hyperparameters; each has its own member ID and initialization/permutation stream identity. Detect shared mutable member records; identical configuration must not mean shared parameters. |
| S11 | Stub the uniform draw with known `u=0`, `u=0.5`, and a value just below `1` | For positive `[a,b]`, compare to `exp(log(a) + u * (log(b) - log(a)))`: lower endpoint, geometric midpoint, upper-near-bound respectively. This catches uniform-linear sampling. Real generators need not emit the exact upper endpoint. |
| S12 | Derived streams for architecture sampling, initialization, permutation, and dropout | Recommend distinct named stream identities; changing/consuming one stream must not advance the others. Compare frozen derivation vectors rather than asserting random permutations can never coincide. Coordinate exact stream ownership with T34. |
| S13 | Serialize sampled member records and load them as a resolved run specification | Round trip preserves floating values, order, IDs, and seeds; rehydration must not silently resample. Sampling metadata includes algorithm/version sufficient for a golden-vector check. |
| S14 | Invalid config passed directly to the sampling API | Reject before first random draw; prevents bypassing validation by avoiding the CLI/config loader. |

### Reproducibility oracle rules

- Pin a small **golden record** only after T13/T34 specify the generator family, seed derivation, choice ordering, numeric conversion, and sampling algorithm. Compute expected seed-derivation and log-transform values independently; do not make a test call the same production helper on both sides of the assertion.
- Exact equality is appropriate for repeated records produced under the same pinned implementation/runtime. Cross-platform golden floating values should use a documented tight tolerance if the algorithm relies on platform `log`/`exp`; integer derived seeds and chosen categorical indices should remain exact. Keep values unrounded in the artifact.
- Random vectors can coincide. Avoid fragile assertions that all seeds must produce distinct architectures, every finite batch permutation must differ, or a small sample must hit every choice. Distributional goodness-of-fit tests do not belong in the fast acceptance gate.
- Changing a master run seed may alter multiple streams by design. Reordering run execution must not. Dataset/split/preprocessing seed invariance belongs to T24/T34 and is not proof obtainable from the sampler alone.
- Fixed seed reproducibility is narrower than bitwise identical CUDA training. This suite certifies config/sampling only; resume training state is covered by T35/T45.
