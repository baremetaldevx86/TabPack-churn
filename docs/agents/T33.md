# T33 — Independent training and loss reduction review

## Assignment and conclusion

Review how homogeneous ensemble members remain independently trained when their
forward/backward passes are batched or packed. **Use separate member parameters
and optimizer states, compute a sample-mean loss for each member, and sum those
member losses before backward.** Packing changes execution, not the objective.
This note is a design review; it does not certify a local implementation.

## Exact objective and tensor contract

Let `m` index `M` homogeneous members, `b` index a member's current minibatch,
and `theta_m` denote all parameters belonging to member `m`. With independent
permutations `I[m,b]`, the training tensors are:

```text
X_m,b = X_train[I[m,b]]             shape [M, B, F]
y_m,b = y_train[I[m,b]]             shape [M, B]
z_m,b = f(X_m,b; theta_m)           shape [M, B]
L_m   = (1 / B) sum_b BCEWithLogits(z_m,b, y_m,b)
L     = sum_m L_m
```

All labels are floating binary targets with exactly the same shape as logits.
If a model returns `[M,B,1]`, remove only the final singleton dimension; an
unqualified squeeze can accidentally remove `M` or `B` when either equals one.
Do not broadcast one label vector across independently permuted feature rows.

The separability argument is direct:

```text
d L / d theta_m = d L_m / d theta_m
d L_j / d theta_m = 0              for j != m
```

Thus one backward call on the sum is equivalent to separate backward calls on
the individual mean losses, with matched initial parameters, inputs, stochastic
masks, and optimizer settings. The gradient scale of member `m` is unchanged
when unrelated members are added or removed. A common optimizer is sufficient
when its update is elementwise/member-separable and every member has the same
step schedule; distinct Python optimizer objects are not required.

### Reduction rules

For unweighted binary logits and targets of shape `[M,B]`, the intended
pseudocode is:

```python
element_loss = binary_cross_entropy_with_logits(logits, targets, reduction="none")
member_loss = element_loss.mean(dim=1)
training_loss = member_loss.sum()
```

- `element_loss.mean()` or `member_loss.mean()` divides each member gradient
  by `M`. This remains a separable objective, but is **not the same training
  update at the specified learning rate** as ordinary single-member training.
- `element_loss.sum()` multiplies each ordinary member gradient by `B`.
- `M * element_loss.mean()` is equivalent to the recommended reduction only
  with equal, nonempty member batch sizes and the same loss denominator.
- The last short batch uses its actual size, not the configured batch size.
  `B=1` and `M=1` must both work. Each member still gets approximately `N/B`
  optimizer steps per epoch; `M*B` is total processed examples per packed step,
  not the batch size seen by any one member.
- For future variable-size/masked batches, divide each member's valid loss sum
  by that member's valid count before summing. A zero-valid member needs an
  explicit optimizer skip; it must not produce a divide-by-zero loss.
- If microbatches accumulate one intended member minibatch, weight each
  microbatch mean by `microbatch_size / intended_batch_size`. Summing unweighted
  microbatch means overweights short chunks. Step the optimizer once afterward.
- Any future sample/class weights require the same denominator as the ordinary
  reference loss; normalization by the sum of weights is not automatically
  equivalent to PyTorch BCE's element-count mean.

Keep logging separate: `member_loss.detach().mean()` is a useful comparable
reported loss across different `M`. Never backward through that logged mean.
For epoch means, weight batch means by their actual sample counts.

### AdamW does not excuse a member-mean loss

With constant positive gradient scale `c`, idealized Adam moment normalization
largely cancels `c`, but its denominator includes epsilon:
`c*m_hat / (c*sqrt(v_hat) + eps) = m_hat / (sqrt(v_hat) + eps/c)`.
Consequently a `1/M` gradient scale is not exact AdamW equivalence, particularly
for small gradients. Finite precision, clipping, and a changing pack size can
make the discrepancy larger. Multiplying AdamW's learning rate by `M` is not a
general fix and also changes decoupled weight decay. Fix the loss reduction.
Compare gradients as well as final parameters: an Adam-only update test may
hide an incorrect reduction when epsilon is negligible.

## Other independence requirements

1. **Distinct trainable entries.** Each member owns all hidden layers, biases,
   and the output head. A stacked parameter tensor may share one allocation;
   its member slices must be nonoverlapping. Repeating module references or
   expanding one weight tensor creates sharing. A shared trainable trunk with
   separate heads is not an independent homogeneous ensemble.
2. **Member-separable forward.** No feature/attention mixing between members.
   Shared immutable preprocessing is fine. If normalization is added later,
   statistics and learned affine parameters must be member-local; flattening
   `[M,B,H]` to `[M*B,H]` for ordinary BatchNorm mixes members. The current
   Linear–ReLU–Dropout architecture avoids this issue.
3. **Independent stochastic draws.** Independent initializations, permutations,
   and dropout masks prevent identical homogeneous trajectories. A dropout
   mask generated once at `[B,H]` and expanded across `M` fails this condition.
   Shared data does not violate gradient separability, but sharing batch order
   falls short of the agreed independent-permutation protocol. Reproducible
   member-specific streams also allow matched standalone/packed oracle tests.
4. **Separate optimizer state.** Adam moments must retain the member axis.
   Same hyperparameters across homogeneous members are intentional; averaging
   moments across members is not. One shared step counter is valid only while
   all relevant members/parameters have identical update schedules.
5. **No cross-member clipping.** A single gradient norm across the whole pack
   scales member `m` according to other members' gradients. If clipping is
   required, compute one norm per member over all that member's active
   parameters. The simplest reduced protocol uses no clipping.
6. **Inactive is not zero gradient.** AdamW can move a zero-gradient slice via
   existing momentum and weight decay. If a member is frozen in a future
   extension, skip its parameter update, decay, moment update, and step counter
   together. Static heterogeneous padding must not influence active outputs or
   gradients; unused slots must not enter any norm or regularizer denominator.

Float32 is the current protocol. Any future shared AMP overflow/skip decision
can couple whether otherwise-finite members take a step and needs a separate
independence review.

## Training independence versus ensemble decisions

Training on `BCE(mean_m sigmoid(z_m), y)` or on `BCEWithLogits(mean_m z_m, y)`
couples the member gradients through ensemble predictions and violates this
objective. Probability averaging belongs to validation/selection and inference
on a shared, consistently ordered evaluation set, under no-grad/eval mode.

Independence here is conditional on the common dataset and fixed training
schedule. It does not mean statistically independent predictions on that data.
Validation-based ensemble stopping/selection deliberately makes the final
chosen snapshots depend on other members. That is compatible with independent
gradient updates up to each fixed step, but must not be described as fully
independent stopping. Record whether the homogeneous control stops/checkpoints
members individually or jointly; a change in that policy is a protocol change,
not a loss-reduction change.

## Acceptance checks for integration

These are proposed checks, not reported passing tests:

- **Gradient oracle:** initialize separate ordinary MLPs, copy their parameters
  into the pack, use distinct deterministic member batches, and disable
  dropout. Compare every active member gradient after summed mean BCE with its
  ordinary counterpart. Include `M>1`, `M=1`, `B=1`, and a short final batch.
- **Isolation:** perturb only member `j`'s data/labels/parameters; all other
  members' losses and gradients must remain unchanged with stochastic inputs
  held fixed. Also differentiate only `L_j`: other member gradient slices are
  zero (or absent for separate modules).
- **Pack-size invariance:** keep member 0's weights, batch, and random draws
  fixed while adding unrelated members. Compare its gradients and a short
  AdamW update trajectory. This catches hidden `/M` reductions and global norms.
- **Optimizer oracle:** compare first/second moments and several updates to
  independent `torch.optim.AdamW` instances, including nonzero weight decay.
  Use deliberately non-negligible epsilon or direct gradient assertions so
  adaptive normalization cannot conceal an incorrect loss factor.
- **Shape/target oracle:** give each member a visibly different index sequence
  and verify its labels follow that exact sequence. For a stochastic test,
  provide matched explicit masks or replayable per-member streams rather than
  assuming resetting the global seed reproduces a different execution order.
- **Aggregation check:** verify inference uses `mean(sigmoid(logits))`, not
  `sigmoid(mean(logits))`; keep ensemble averaging outside the training loss.

Allow documented numerical tolerances for different matrix/reduction kernels;
bitwise equality across CPU/CUDA or packed/sequential execution is unnecessary.
