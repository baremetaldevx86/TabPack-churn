## Implemented public API

### Configuration and member sampling

- `ReducedConfig(...)` is a frozen dataclass with the ledger's reduced defaults:
  seeds `(0, 1, 2)`, four members, selection limit four, 100 epochs, patience 16,
  batch 256, default float32, and the specified baseline/search spaces.
- Baseline constructor fields are `baseline_depth`, `baseline_width`,
  `baseline_dropout`, `baseline_learning_rate`, `baseline_weight_decay`.
- Search fields are `heterogeneous_depths`, `heterogeneous_widths`,
  `heterogeneous_dropouts`, `heterogeneous_learning_rate_range`, and
  `heterogeneous_weight_decay_range`.
- Counts/seeds reject booleans, strings, fractional values, and invalid ranges.
  Seeds have domain `0 <= seed < 2**63`; duplicate run seeds/choices are errors.
  Lists normalize to immutable tuples. Log ranges require finite positive
  endpoints with `low <= high`; equal endpoints return the exact constant.
  Baseline weight decay may be zero. Patience may exceed the epoch budget,
  and selection limit may exceed current member count because retained
  snapshots enlarge the online pool. `float32` and explicit `float64` are
  recognized, with float32 the reduced default.
- `ReducedConfig.from_dict()` accepts flat dataclass fields or the nested
  representation produced by `to_dict()`. Unknown/duplicate fields fail.
- `sample_members(config, seed, mode="heterogeneous")` returns an immutable
  tuple of `MemberSpec` records. Modes `homogeneous` and
  `independent_mlp_ensemble` are equivalent; `heterogeneous` and
  `packed_heterogeneous_ensemble` are equivalent. Optional
  `heterogeneous=True/False` is a convenience spelling. For an ordinary MLP,
  sample one homogeneous member by replacing `member_count=1` in the config.
- `MemberSpec` exposes `member_id`, `member_index`, `depth`, `width`, `dropout`,
  `learning_rate`, `weight_decay`, and named `stream_seeds`. Its `streams`
  property returns a fresh dictionary. `to_dict()`/`from_dict()` round-trip
  resolved values without resampling. IDs use `member-0000` and numeric order.
- Sampling uses a separate local `random.Random` generator for each member and
  field. It is prefix-stable, independent of global RNG state and execution
  order, and redraws heterogeneous settings for each run seed. Discrete choices
  are uniform; continuous draws are log-uniform. The standard-library generator
  policy is exported as `SAMPLING_ALGORITHM`.
- `named_seed(root_seed, *path)` uses the versioned `sha256-named-v1` policy
  exported as `SEED_ALGORITHM`. Paths have type-tagged, length-delimited parts;
  the SHA-256 first eight bytes, big-endian, are masked to 63 bits. No Python
  `hash()` or additive member seed is used. `derive_seed` and
  `derive_named_seed` are aliases.
- Training stream names are `initialization`, `permutation`, and `dropout`.
  Execution can further derive epoch/layer/batch seeds by using the corresponding
  member stream seed as a root. Core only supplies stream identities; training
  must actually route its draws through those streams.

### Metrics and probability averaging

- `binary_roc_auc(y_true, y_score)` sorts and groups exact equal scores, giving
  half credit to cross-class ties. Scores may be any finite real numbers;
  both label classes are required. Empty/nonbinary/nonfinite/mismatched/rank-2
  inputs fail with `ValueError`.
- `binary_log_loss(y_true, y_prob, eps=None)` validates `[0,1]` probabilities,
  uses natural logarithms and sample-mean reduction, and clips only for loss.
  Default epsilon is float64 `2**-52`, independent of training dtype. Explicit
  epsilon must be finite, positive, below 0.5, and representably below one when
  subtracted from one. Single-class labels are legal for log-loss.
- Boolean labels normalize to 0/1; booleans in numeric prediction/config/result
  fields are rejected. Inputs with `.detach()`, `.cpu()`, and `.tolist()` can
  pass the same boundary without importing a tensor/array package here.
- `average_probabilities(predictions)` takes member-major vectors and returns
  their row-wise arithmetic probability mean using `math.fsum`; it does not
  average logits or member metrics. Inputs are validated and never mutated.

### Greedy and online selection

```python
candidate = Candidate("member-0000@epoch-3", "member-0000", 3, probabilities)
result = greedy_select(y_validation, candidates, max_size=config.max_selected)
accepted = retain_best_selection(previous_result, result)
```

- `Candidate` snapshots copy predictions into immutable tuples. IDs are unique
  within one call, while repeated member IDs at different source epochs remain
  legal. Duplicate snapshot IDs fail instead of acquiring accidental weights.
- Best singleton is always selected, even at or below ROC-AUC 0.5. Empty pools
  and nonpositive limits fail. A limit larger than the pool naturally stops at
  pool exhaustion. There is no empty-baseline or warm-started selection API.
- After initialization, each unused candidate is scored with the selected
  probability average. Exact strict improvement is mandatory. Ties resolve by
  prospective ensemble AUC, then candidate's individual AUC, then supplied pool
  order. No epsilon or rounded scores affect decisions.
- The caller supplies `previous_selected_snapshots + current_epoch_snapshots`
  in its documented stable order. `retain_best_selection` accepts a rebuild
  only when its validation AUC strictly exceeds the incumbent; ties/regressions
  retain the exact incumbent object. It does not warm-start the greedy path.
- `SelectionResult` includes `selected`, `selected_ids`, `selected_indices`
  (original pool indices in greedy acceptance order), `probabilities`,
  `validation_auc`, original `candidate_order`, per-round `steps`, evaluation
  count, and stop reason. The trace includes initialization and a final rejected
  round when present. `select_greedy` is an alias, and `max_ensemble_size` is an
  alternative spelling for `max_size`.

This deliberately overrides T16's proposed empty-baseline, canonical-ID sort,
and warm-start choices, following the integration decision and T3/T23 evidence.
The function accepts only validation labels/predictions; model state capture,
selection freezing, and final test evaluation belong to the training caller.

### Result aggregation helpers

- `mean_sample_std(values)` returns `(mean, sample_std)`, using stable stdlib
  statistics and `ddof=1`. Empty input yields `(None, None)`; singleton standard
  deviation is `None`; real zero remains zero. `sample_mean_std` adds a count
  in mapping form. Inputs must be finite numeric values, excluding booleans.
- `aggregate_results(records, expected_seeds=..., expected_methods=...,
  strict=True)` reduces one compatible experiment group. Each complete record
  requires `method`, integer `seed`, `status="complete"`, and validation/test
  ROC-AUC/log-loss. Nested `metrics[split][metric]` and explicit flat
  `validation_roc_auc`/`test_log_loss`-style fields are supported.
- Every complete run contributes once, with seeds sorted numerically and
  methods in declared order. Members, snapshots, and epoch diagnostics do not
  add observations. Required missing metrics and invalid ranges are errors.
- `failed`/`cancelled` statuses stay in diagnostics; missing, failed, cancelled,
  and incomplete seed lists are explicit. Default strict mode rejects an
  incomplete matrix; diagnostic `strict=False` retains null zero-success
  summaries. Empty input requires both expected seeds and methods. Supplying
  the manifest's matrix is necessary to establish planned completeness; if
  omitted, the helper can only infer the observed seed/method union.
- Duplicate complete outcomes, duplicate run IDs, undeclared methods/seeds,
  invalid status/schema versions, and incompatible supplied comparison/source/
  data/environment/timing or method-config identities fail. Retry acceptance
  must be resolved explicitly before aggregation, never by selecting test score.
- Optional timings are `fit_wall_s`, `final_test_predict_wall_s`, and
  `run_wall_s` under `timing` or as flat fields. Missing timings reduce only
  their own `n_observed`; negative/nonfinite timings fail.
- Output includes `complete`, `context`, `groups`, and `diagnostics`. Per-group
  metric/timing summaries expose mean, sample SD, counts, and seed IDs.
  `aggregate_runs`/`summarize_results` are aliases.
- `paired_deltas(baseline_by_seed, candidate_by_seed)` joins actual seed IDs,
  reports candidate-minus-baseline values plus sample summary and excluded seeds.
  `canonical_json(value)` gives compact sorted UTF-8-compatible strict JSON,
  preserving numeric precision and rejecting NaN/Infinity.

This is the T20/T32/T44 in-memory reduction boundary. Manifest file discovery,
artifact hashes, accepted-attempt policy, full result/selection provenance
validation, atomic writing, CSV/Markdown projection, and filesystem paths remain
coordinator integration responsibilities rather than additional core side effects.
