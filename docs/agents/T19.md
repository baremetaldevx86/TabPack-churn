# T19 — Safe preflight diagnostic specification

## Assignment

Specify a bounded, read-only preflight for the Churn experiment. It must check the
active Python environment, PyTorch/CUDA, host RAM and output/data disk space, the
canonical data layout, and reproducibility inputs before `run` can train. It must
not install packages, download data, create checkpoints, allocate large tensors,
alter global settings, or start training.

This is an implementation contract and operator checklist; no source module or
training run was added by this task.

## Safe invocation

The preferred eventual command is the CLI contract proposed by T41:

```powershell
python -m tabpack.cli preflight `
  --config configs/churn_reduced.yaml `
  --data-root data/churn `
  --run-dir runs/churn-reduced `
  --device auto `
  --num-workers 0 `
  --json
```

The command must be offline and side-effect free by default. It may read the
config, data metadata/split files, package metadata, and resource probes. It must
not create `run-dir`; an optional explicitly requested report may be written
atomically to a new path. `--help` and `--version` must not touch the dataset or
GPU. Use `--device cpu` for a CPU-only acceptance check. Use `--device auto` to
observe whether a usable GPU is available. An explicit `--device cuda` is strict:
unavailable or unhealthy CUDA is an error, not an implicit CPU fallback. `auto`
may resolve to CPU with a warning. If a future config exposes an explicit
`allow_cuda_fallback` policy, record that policy and its reason rather than
silently applying it.

Until the CLI exists, the following bounded probes are a safe operator fallback.
Run them from the intended project environment; they do not install, download,
train, or write files. Capture stdout/stderr and exit status for each probe.

```powershell
# 1. Active interpreter and package metadata (no `pip freeze`).
python -B -c "import sys,platform,struct,importlib.metadata as m,json; names=['torch','numpy','scipy','scikit-learn']; print(json.dumps({'executable':sys.executable,'python':sys.version,'implementation':platform.python_implementation(),'bits':struct.calcsize('P')*8,'platform':platform.platform(),'venv':sys.prefix!=sys.base_prefix,'packages':{n:m.version(n) if any(d.metadata['Name'].lower()==n for d in m.distributions()) else None for n in names}},default=str,indent=2))"

# 2. Torch build/runtime facts; no tensor allocation and no training.
python -B -c "import json,torch; ok=bool(torch.cuda.is_available()); print(json.dumps({'torch':torch.__version__,'cuda_build':torch.version.cuda,'cudnn':torch.backends.cudnn.version(),'cuda_available':ok,'device_count':torch.cuda.device_count(),'devices':[{'name':torch.cuda.get_device_name(i),'capability':list(torch.cuda.get_device_capability(i)),'vram_bytes':torch.cuda.get_device_properties(i).total_memory} for i in range(torch.cuda.device_count())] if ok else [],'threads':torch.get_num_threads(),'interop_threads':torch.get_num_interop_threads(),'deterministic':torch.are_deterministic_algorithms_enabled(),'cudnn_benchmark':torch.backends.cudnn.benchmark,'cudnn_deterministic':torch.backends.cudnn.deterministic,'tf32_matmul':torch.backends.cuda.matmul.allow_tf32,'tf32_cudnn':torch.backends.cudnn.allow_tf32},indent=2))"

# 3. Independent NVIDIA driver probe; a missing command is a CPU warning only.
nvidia-smi --query-gpu=name,driver_version,memory.total,memory.free --format=csv,noheader,nounits

# 4. Host memory and volume capacity. Resolve the actual data/output volumes
# before running; these examples use C: only.
Get-CimInstance Win32_OperatingSystem | Select-Object Caption,TotalVisibleMemorySize,FreePhysicalMemory
Get-PSDrive -Name C | Select-Object Name,Used,Free

# 5. Repository state. An unborn local repository is represented as unknown,
# never replaced by the upstream reference SHA.
git rev-parse --verify HEAD
```

The fallback probes are diagnostics only. They cannot establish that a dataset
is canonical or that the configured memory budget fits; the integrated preflight
must perform those checks and return structured results.

## Required checks and captured outputs

Every check has a stable name/code, `pass`, `warning`, `error`, or `unknown`
status, observed facts, required threshold or expectation where applicable, and
an actionable remediation. Keep check order stable so JSON and logs do not flap.
Capture the following fields in a `preflight.v1` result (with `null` plus a
reason for unavailable observations):

```json
{
  "schema_version": "preflight.v1",
  "status": "ready|ready_with_warnings|blocked",
  "ok": true,
  "requested_device": "auto|cpu|cuda",
  "resolved_device": "cpu|cuda:0|null",
  "checks": [
    {
      "name": "torch_import",
      "code": "TORCH_OK",
      "status": "pass",
      "observed": {},
      "required": {},
      "remediation": null
    }
  ],
  "environment": {},
  "data": {},
  "reproducibility": {}
}
```

Do not put credentials, environment-variable dumps, command lines, raw
tracebacks, GPU UUIDs, serial numbers, hostnames, usernames, or secret-bearing
URLs in a persisted report. A human-facing error may include the user-supplied
data/output path; provenance artifacts should use the sanitized logical aliases
and hashes specified by T48.

### 1. Python and dependency checks

* Verify the executable is the intended active interpreter, Python is 64-bit,
  and the supported version range from the project lock/config is satisfied.
  Record implementation, full version, OS family/build/architecture, and whether
  an isolated environment is active. Do not mutate the environment.
* Import `torch` and record its complete version including a build suffix such as
  `+cu128`. Import every package required by the resolved config, at least
  `numpy` and the project's declared preprocessing/metric dependencies. A
  missing required package or import exception is blocking; do not reinterpret a
  broken import as CPU-only operation.
* Capture active-interpreter package name/version pairs from
  `importlib.metadata`, not a global `pip freeze`. Include lock-file path/hash
  when one exists. Do not record editable-install local paths or package index
  credentials.
* Verify config parsing/schema before data or device work. Invalid config,
  unsupported dtype, bad family/member counts, invalid seed list, or impossible
  batch/epoch/patience values is a blocking configuration error.

Expected failure guidance:

| Code | Meaning | Guidance |
| --- | --- | --- |
| `PYTHON_WRONG_INTERPRETER` | Python/version/bitness is outside the supported environment | Activate the project environment and rerun; do not install automatically. |
| `TORCH_MISSING` | `torch` cannot be imported | Install/select the pinned environment through the project's documented setup, then rerun. |
| `TORCH_IMPORT_FAILED` | Import raised an error other than missing package | Repair or recreate the environment; include only a sanitized exception class/message. |
| `DEPENDENCY_MISSING` | A config-required package is absent | Select the locked environment or follow documented dependency setup. |
| `CONFIG_INVALID` | Config cannot be parsed or violates schema | Fix the named config field; no training or output is started. |

### 2. CUDA and device checks

Record `torch.version.cuda`, cuDNN version, `torch.cuda.is_available()`, device
count, product name, compute capability, total/free VRAM when safely observable,
and the independent driver version from `nvidia-smi`. A missing `nvidia-smi` is
not by itself a CPU failure if an explicit CPU run is requested. Do not enumerate
GPU UUIDs or serial numbers.

The default probe performs no large allocation. If the config requests CUDA, the
implementation may perform one bounded one-element tensor create/copy/delete
probe to detect a driver/runtime failure, but it must report that this probe ran,
avoid synchronization loops, and never treat it as a performance benchmark. A
probe exception is retained as a sanitized diagnostic fact.

Device policy:

* `cpu`: require usable Python/PyTorch and resolve exactly to CPU; CUDA is not
  required. This is the portable fallback and must remain runnable without a
  GPU.
* `auto`: choose CUDA only after availability and the bounded runtime probe pass;
  otherwise resolve CPU and emit `CUDA_FALLBACK` warning with requested and
  resolved devices and remediation. Do not make a second CUDA attempt.
* `cuda`: require a healthy CUDA runtime and resolve to the requested CUDA device;
  unavailable device, driver mismatch, insufficient VRAM, or failed probe is a
  blocking `CUDA_UNAVAILABLE`/`CUDA_RUNTIME_FAILED` error. Tell the user to use
  `--device cpu`/`auto` or repair the compatible PyTorch/driver installation.

Failure guidance:

| Code | Meaning | Guidance |
| --- | --- | --- |
| `CUDA_FALLBACK` | `auto` requested CUDA but selected CPU | Continue only with the recorded CPU result, or repair the driver/build for GPU use. |
| `CUDA_UNAVAILABLE` | Explicit CUDA requested but no usable device exists | Use CPU/auto or install/select a compatible driver and PyTorch build. |
| `CUDA_RUNTIME_FAILED` | Availability check passed but bounded runtime probe failed | Treat CUDA as unusable; inspect driver/runtime compatibility and rerun. |
| `VRAM_LOW` | Estimated peak GPU memory exceeds free VRAM | Reduce batch/members, select CPU, or use a GPU with sufficient free memory. |

### 3. RAM and disk checks

Use `shutil.disk_usage()` (or an equivalent read-only volume probe) on both the
dataset root and run-output parent, because they may be different volumes. Do
not create a test file, fill a volume, or assume the current working directory's
capacity. Report `available_bytes`, the volume/path alias, estimated required
bytes, and the safety margin.

Estimate, without constructing a model or allocating a full tensor, from the
resolved row/feature counts, dtype, batch size, member count, architecture,
optimizer state, checkpoint policy, and expected temporary files. Include the
raw dataset and preprocessed representation where applicable. A documented
conservative margin (for example 20%, or the project-configured value) must be
included in `required_bytes`; do not invent a precise measurement when a factor
is unknown. Exact equality at the documented threshold is pass; one byte below
is error. Unknown usage or an unavailable probe is a controlled `RESOURCE_UNKNOWN`
warning/error according to the configured strict policy, never an exception or
silent pass.

For RAM, capture total and currently available physical bytes using a read-only
OS API. Compare available RAM to the estimated peak host requirement, including
data buffers, model/optimizer state, and configured workers. The default Windows
worker count is zero. Do not allocate an array to test the threshold. Report the
metric used (available versus total) explicitly.

Failure guidance:

| Code | Meaning | Guidance |
| --- | --- | --- |
| `DISK_LOW` | Affected volume is below required bytes plus margin | Free space or choose another data/output location; no files were created. |
| `RAM_LOW` | Available physical RAM is below estimated peak | Close applications or reduce batch/members/workers; rerun preflight. |
| `RESOURCE_UNKNOWN` | Probe or model estimate is unavailable | Resolve the probe/config or use an explicit conservative policy; do not claim ready. |
| `OUTPUT_NOT_WRITABLE` | Parent is missing/unwritable or path conflicts | Select a writable output parent; preflight must not create it implicitly. |

### 4. Dataset and preprocessing checks

Preflight must be offline and must never acquire a missing dataset. Resolve the
declared data root and verify:

1. The path exists, is readable, and identifies the canonical public Churn
   source/provenance expected by the config. A directory's mere existence or an
   unrelated file is not success. IBM Telco, synthetic data, and an unrecognized
   source are errors, not substitutions.
2. Recognized train, validation, and test split files/metadata exist, are
   non-empty, and have readable headers/shape. Capture logical split names,
   row counts, feature names/types, target name and binary value mapping, and
   disjoint-ID/overlap results where IDs are available. Do not load all rows just
   to print a sample and do not include row-level records in the report.
3. The expected feature schema and target are consistent across splits. Reject
   malformed labels, missing target, duplicate/overlapping split IDs, unsupported
   columns, or an unverified data fingerprint. If a full hash is required, hash
   only the declared input files and record the digest/size; do not hash a secret
   URL or arbitrary workspace contents.
4. The preprocessing declaration says numeric median imputation and
   quantile-normal transform are fitted on **train only**, while categorical
   most-frequent imputation and one-hot vocabulary are also fitted on **train
   only**, with unknown categories ignored. Capture the fit split and
   preprocessing/schema version. A transform fitted using validation/test data is
   `PREPROCESSING_LEAK` and blocks the run.

Failure guidance:

| Code | Meaning | Guidance |
| --- | --- | --- |
| `DATA_MISSING` | Root or required split is absent | Acquire/validate the canonical Churn data in a separate explicit workflow, then rerun. |
| `DATA_UNRECOGNIZED` | Existing files are not the declared canonical source | Point to the validated source; never substitute IBM Telco or synthetic data. |
| `SPLIT_MISSING` | Train/validation/test split is absent or empty | Restore the named split and its provenance metadata. |
| `DATA_SCHEMA_INVALID` | Feature/target/label shape or type is invalid | Repair the source or config and rerun validation. |
| `DATA_OVERLAP` | Split identifiers overlap | Recreate disjoint canonical splits; do not continue. |
| `PREPROCESSING_LEAK` | Fit state uses non-training rows | Refit preprocessing using train only and record the new artifact hash. |
| `DATA_FINGERPRINT_MISMATCH` | Files differ from declared provenance | Revalidate/download explicitly; never silently accept changed bytes. |

### 5. Reproducibility checks

Resolve and capture, before a run:

* ordered seeds (default `[0, 1, 2]`), master/member seed derivation rule and
  version, and independent member initialization/permutation policy;
* float32 dtype, optimizer/config values, ordered realized member
  hyperparameters, batch size, epoch/patience limits, and worker count;
* Python, NumPy, and PyTorch RNG policy. The runner should seed Python,
  NumPy, and PyTorch (CPU/CUDA) from the recorded derivation. If a DataLoader
  uses workers, capture a worker seed initializer and explicit generator; use
  zero workers by default on Windows;
* `PYTHONHASHSEED` state as a fact (it must be set before process startup if
  required), torch intra/inter-op thread counts, deterministic-algorithm setting,
  cuDNN benchmark/deterministic settings, TF32 settings, and mixed-precision
  policy;
* local implementation Git SHA, dirty/unborn state, source inventory hash,
  config hash, and data inventory/hash. An unborn local repository is `null` with
  reason `unborn_repository`; never claim the upstream reference SHA as local
  code identity;
* exact package versions, PyTorch CUDA build, driver, OS, CPU/GPU summary, and
  requested/resolved device.

For a strict reproducibility profile, require deterministic algorithms, cuDNN
benchmark disabled, TF32 disabled, fixed worker policy, and an explicit seed
derivation. If deterministic mode rejects an operation, fail with a controlled
`DETERMINISM_UNSUPPORTED` diagnostic rather than silently changing the mode.
Record that PyTorch does not guarantee identical results across releases or
across CPU/GPU platforms; a successful preflight establishes a reproducible
configuration, not a cross-platform bitwise guarantee.

Failure guidance:

| Code | Meaning | Guidance |
| --- | --- | --- |
| `REPRO_CONFIG_INCOMPLETE` | A seed, derivation, dtype, worker, or deterministic setting is unspecified | Resolve it in config and record the effective value. |
| `DETERMINISM_UNSUPPORTED` | Requested deterministic policy cannot run the selected operation/device | Change the operation/device or explicitly label the run non-strict; do not silently relax it. |
| `PROVENANCE_INCOMPLETE` | Code/config/data identity cannot be captured | Complete the identity capture; do not publish the run as canonical evidence. |

## Exit status and side-effect contract

Align with T41 so callers can automate recovery:

* `0`: ready, or ready with warnings when not in strict mode;
* `2`: usage/config/schema error;
* `3`: dependency, device, permission, data, or resource preflight failure;
* strict mode converts warnings such as CUDA fallback or unknown resource
  estimates to a blocking result and exit `3`.

On any blocking check, return all independently discoverable diagnostics in a
stable order, do not invoke a dataset downloader/model constructor/training
callback, and do not create a run directory or partial checkpoint. Normal mode
prints concise remediation without a traceback; `--json` emits one
machine-readable object. A diagnostic report must be serializable even when a
probe itself fails.

## Local observations captured

These are a single-machine snapshot, not acceptance thresholds and not a claim
that another machine matches it:

* Windows 11, CPython 3.12.10, 64-bit, outside a virtual environment.
* Active packages observed: `torch 2.11.0+cu128`, `numpy 2.5.3`; `scipy` and
  `scikit-learn` were not installed in that interpreter.
* `torch.version.cuda` was `12.8`, cuDNN `91900`, CUDA was available, one RTX
  5050 Laptop GPU was visible with compute capability `[12, 0]` and approximately
  8.55e9 total bytes reported by PyTorch. `nvidia-smi` reported driver `610.88`
  and approximately 8.15e3 MiB total / 7.26e3 MiB free.
* One RAM probe reported approximately 16,457,592 KiB total and 1,044,444 KiB
  free; one C: volume probe reported approximately 144,065,437,696 bytes free.
  Free RAM is volatile and must be rechecked immediately before a run.
* `git rev-parse --verify HEAD` reported no single revision because the local
  repository is unborn. The preflight must preserve that fact.
