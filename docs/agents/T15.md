# T15 — Packed per-member AdamW design review

## Assignment and scope

Specify an independently authored, vectorized AdamW update for packed model
parameters. The design must preserve the result of applying ordinary AdamW to
each member independently, while allowing member-specific optimizer
hyperparameters and explicit handling of zero/inactive members. This is a
design/review note only: no source changes, dependency installation, or
training were performed.

The local reduced protocol uses float32 AdamW and a summed-over-members loss
(sample mean inside each member, then sum over members). The packed optimizer
must therefore not compensate for a hidden `1/M` loss normalization.

Reviewed:

* Paper section 3.4, “Optimizer Pack,” which defines stacked optimizer state

  `https://raw.githubusercontent.com/yandex-research/tabpack/05a89e21b955f12de84889d662e15ca534019aaa/src/project/optim.py`.
* PyTorch AdamW semantics, especially decoupled multiplicative weight decay:
  `https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW.html`.

The paper and pinned repository are reference material only. The local project
must not import or execute their implementation. The official reference's
`AdamWPack` is a useful vectorization precedent, but its ordinary `step()`
applies the broadcast decay/update to every row passed to it. Local early
stopping/pruning needs an explicit active-mask contract so a finished member
does not continue to drift.

## Tensor/API contract

Let `M` be the pack size. Every packed parameter `p` has shape
`[M, *S]`; its gradient and moment tensors have the same shape. The first
dimension is always the member dimension, never a feature or batch dimension.

Recommended conceptual API:

```text
PackedAdamW(
    packed_parameters,
    lr: float | Tensor[M],
    betas: (float | Tensor[M], float | Tensor[M]),
    eps: float | Tensor[M],
    weight_decay: float | Tensor[M],
    *,
    active: Tensor[M] | None = None,
    member_masks: mapping[parameter, Tensor[M]] | None = None,
    slot_masks: mapping[parameter, Tensor[M, *S]] | None = None,
    shared_step: bool = False,
)
```

The concrete project API may use parameter groups, but each group must have a
single pack size and its scalar/vector hyperparameters must broadcast to
`[M, *S]`. Validate at construction time:

* `lr >= 0`, `weight_decay >= 0`, `eps > 0`;
* each beta is in `[0, 1)`;
* vector hyperparameters have exactly length `M` and are on the same device
  (or are moved once during setup), rather than silently truncating/broadcasting
  an unrelated dimension;
* sparse gradients are rejected;
* all packed parameters in one group have the same member dimension.

Scalars are shared hyperparameters. A length-`M` tensor gives one value per
member. Store the resolved vectors in the optimizer state/config so that
checkpoint restore and reproducibility do not depend on Python-list identity.
`shared_step=True` is allowed only when every member is updated on every call;
otherwise use a per-member step counter (and, for structurally absent
parameters, a per-parameter counter as described below).

## AdamW equations

For one parameter row belonging to member `m`, let `theta` be the value before
the step, `g` its current dense gradient, `eta_m` the learning rate,
`lambda_m` the weight decay, and `b1_m`, `b2_m`, `eps_m` the member-specific
hyperparameters. For an effective active mask `q_m` equal to one, increment
the member/parameter step `t_m` and perform the PyTorch-compatible AdamW order:

```text
theta_decay = (1 - eta_m * lambda_m) * theta
m_t = b1_m * m_(t-1) + (1 - b1_m) * g
v_t = b2_m * v_(t-1) + (1 - b2_m) * (g * g)
m_hat = m_t / (1 - b1_m ** t_m)
v_hat = v_t / (1 - b2_m ** t_m)
theta_t = theta_decay - eta_m * m_hat / (sqrt(v_hat) + eps_m)
```

Weight decay is **decoupled**: do not add `lambda_m * theta` to `g`, `m`, or
`v`. Decay happens even when `g` is numerically all zeros, provided the
parameter/member has a gradient object and is active. A zero learning rate
must not skip moment or step updates; it only makes the parameter update and
decay factor equal to no change. A zero weight decay must be an exact no-decay
factor. Biases and any explicitly exempt parameter groups should use
`weight_decay=0` rather than a special branch in the AdamW kernel.

For a scalar/vector update, create broadcast views with shape
`[M, 1, ..., 1]`; never reshape a member vector against the last dimension.
The optimizer may loop over parameter groups and packed tensors, but must not
loop over members to perform the math. In-place updates under `no_grad` are
appropriate, provided inactive rows are preserved before/after the operation.

## Effective activity, zero members, and padding

There are three distinct cases that must not be conflated:

1. **Training-active member:** `active[m]` is true. Its real parameters are
   updated, moments incorporate its gradient (including an all-zero gradient),
   its step advances, and decoupled decay applies.
2. **Finished/inactive member:** `active[m]` is false. Its parameter values,
   moments, and step counter are bitwise unchanged by this call; no weight
   decay occurs. This is pause/freeze semantics required by member early
   stopping. Reactivation resumes the old state; pruning may instead compact
   and permanently discard that row.
3. **Structurally absent parameter/slot:** a shallow member does not own a
   deeper layer, and a narrow member does not own padded width slots. Use
   `member_masks[p][m]` for whole-parameter ownership and, where needed,
   `slot_masks[p]` for element ownership. The effective row mask is
   `q[p,m] = active[m] AND member_masks[p,m]`.

For a parameter tensor, update moments and parameters only where `q` (and an
optional slot mask) is true. One safe vectorized pattern is:

```text
q_view = q.reshape(M, 1, ..., 1)
step_new = step + q                         # per-member integer/bool update
m_candidate = beta1_view*m + (1-beta1_view)*g
v_candidate = beta2_view*v + (1-beta2_view)*g*g
p_candidate = AdamW(theta, m_candidate, v_candidate, step_new, hp)
m.copy_(where(element_mask, m_candidate, m))
v.copy_(where(element_mask, v_candidate, v))
p.copy_(where(element_mask, p_candidate, p))
step.copy_(step_new)
```

In real code, bias-correction powers must use the old/new per-member step
consistently and `where` must prevent inactive rows from evaluating a
meaningful update with an invalid zero step. An equivalent implementation can
index active rows and scatter them back, but it must preserve the same packed
layout and avoid a Python member loop.

If all effective masks are false, skip lazy state initialization and return
without changing parameters or optimizer state. If `M == 0` is representable
by the model, define `step()` as a no-op with empty state; otherwise the pack
factory should fail clearly with `ValueError` before constructing an optimizer.
Do not silently turn an empty pack into one dummy member.

Padded parameter slots should be initialized to zero and have zero gradients.
For exactness and hygiene, apply `slot_masks` (or re-zero padded slots after
each update); relying solely on multiplicative decay to preserve a random
padded value is not sufficient. A padding slot must never contribute to a
different member through a batched matrix multiplication.

## Step-counter and state policy

State per packed parameter is:

```text
exp_avg:     [M, *S], same dtype/device as the update state
exp_avg_sq:  [M, *S], same dtype/device as the update state
step:        [M] (or scalar only under proven shared-step conditions)
```

For a simple packed MLP where every real parameter exists for every member,
one per-member `step[M]` can be shared across packed tensors. For heterogeneous
depth represented by padded layer tensors, a member's nonexistent deeper
parameter must not acquire a false optimizer history. Either exclude that
member row from the parameter's group/state using `member_masks`, or keep
`step[p][M]` per packed parameter. The latter most closely matches ordinary
PyTorch AdamW, whose step state is attached to each parameter.

Lazy initialization should allocate moments only when at least one effective
member is active for that parameter. If a group has a gradient object but a
member mask is false, that row remains zero/unchanged and does not count as a
step. If `grad is None`, skip the whole parameter exactly as PyTorch does:
there is no decay, moment update, or step increment for that parameter.

When pruning members, compact every member-axis object with the same keep index:
packed parameters, buffers, optimizer moments, step vectors, hyperparameter
vectors, masks, and stable member IDs. Never compact only model weights. The
official reference's `optimizer_pack_remove` follows this general state-slice
rule and explicitly allows state to be absent for never-used blocks; the local
implementation should make that case deterministic and testable.

## Tests required before integration

No implementation tests were run because the source and test modules are not
present yet. T22 should turn these into focused tests without long training:

1. **Independent numerical oracle:** initialize `M=3` packed tensors and `M`
   ordinary `torch.nn.Parameter`s identically; use distinct `lr`, betas, eps,
   and weight decay per member; apply the same 3–5 dense gradient steps. Compare
   parameters, `exp_avg`, `exp_avg_sq`, and steps to `torch.optim.AdamW` with
   `torch.testing.assert_close` at a documented float32 tolerance.
2. **Decoupled decay:** use zero gradients and nonzero weight decay; verify the
   parameter shrinks while moments remain the zero-gradient oracle, and verify
   the result differs from coupled L2-in-gradient Adam. Verify `wd=0` and
   `lr=0` semantics separately.
3. **Inactive rows:** give every member nonzero gradients and nonzero decay,
   set `active=[True, False, True]`, and verify row 1's parameter, moments, and
   step are unchanged. Reactivate row 1 and compare its continuation with an
   independent optimizer that was paused for the same calls.
4. **All inactive/empty:** all-false activity must not allocate or mutate state;
   an explicitly supported `M=0` pack must be a no-op, while an unsupported
   empty construction must fail with the documented error.
5. **No cross-member contamination:** perturb only gradient row `m`; every
   other row's parameter/moments/step must remain identical. Check that each
   vector hyperparameter broadcasts across trailing parameter dimensions.
6. **Heterogeneous ownership:** use a shallow member with a masked deeper layer
   and narrow padded slots. Verify absent rows/slots stay unchanged and have no
   state/step history, while real rows match independent models.
7. **Missing gradients and groups:** `grad=None` must skip decay and state;
   zero-weight-decay bias groups must not decay; scalar and length-`M` group
   hyperparameters must produce identical results when the vector is constant.
8. **State/pruning round-trip:** save/load packed optimizer state and compact
   selected member indices; compare continuation with independent optimizers on
   those members. This must include per-member step vectors.
9. **Loss scaling integration:** construct a packed BCE loss as sample mean per
   member followed by sum over members. Compare each packed gradient to its
   independently computed member gradient; no extra division by `M` is allowed.

Tests should run on CPU first and optionally CUDA with the same fixture. Do not
claim bitwise equality across devices; report tolerances and compare against
the same-device ordinary AdamW oracle.
