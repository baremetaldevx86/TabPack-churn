homogeneous ensemble, and heterogeneous packed ensemble through the shared
experiment orchestration. This is a **test design**, not an implemented or passed
training test. Its output is **synthetic smoke evidence, never Churn evidence**.

Implement `tests/test_smoke_synthetic.py`, using a pytest `tmp_path` for all

uses, providing an in-memory split object or an injected split loader. That

If the existing top-level API requires files, serialize this fixture only into

synthetic. Do not invent a downloadable synthetic replacement dataset or a
production `Churn` alias. The fixture adapter replaces only acquisition; the

Patch the application's download/acquisition boundary to raise immediately if
called. This is an offline test, with no external dataset or cache requirement.
Avoid broad socket monkeypatching that obscures unrelated runner behavior.

## Exact fixture

Use no random data generation. Interpret `None` as a missing value when building
the loader's native table/array representation. `row_id` is retained for split
assertions and provenance only: it must never enter the model feature matrix.

```python
def rows(n, offset, held_out):
    result = []
    for j in range(n):
        i = offset + j
        y = i % 2
        x0 = None if i % 7 == 0 else (2 * y - 1) + ((i // 2) % 4) / 16
        x1 = ((3 * i) % 11) / 10
        cat = (
            None if i % 9 == 0
            else "violet" if held_out and j % 5 == 0
            else "amber" if y == 0
            else "blue"
        )
        result.append({"row_id": i, "x0": x0, "x1": x1, "cat": cat, "y": y})
    return result

train = rows(32, 0, False)
validation = rows(12, 32, True)
test = rows(12, 44, True)
```

Expected structural properties, already checked independently:

| Split | Rows | Class 0 / class 1 | Observed nonmissing categories |
| --- | ---: | --- | --- |
| train | 32 | 16 / 16 | amber, blue |
| validation | 12 | 6 / 6 | amber, blue, violet |
| test | 12 | 6 / 6 | amber, blue, violet |

All 56 IDs are unique, each split contains numeric and categorical missingness,
and only held-out splits contain `violet`. Labels are intentionally strongly
related to features to keep debugging interpretable; their predictability is
not an accuracy acceptance criterion. There is no resplitting or stratification
step, and no preprocessing fit on the combined 56 rows.

## Tiny fixed run configuration

Use CPU, float32, seed `1729`, one worker, batch size 8, at most 3 epochs,
patience 3, and maximum selected ensemble size 3. Use numeric median imputation
plus quantile-normal transformation and categorical most-frequent imputation
plus one-hot encoding with ignored unknown categories, all fit on train only.
If the transform exposes `n_quantiles`, set it to `min(16, n_train)` and fix its
random state; otherwise use the application's documented train-size cap.

Use explicit member specifications, not distributional assertions about sampled
widths. If training always samples, inject these specifications at the existing
sampling boundary after normal configuration validation. This fixture is a
test-specific size override, not a revision of the real experiment budget.

| Path | Members | Depths | Widths | Dropout | Learning rates | Weight decay |
| --- | ---: | --- | --- | --- | --- | --- |
| ordinary MLP | 1 | 2 | 8 | 0 | 0.01 | 0.0001 |
| independent homogeneous MLP ensemble | 3 | 2, 2, 2 | 8, 8, 8 | all 0 | all 0.01 | all 0.0001 |
| heterogeneous packed ensemble | 3 | 1, 2, 3 | 4, 8, 12 | all 0 | 0.01, 0.005, 0.003 | 0, 0.0001, 0.001 |

Zero dropout limits unnecessary stochastic variation; depth, width, learning
rate, and decay still exercise heterogeneous packing. Use the application's
normal deterministic member-seed derivation and independent training
permutations. Do not impose equality between different methods' predictions.
Restore global RNG/deterministic settings and thread settings when the fixture
exits so this test cannot affect the rest of the suite.

## Execution and essential assertions

1. **Preprocessing and identity:** check the counts above, disjoint IDs, binary
   labels, and feature/target separation. After preprocessing, all splits have
   equal feature width and finite float32 features. Inspect fitted categorical
   vocabulary to ensure `violet` is absent; its one-hot block must be all zero
   when transformed. Assert the preprocessing fit receives precisely the 32
   training rows, not 56 combined rows. Avoid asserting an implementation-
   specific output width if the preprocessor adds documented indicators.
2. **All three paths actually train:** require distinct method records and
   confirm the ordinary model, independent collection of 3 ordinary models,
   and 3-member packed model reach the actual training entrypoints. Each base
   member must execute at least one update with finite loss and finite active
   parameters; at least one active parameter per member must change from its
   initial snapshot. Allow padded/masked packed values to remain unchanged.
   Do not require a particular accuracy, decreasing loss on every step, or
   a fixed number of selected checkpoints.
3. **Validation/checkpoint flow:** require finite validation probabilities of
   the correct row/member dimensions. Ordinary checkpoint choice and each
   ensemble's configured selection policy must use validation only. For the
   packed online selector, record candidate provenance `(member_id, epoch)`:
   the first epoch uses current members, and subsequent epochs include current
   members plus the preceding selection's snapshots. Require 1–3 selected
   candidate records and no repeated candidate within a selection. The same
   member at different epochs is legal. Do not demand selection grow to 3;
   strict improvement may legitimately retain a singleton.
4. **Freeze before test:** instrument the narrow test-prediction/evaluation
   boundary and the selection-freeze event per method. The training/selection
   component must not receive test labels or test metric results, and final
   test inference must occur after that method's selection is frozen. A loader
   may load or validate all three split schemas upfront; distinguish this from
   using test data for learning or selection. Verify no final test result is
   returned to the selector. Prefer these dependency/ordering assertions to
   inferring leakage absence from a good score.
5. **Ensemble and final metrics:** final probabilities have shape `(12,)`, are
   finite, and lie in `[0, 1]`. On the restored selected snapshots, recompute
   each ensemble's arithmetic mean of **probabilities** and compare to emitted
   ensemble predictions (`rtol=1e-6`, `atol=1e-7`). For the ordinary path,
   compare against its restored best checkpoint. Binary accuracy and ROC-AUC
   are finite and in `[0, 1]`; any emitted log loss is finite and nonnegative.
   Dedicated metric tests provide the correctness oracle—this smoke should
   not compare against fabricated Churn scores or self-derived golden values.
6. **Artifacts round-trip:** reload run metadata, selected checkpoint state,
   and predictions using the application's own readers. Re-run inference from
   restored state and compare with the saved predictions at the tolerance
   above. Selection records must resolve to actual saved snapshots, preserving
   member configuration and epoch. All files remain under `tmp_path`; no real
   dataset directory or result tree is written. If the pipeline aggregates its
   own runs, its synthetic-only summary must contain all three methods and one
   seed, and must retain the synthetic identity.
7. **Deterministic replay:** run the suite again from fresh models and fresh
   preprocessing in a second temporary output directory with the same config,
   dataset, and seed. Compare selected `(member_id, epoch)` records exactly;
   compare predictions/metrics numerically at the tolerance above. Do not
   compare wall-clock timing, memory observations, run IDs, creation times, or
   serialized checkpoint bytes. Replay is scoped to the same dependency stack
   and CPU environment, not bitwise portability across PyTorch/BLAS versions.

Suggested test name: `test_synthetic_all_paths_roundtrip_and_replay`. Run with
`python -m pytest tests/test_smoke_synthetic.py -q` **after implementation**.
The two passes imply six tiny method runs; put this on the ordinary offline CPU
CI path. Time the first integrated run before imposing a CI timeout. Do not
assert a training speedup or exact memory/timing figure on this fixture.

## Hard separation from real Churn results

Use equivalent fields supported by the final manifest schema, with these
semantics explicitly retained in every artifact and any smoke-only summary:

```json
{
  "dataset_id": "synthetic_smoke_v1",
  "data_origin": "synthetic",
  "run_kind": "smoke_test",
  "scientific_result": false,
  "fixture_version": 1,
  "seed": 1729,
  "split_sizes": {"train": 32, "validation": 12, "test": 12}
}
```

Do not label these artifacts `Churn`, use them to populate the real Churn
results table, or let smoke success satisfy the real-data experiment acceptance
gate. Synthetic provenance must survive aggregation; a mixed synthetic/real
input must be rejected or explicitly partitioned by dataset identity. Add this
aggregation guard in the dedicated aggregation tests rather than adding an
unrelated large fixture here. A user-facing smoke receipt can say: “Synthetic
pipeline smoke passed: all three model paths; no Churn experiment performed.”
