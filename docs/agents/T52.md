## Implemented acquisition and trust boundary

The immutable URL, full archive SHA-256, and byte size are fixed code constants.
Production acquisition offers no arbitrary URL/source-lock override. Every
redirect must use verified HTTPS and an exact approved delivery host. It rejects
URL credentials/fragments, partial responses, unexpected HTTP content encoding,
wrong Content-Length, truncated or oversized bodies, and wrong SHA-256. Downloads
have socket/overall deadlines, private temporary files, cleanup on failure, and
atomic no-clobber publication.

**Integration choice resolving the missing T7 inventory:** the complete pinned
archive is retained locally as the trust anchor. Each offline load verifies its
size/hash into a private captured snapshot, scans the exact allowed Churn names,
and derives their sizes/digests from those verified bytes. It then requires the
local extracted inventory and bytes to match exactly. An editable receipt cannot
certify its own arbitrary local files, and synthetic or same-shaped Churn-like
files cannot satisfy the production archive hash gate.

This is the full-archive route described in T38, not partial/range verification.
There are no fabricated static member hashes. A later reviewed per-member lock
could remove the need to retain/rescan the archive, but the current implementation
intentionally establishes member authority from the full archive on every load.

The bounded streaming tar reader:

- Copies only fixed allowlisted regular Churn files; other dataset payloads are
  discarded under the same scan limits. The exact present numeric/categorical/
  explicit-binary block set comes from the hash-verified archive itself.
- Rejects traversal, absolute/drive/UNC paths, alternate separators/streams,
  Windows reserved devices and trailing-dot/space aliases, control characters,
  duplicate/case-colliding names, and file/directory collisions.
- Rejects symlinks, hardlinks, devices, FIFOs, nested archives, and GNU/PAX sparse
  payloads. Sparse extent-table parsing is rejected before allocation.
- Bounds regular and extended-header sizes, member count/name length, total
  decompressed stream bytes including skipped payloads/headers, compression ratio,
  Churn bytes held in memory, and parsing time. It validates the gzip trailer.
- Writes only after full archive and dataset validation, stages in a fresh
  sibling directory, and publishes to a new destination. Existing destinations
  are not overwritten. Existing filesystem path components reject links and
  Windows reparse points.

## Loader and preprocessing

NPY parsing validates bounded headers, dtype/rank, and exact declared payload
length before allocation and uses `allow_pickle=False`. Object/structured/complex
payloads, wrong feature/label dtypes, infinity, malformed binary values, mismatched
rows, invalid target classes, and missing/unexpected files fail closed.

Canonical source splits retain their original order and must be int32, unique,
pairwise disjoint, in range, complete, and exactly 6400/1600/2000 rows; each split
must contain both binary classes. Source indices and raw split arrays are copied
and read-only. Data identity covers the role-tagged member inventory, including
metadata and split-file bytes.

Following T8/T18/T24:

- Numeric median imputation and `QuantileTransformer` are fit exclusively on
  train. Quantiles use `min(1000, n_train)`, normal output, all training rows
  (`subsample=n_train`), and fixed random state 0 by default; there is no noise.
- Categorical missingness is train-mode imputed, with ascending typed-value tie
  breaking. OneHotEncoder uses dense float32 and `handle_unknown='ignore'`.
  Missing is None/floating NaN; empty strings and literal `"nan"` are categories.
- All-missing train columns fail. Constant observed columns remain. Explicit
  `x_bin` columns are categorical; no all-split discovery of binary `x_num`
  columns is performed.
- Numeric then categorical one-hot output is contiguous, finite float32. Names,
  category block offsets, and source lineage are retained outside model inputs.
- Learned-state metadata/fingerprint includes medians, full quantile/reference
  arrays, modes, vocabulary, offsets, names, effective parameters, and dependency
  versions. Held-out features and all labels are excluded from fitted state.

## Public integration API

```python
from tabpack.data import (
    acquire_churn, download_churn_archive, extract_churn_archive,
    load_churn, prepare_data, fit_preprocessor, transform_features,
    make_synthetic_fixture, ChurnDataError,
)

# Explicit network acquisition; root means the final Churn dataset directory.
acquire_churn("data/churn")
# Default retained archive: data/tabpack-data.tar.gz

# Separate file-oriented acquisition is also supported:
# archive = download_churn_archive("data/tabpack-data.tar.gz")
# extract_churn_archive(archive, "data/churn")

raw = load_churn("data/churn")  # Offline, verifies the retained archive.
prepared = prepare_data(raw)
# Optional archive_path=... on acquire_churn/load_churn selects local storage,
# never a different network source or source identity.
```

- `raw`: `.train/.val/.test` are FeatureBlock objects (`.numeric`, `.categorical`,
  `.row_ids`, names); `.y_train/.y_val/.y_test`, `.y`, `.source_indices`,
  `.dataset_id`, `.dataset_sha256`, and `.inventory` expose validated data and
  provenance. `inventory` contains path, role, size_bytes, and SHA-256.
- `prepared`: `.train/.val/.test` are float32 arrays; `.x`/`.y` are split mappings;
  labels, identity, and indices are retained. `.preprocessor` provides
  `.metadata`, `.fingerprint`, `.learned_state_sha256`, `.feature_names`,
  `.output_width`, `.numeric_medians`, `.categorical_modes`, and `.transform()`.
- `fit_preprocessor(train: FeatureBlock, *, n_quantiles=1000, random_state=0)`
  accepts only features. `transform_features(fitted, features)` is the helper.
- `make_synthetic_fixture()` explicitly supplies T42's deterministic **32/12/12**
  fixture with identity **`synthetic_smoke_v1`**. It uses the same preparation
  path and is never called by real acquisition/loading. `synthetic_fixture` is
  an explicit alias.
- `ChurnDataError.code` supports machine-readable CLI failures. Imports and
  loading do not require scikit-learn; preprocessing reports a dependency error
  if it is absent.

**Coordinator:** load once and reuse the prepared data across methods; archive
