# T47 — Validation selection overfitting review

## Assignment

Review validation-based checkpoint and member selection for the reduced Churn experiment, with emphasis on overfitting caused by repeatedly searching validation predictions. Recommend an honest holdout and reporting protocol.

## Sources and evidence

- Project ledger, `swarm.md`: the provisional reduced protocol uses three seeds (`[0, 1, 2]`), four packed base members, at most four selected members, up to 100 epochs, patience 16, and validation ROC-AUC for checkpoint and greedy choices. Its online candidate pool contains current-epoch members and previous selected checkpoint snapshots; snapshots may reuse a member ID at different epochs (`swarm.md`, decisions 6–8).
- TabPack paper v1, §3.5: greedy ensembling repeatedly adds the candidate producing the largest validation improvement, and the online pool combines latest base states with prior-epoch ensemble members. Thus, repeated candidate comparisons over epochs are repeated validation use, not independent confirmation measurements. The per-epoch pool is bounded, rather than an archive of every checkpoint.
- TabPack paper v1, §3.6: ensemble early stopping is based on consecutive non-improvements on validation performance.
- TabPack paper v1, §4.2: the paper distinguishes optimistic multi-seed evaluation (repeat the full sampled-member procedure per seed) from a conservative tune-once protocol (rerun using only the main run's selected base-model configurations). This does not mean freezing trained weights across seeds. The paper's protocol names concern search opportunity and baseline alignment; they are distinct from statistical validation-selection optimism. An untouched test set can honestly evaluate the optimistic procedure. Source: <https://arxiv.org/html/2607.05380v1>.

Related note read before completion: `docs/agents/T35.md`, especially its `selection` contract and resume semantics. It treats selection as training state, excludes test labels/predictions/metrics from training checkpoints, and emits post-freeze test results linked to the final checkpoint hash. Adopt that boundary. An identical read-only evaluation repeated after a crash is not a new selection trial; log it without treating it as another seed. Directed question for T4/T16/T29/T32/T40/T50: confirm the same frozen-test boundary, all-prespecified-seeds reporting, and separation of the paper's optimistic-protocol label from validation-score optimism.

## Findings

1. **The validation score is an adaptive training/tuning signal.** It selects ensemble checkpoint snapshots, chooses greedy additions, and triggers stopping. With four base members and four retained snapshots, a later epoch has at most eight candidates; over 100 epochs there can nevertheless be up to 400 distinct current-member checkpoints. Multiple epochs of the same member are correlated candidates, not independent ensemble draws. The selected validation ROC-AUC is subject to selection optimism and must not be described as an unbiased generalization estimate. Strict positive improvement and patience limit search but do not establish statistical significance; fixed random hyperparameter ranges do not make validation-based member selection “no selection.”
2. **The test set must be a final audit, not a selection resource.** Keep the canonical train/validation/test split when obtainable. Fit all preprocessing on train only. Use validation for the predeclared checkpoint, greedy-member, and stopping rules; freeze the resulting ensemble and only then evaluate test ROC-AUC. Do not inspect test scores per epoch, choose a seed/checkpoint/member set by test score, or rerun after a test-driven change.
3. **Freeze the full protocol before confirmatory test evaluation.** The frozen specification includes data split, preprocessing, member sampling ranges, number of members, epoch/patience limits, metric direction, tie/strict-improvement rule, candidate-pool semantics, maximum ensemble size, seed list, and aggregation rule. Prefer completing and freezing all methods/seeds before showing any test metrics. Prespecify secondary metrics and any decision threshold too; use a fixed threshold or validation-only choice, never a test-optimized threshold. Do not silently refit preprocessing or weights on train+validation after selecting snapshots. A change made after seeing test results creates a new exploratory experiment; it cannot be folded into the same confirmatory result.
4. **Report all prespecified seeds, not the winner.** For seeds 0, 1, and 2, report each frozen-run test ROC-AUC plus mean and sample standard deviation (`ddof=1`). Never report the best seed, best epoch, or best member subset as the headline. This SD describes training/sampling variability on one fixed Churn split; it is not a confidence interval for new customers, split variability, or cross-dataset performance. With only three seeds, call uncertainty descriptive/preliminary and avoid significance claims. If comparing reduced TabPack-style, homogeneous independent ensemble, and ordinary MLP, apply the same split, seed count, and frozen-test rule to every method and retain paired per-seed differences where the run mapping is prespecified. Same seed IDs do not guarantee identical random streams across architectures. Distinguish mean of per-run AUCs from AUC of predictions averaged across seeds: the latter evaluates an extra cross-seed ensemble and is not the default estimand. Report failed/missing runs explicitly rather than replacing them with favorable seeds.
5. **Expose the size of the validation search.** Results artifacts should record, per seed, stopping epoch, number of validation evaluations, candidate count by epoch (including retained snapshots), selected member IDs and source epochs, final validation score, and final test score. This makes the selection opportunity visible and prevents a deceptively simple “best validation” number from hiding extensive search. The test score should be recorded only after selection is frozen.
6. **Holdout handling when development continues.** The untouched canonical test set already audits the entire adaptive validation-selection procedure; extra splitting is not necessary merely because validation is reused. Preserve canonical splits for this reduced experiment. If a future budget allows studying selection overfitting itself, predeclare an additional inner checkpoint/ensemble-selection split or nested resampling wholly within development data, leaving canonical test untouched. This reduces data available to each decision and is a separate, non-paper-equivalent protocol. If test outcomes have influenced development, a fresh genuinely untouched external/previously reserved holdout is needed for a new confirmatory claim. Reusing the same rows with another seed, repartitioning already-inspected rows, or merely locking a new configuration does not restore holdout independence.

## Recommended wording for the reduced result

“Reduced Churn results use the optimistic full-procedure multi-seed protocol, with fresh sampling and validation selection in each of three prespecified runs. Checkpointing, early stopping, and greedy member selection use validation ROC-AUC; test evaluation follows frozen selection. We report all three per-run test AUCs and their mean ± sample SD on the same canonical split. Validation scores are selection-optimistic; seed SD reflects run variability only. These reduced, preliminary measurements are not a reproduction of the paper's conservative protocol or paper-equivalent scores.”

Use this wording only if the recorded artifacts support it. If the test set was used to alter any setting, label the resulting numbers exploratory and disclose test reuse; a newly locked rerun on the same exposed test set is not a fresh confirmatory evaluation.
