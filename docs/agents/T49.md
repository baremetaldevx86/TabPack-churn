# T49 — Portable Windows PowerShell quickstart review

## Assignment and review boundary

Review a copy/paste-friendly Windows PowerShell 5.1 quickstart for the
reduced Churn experiment. It must cover an isolated venv, locked dependencies,
read-only preflight, explicit Churn acquisition, non-training dry-run, and the
three-family experiment command. This note proposes the final shape; the
package, lock files, downloader entry point, and CLI are not present in this
checkout, so the commands were not run and must be checked against the
integrated `--help` output before publication.

The examples use the CPU lock and `--device cpu` because that is the portable
acceptance path. A CUDA run needs the separately compiled CUDA lock, a tested
driver/runtime, and an explicit preflight receipt; installing a `+cu128` wheel
alone does not establish that CUDA is usable.

## PowerShell portability rules

* Invoke the venv interpreter by its full path. This avoids activation-policy
  failures and avoids accidentally using globally installed packages.
* Pass arguments through a PowerShell array (`& $python @args`). This keeps
  paths containing spaces as one argument and avoids fragile backtick line
  continuations. Do not use POSIX `source`, `./.venv/bin/python`, `&&`, or
  shell-specific quoting.
* Use `Test-Path -LiteralPath` before creating a parent directory. Never
  pre-create a non-empty run directory; `run` must own its fresh artifact
  directory.
* Check `$LASTEXITCODE` immediately after each native Python invocation. A
  displayed JSON object is not success if the process returned a nonzero code.
* Keep `preflight`, `dry-run`, and `run` offline with respect to acquisition.
  Data download is a separate, explicit, verified operation.

## Proposed quickstart

Run these from the repository root. The variables are deliberately ordinary
PowerShell strings; they may resolve to a checkout whose path contains spaces.

```powershell
$ErrorActionPreference = 'Stop'

$repo = (Get-Location).Path
$venv = Join-Path $repo '.venv'
$python = Join-Path $venv 'Scripts\python.exe'
$config = Join-Path $repo 'configs\churn_reduced.yaml'
$dataRoot = Join-Path $repo 'data\churn'
$runsRoot = Join-Path $repo 'runs'
$runDir = Join-Path $runsRoot 'churn-reduced'
$cpuLock = Join-Path $repo 'requirements\py312-win-cpu.txt'

if (-not (Test-Path -LiteralPath $repo -PathType Container)) {
    throw 'Run this from the filesystem repository root.'
}
if (-not (Get-Command py -ErrorAction SilentlyContinue)) {
    throw 'The Python launcher (py.exe) was not found; install/select CPython 3.12 first.'
}
if (Test-Path -LiteralPath $venv) {
    throw "Refusing to replace existing venv: $venv"
}
& py -3.12 -m venv $venv
if ($LASTEXITCODE -ne 0) { throw 'venv creation failed.' }
if (-not (Test-Path -LiteralPath $python)) {
    throw "The venv interpreter was not created: $python"
}
& $python -c "import sys,struct; print(sys.executable); print(sys.version); raise SystemExit(0 if sys.version_info[:2] == (3, 12) and struct.calcsize('P') == 8 else 1)"
if ($LASTEXITCODE -ne 0) { throw 'The venv is not running supported 64-bit Python 3.12.' }
```

The `py -3.12` selector verifies the minor version, not necessarily patch
version 3.12.10. If the final lock requires that exact patch, add a check for
`sys.version_info[:3]` and fail before installation.

### Install the selected lock

The coordinator should publish both `requirements\py312-win-cpu.txt` and
`requirements\py312-win-cu128.txt`, with every third-party requirement pinned
and hashed. The lock/build-tool setup must also supply the packaging backend
before the `--no-build-isolation` step; include the final config parser if YAML
is retained. Do not install both torch variants into one venv. The bootstrap pip
upgrade is separate from the experiment lock; it is not evidence that the
global pip or global packages are being used.

```powershell
if (-not (Test-Path -LiteralPath $cpuLock)) {
    throw "Missing resolved lock: $cpuLock"
}

& $python -m pip install --disable-pip-version-check --upgrade --only-binary=:all: pip==25.2
if ($LASTEXITCODE -ne 0) { throw 'Pinned pip bootstrap failed.' }

$installArgs = @(
    '-m', 'pip', 'install',
    '--require-hashes', '--only-binary=:all:',
    '-r', $cpuLock
)
& $python @installArgs
if ($LASTEXITCODE -ne 0) { throw 'Locked dependency installation failed.' }

& $python -m pip check
if ($LASTEXITCODE -ne 0) { throw 'pip check failed.' }

# Run only after the local package/entry point has been integrated.
if (-not (Test-Path -LiteralPath (Join-Path $repo 'pyproject.toml'))) {
    throw 'The local package metadata is not present; do not substitute a global install.'
}
& $python -m pip install --no-deps --no-build-isolation -e $repo
if ($LASTEXITCODE -ne 0) { throw 'Local package installation failed.' }

& $python -m tabpack.cli --help
if ($LASTEXITCODE -ne 0) { throw 'The tabpack CLI is not importable from the isolated venv.' }
```

For an explicitly tested CUDA environment, replace `$cpuLock` with the CUDA
lock and record that choice. Use `--device cuda` only when CUDA preflight is
healthy; use `--device auto` only when a recorded CPU fallback is acceptable.
Do not silently retry a failed explicit-CUDA run on CPU.

### First preflight (before data)

This confirms the config/environment and gives the expected missing-data
diagnostic without downloading or creating a run directory. A code 3 with
`DATA_MISSING` is expected before acquisition; any other error must be fixed
before continuing. The final post-acquisition preflight below must return zero.

```powershell
if (-not (Test-Path -LiteralPath $repo -PathType Container)) {
    throw 'The repository parent is not a filesystem directory.'
}
if (-not (Test-Path -LiteralPath $runsRoot)) {
    New-Item -ItemType Directory -Path $runsRoot | Out-Null
}
if (-not (Test-Path -LiteralPath $runsRoot -PathType Container)) {
    throw 'The runs parent is not a directory.'
}
if (Test-Path -LiteralPath $runDir) {
    throw "Run directory already exists; choose a fresh run ID: $runDir"
}

$commonArgs = @(
    '--config', $config,
    '--data-root', $dataRoot,
    '--device', 'cpu',
    '--num-workers', '0',
    '--seeds', '0,1,2',
    '--families', 'ordinary,independent,packed'
)
$preflightArgs = @('-m', 'tabpack.cli', 'preflight') + $commonArgs + @(
    '--run-dir', $runDir,
    '--json'
)
& $python @preflightArgs
$preflightExit = $LASTEXITCODE
if (($preflightExit -ne 0) -and ($preflightExit -ne 3)) {
    throw "Initial preflight failed with exit code $preflightExit."
}
```

Inspect the JSON rather than treating every code 3 as harmless. Preflight is
side-effect free by default: it must not create `$dataRoot`, `$runDir`, a
checkpoint, or a cache, and must not call the network. The setup above creates
only `$runsRoot`, whose writability preflight can inspect; this is distinct
from preflight creating an artifact directory.

### Final preflight and non-training dry-run

Use strict preflight after data validation so warnings cannot be mistaken for
readiness. `dry-run` resolves the plan but must not train, initialize an
optimizer, evaluate test data, download data, or create `$runDir`.

```powershell
$strictPreflightArgs = @('-m', 'tabpack.cli', 'preflight') + $commonArgs + @(
    '--run-dir', $runDir,
    '--strict',
    '--json'
)
& $python @strictPreflightArgs
if ($LASTEXITCODE -ne 0) { throw 'Post-acquisition preflight did not pass.' }

$dryRunArgs = @('-m', 'tabpack.cli', 'dry-run') + $commonArgs + @(
    '--run-dir', $runDir,
    '--strict',
    '--json'
)
& $python @dryRunArgs
if ($LASTEXITCODE -ne 0) { throw 'Dry-run failed.' }
if (Test-Path -LiteralPath $runDir) {
    throw "Dry-run unexpectedly created the run directory: $runDir"
}
```

Review the plan for the resolved data fingerprint, three families, four base
members for each ensemble, seeds, sampled member hyperparameters, device,
feature width, budget, and the reduced TabPack-style optimistic label. A
dry-run plan is not a result and must not be passed to `report`.

### Full reduced experiment

Reuse the parent directory created above, then let `run` create the fresh run
directory. The command below uses the provisional ledger protocol: seeds
`0,1,2`, all three families, CPU, and zero workers. The versioned config must
carry the four-member, 100-epoch, patience-16, batch-256, float32, optimizer,
and selection settings; do not assume an abbreviated command supplies them.

```powershell
$runsParent = Split-Path -Parent $runDir
if (-not (Test-Path -LiteralPath $runsParent -PathType Container)) {
    throw "Run parent is missing or not a directory: $runsParent"
}
if (Test-Path -LiteralPath $runDir) {
    throw "Run directory already exists; choose a fresh run ID: $runDir"
}

$runArgs = @('-m', 'tabpack.cli', 'run') + $commonArgs + @(
    '--run-dir', $runDir
)
& $python @runArgs
if ($LASTEXITCODE -ne 0) { throw 'Reduced experiment failed or was incomplete.' }
```

Use a fresh run ID for every changed config, device, lock, or data identity.
Do not add an unrecognized `--smoke` dataset switch. A short real-Churn
readiness run must use an explicit smaller config and be labelled noncanonical;
the offline synthetic smoke path should use the injected test fixture from
T42, not production acquisition or a synthetic fallback.

An optional artifact-only report can be generated after a complete run:

```powershell
$reportParent = Join-Path $repo 'reports'
if (-not (Test-Path -LiteralPath $repo -PathType Container)) {
    throw 'The repository parent is not a filesystem directory.'
}
if (-not (Test-Path -LiteralPath $reportParent)) {
    New-Item -ItemType Directory -Path $reportParent | Out-Null
}
$reportPath = Join-Path $reportParent 'churn-reduced.md'
$reportArgs = @(
    '-m', 'tabpack.cli', 'report',
    '--run-dir', $runDir,
    '--format', 'markdown',
    '--output', $reportPath,
    '--strict'
)
& $python @reportArgs
if ($LASTEXITCODE -ne 0) { throw 'Strict report generation failed.' }
```

## Review findings and integration actions

1. **T12 dependency guidance adopted.** Use direct venv invocation, separate
   CPU/CUDA locks, `--require-hashes --only-binary=:all:`, pinned bootstrap
   pip, and `pip check`. Do not use raw `pip freeze` as provenance; capture
   sanitized active-interpreter distribution metadata and the selected lock
   digest per T48.
2. **T19/T41 preflight behavior adopted.** Preflight is offline and
   side-effect free; explicit CPU is portable, explicit CUDA is strict, and
   the initial missing-data code 3 is distinct from final strict readiness.
   The argument arrays preserve paths with spaces and the documented exit
   status is checked immediately.
3. **T38 acquisition review adopted.** The quickstart intentionally leaves the
   downloader module unresolved rather than encouraging an unsafe ad hoc
   archive pipeline. T7 must supply the final source lock, consumed-file
   manifest, and exact verified command before this template can be published.
4. **T28 correction.** T28's older `run --smoke` example and unpinned install
   placeholders are not suitable as final quickstart commands. T41's current
   contract says synthetic smoke is an injected test fixture and that real
   readiness uses a separately labelled config.
5. **T48 provenance boundary adopted.** The quickstart records the lock,
   source/data identities, resolved configuration, device, seeds, and run
   artifacts through the integrated manifest. Public provenance must exclude
   secrets, absolute paths, raw environment dumps, and signed download URLs;
   the displayed interpreter path is local diagnostic output only.

## Acceptance checklist

Before publication, the coordinator should verify in a fresh Windows 5.1
PowerShell session:

* a checkout path containing spaces works without activation;
* Python 3.12 and the selected lock install into a fresh venv, `pip check`
  passes, and the local CLI help resolves from that venv;
* preflight does not create data/run artifacts and reports `DATA_MISSING`
  before acquisition;
* the approved downloader rejects mutable/unverified sources and publishes
  only a validated canonical Churn root;
* final strict preflight returns zero, dry-run returns zero without a run
  directory, and the plan is deterministic apart from volatile diagnostics;
* the full command resolves all requested seeds/families and creates a fresh
  complete run; and
* report rejects incomplete/mixed artifacts and preserves the reduced,
  non-paper-equivalent qualification.
