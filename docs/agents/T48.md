# T48 — Secret-free provenance artifact specification

## Assignment and evidence

Specify a portable provenance record for each measured Churn experiment. This is a proposed integration contract, not an emitted run record.

- `swarm.md`: reduced protocol, canonical splits, coordinator-reported hardware, and pinned upstream revision.
- [Official README at the pinned revision](https://raw.githubusercontent.com/yandex-research/tabpack/05a89e21b955f12de84889d662e15ca534019aaa/README.md): identifies the official repository and the public dataset archive URL. The README's `resolve/main` archive URL is mutable; it is not a content identity.
- [Paper v1](https://arxiv.org/html/2607.05380v1): reference URL supplied by the coordinator; no additional paper claims are made here.
- [RFC 3339 §5.6](https://www.rfc-editor.org/rfc/rfc3339#section-5.6): timestamp format.
- Read-only `git rev-parse --verify HEAD` failed with `fatal: Needed a single revision` during this review. An unborn repository must be represented explicitly, not assigned the upstream SHA.

## Artifact and lifecycle

Proposed location, aligned with T20: `runs/<experiment_id>/<run_id>/provenance.json`, accompanied by `config.resolved.json`, `source-files.json`, and `data-files.json`. Paths are relative logical artifact names, with `/` separators. One run ID means one method/seed attempt; an aggregate lists accepted run IDs and finalized provenance-file SHA-256 values. Because `runs/` is ignored, the coordinator should publish the small secret-free evidence bundle under a retained location such as `reports/<experiment_id>/`.

1. Generate a random run ID independent of machine/user identity. Capture inputs and environment before training. Write an atomic `provenance.progress.json` with `status: "running"`; aggregators ignore progress files.
2. Record selection freeze before final test evaluation. Finalize `provenance.json` with `status: "complete"`, `"failed"`, or `"cancelled"`, matching T20; use controlled error codes, not raw exception text. A running or failed artifact cannot be aggregated as a completed score.
3. Hash completed checkpoint/selection files and finalize provenance atomically; then write T20's `result.json` referencing the provenance hash. Provenance may name the result path but must not hash that result, avoiding a cyclic hash dependency. An experiment-level index can hash both final files. A companion `provenance.sha256` may hash the final manifest bytes; do not put a self-referential manifest hash inside it.
4. Do not overwrite completed runs. A resume receives a new attempt ID plus parent run/checkpoint hashes and preserves earlier timestamps. Hash/data/config mismatches are explicit incompatibilities, not silent continuation.

## Required fields

Use `schema_name: "tabpack-provenance"` and integer `schema_version: 1`, aligning T20's versioning convention. A missing observation uses `null` and a structured reason such as `not_available`, `not_applicable`, or `unborn_repository`; never invent values. Required reproducibility inputs must be present before a run is accepted as release evidence.

| Group | Required content |
| --- | --- |
| `run` | Experiment ID, run ID, nonnegative attempt number, method, seed, status, protocol label `reduced_tabpack_style_optimistic`, optional parent run/checkpoint identity. |
| `git` | **Local implementation** full `sha`, Git object format, `dirty` boolean, `head_state`, and `source_inventory_sha256`. Capture before execution; do not substitute a later release commit. Exclude author identity and remote configuration. |
| `sources` | Role, public canonical URL, immutable revision/version when available, and UTC observation/retrieval time. Separate paper, upstream reference code, and actual dataset source. Record whether an expected data digest is upstream-published or locally observed. |
| `software` | Python implementation/full version, OS family/release/build/architecture, exact installed distribution names and versions from the **running interpreter**, dependency-lock relative path and SHA-256 when present. Capture at least torch, numpy, scipy, scikit-learn, and all other experiment-runtime distributions/transitive dependencies. Preserve torch build suffix, e.g. `+cu128`. Record CUDA build version, cuDNN version, and actual GPU driver version separately. |
| `hardware` | CPU model, physical/logical core counts if observable, total RAM bytes, accelerator model/count/VRAM bytes/compute capability, requested and actual device. Use `null` plus reason when unavailable; CPU execution uses an empty selected-accelerators list. Record visible accelerators separately from those actually used. |
| `execution` | Dtype, seed-stream derivation scheme/version, deterministic-algorithm settings, cuDNN benchmark/deterministic settings, TF32 settings, torch thread counts, workers, and relevant numeric threading/runtime settings via a typed allowlist. | `data` | Dataset name `churn`, source revision, inventory path, aggregate SHA-256, per-file raw byte hashes/sizes/roles, split names/row counts/feature schema, target mapping, preprocessing configuration and train-only fit split. Optional fitted-preprocessor artifact hash links the exact learned transform. |
| `timestamps` | Manifest creation, source/data retrieval when observed, run start/end, selection frozen, test evaluation start/end, finalization; UTC RFC 3339 strings with fixed millisecond precision, e.g. `2026-09-25T12:34:56.789Z`. Unobserved historical retrieval times remain null. |

## Exact hashing rules

**Byte hashes:** SHA-256, lowercase 64-character hexadecimal. Hash the bytes actually consumed or written, not file names, modification times, decoded text, or remote ETags. Re-read and compare inputs at finalization, or train from an immutable captured input snapshot; record failure if they changed during the run.

**Canonical JSON, `python-json-v1`:** objects have string keys; accepted values are JSON scalars, arrays, and objects; finite numbers only; no duplicate keys. Serialize the validated typed object with `json.dumps(value, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False).encode("utf-8")`, with no BOM or trailing newline. Store these exact canonical bytes and hash them. Record Python version. This is a deliberately versioned Python serialization convention, not a claim of RFC 8785/cross-language numeric canonicalization. Consumers can verify the stored bytes without reserializing floats.

**Config hash:** expand defaults and CLI overrides, normalize types, and materialize ordered sampled member configurations before hashing. Include dataset identity hash, train/val/test roles, preprocessing parameters/random state, method, master/member seeds and derivation version, architecture/optimizer/selection rules, tie tolerance/order, patience/epoch/batch budgets, dtype/device, and determinism settings. Exclude output directories, timestamps, run IDs, and host-specific input paths; the dataset hash identifies input content. Reject unknown config fields and secrets before serialization. The hash must describe the effective computation, not merely the input YAML/TOML file. Keep the original user-config byte hash optionally as an additional identity.

**Data hash:** `data-files.json` is a canonical JSON array of records `{ "path": <relative logical input path>, "role": <train/val/test/schema role>, "size_bytes": <integer>, "sha256": <byte hash> }`, sorted lexicographically by `path`. Include every consumed split array/table, target, feature/schema metadata file, and any consumed split-index file. Paths are relative to the dataset root, normalized to `/`, unique, and cannot contain traversal or absolute roots. The data hash is SHA-256 of this inventory's canonical bytes. Do not include timestamps, cache paths, or download URL in this hash: transport/cache differences should not change data identity. Include row-order-sensitive raw split bytes so reordering is detected. If an archive is already downloaded, its hash is an additional transport identity, not a replacement for consumed-file hashes.

**Source hash:** `source-files.json` uses the same sorted file-inventory rule with roles for independently authored runtime code, preprocessing/downloading code, dependency definitions/lock, and experiment configuration definitions. Capture every executable run input, including untracked runtime code, from an explicit package/entrypoint allowlist; omit output, `.git`, `.venv`, local settings, research notes, and unrelated files. Store inventory SHA-256. Git SHA identifies the committed tree; the byte inventory distinguishes dirty/untracked/line-ending differences. File hashes alone cannot reconstruct unavailable dirty source: release evidence needs a retained immutable source snapshot/commit matching the recorded inventory. A null local SHA is valid diagnostic metadata but incomplete release provenance.

## Secret-free collection

- Build the artifact from approved typed fields; do not dump environment variables, `pip freeze`, `pip config`, Git config/remotes, HTTP headers, raw CLI arguments, arbitrary exception messages, or complete system diagnostic output.
- Collect installed dependency **name and version** from `importlib.metadata` in the active isolated interpreter. Do not serialize `direct_url.json`, editable-install local paths, index credentials, or the user's global package environment.
- Source URLs must be public canonical identities: HTTPS origin/path and only known nonsecret revision parameters where essential. Drop userinfo, fragments, signed-download query strings, access tokens, and redirect URLs. Store a public revision plus content digest instead of an expiring signed transport URL.
- Omit username, hostname, home/absolute workspace paths, IP/MAC addresses, GPU UUIDs, hardware serials, process command lines, and credential values. CPU/GPU product names and aggregate capacities suffice.
- Do not include secrets in config, even as hashes or redacted secret hashes. Parse only the experiment schema; acquisition credentials belong outside it. Opaque external file locations receive stable logical aliases and content identities.
- Do not embed dataset records, customer identifiers, or row-level hashes. Whole input-file hashes, feature schema, and aggregate counts are sufficient for this public reproducibility artifact.

## Acceptance checks for integration

1. Round-trip JSON and recompute config/data/source inventory digests from saved bytes; no unsupported schema version, placeholder digest, NaN, or duplicate path is accepted.
2. Changing a seed, effective default, sampled member order, split bytes, or split role changes the relevant identity; changing workspace location, source-download timestamp, or run ID does not change config/data identities.
3. Compare active dependency versions with the retained lock/environment selection; distinguish torch CUDA build support from actual driver/hardware availability. CPU runs must not claim GPU timing.
4. Ensure complete runs have start/end/finalization times and freeze-before-test ordering. Record any detected wall-clock adjustment and use monotonic event ordering/durations rather than rewriting timestamps.
5. Validate a synthetic credential-bearing input/URL fixture: it is rejected or reduced to an approved public identity, with no credential present in emitted text, logs, errors, or hashes of secret config values.
6. Check local SHA and source inventory independently of the upstream SHA. A release commit that only adds results can link to the earlier recorded execution SHA; it must not rewrite the run's history.
7. Aggregation must retain run IDs and manifest digests, and reject incompatible protocol/data/config families unless differences are explicitly grouped. Compare method-specific configs using shared split/preprocessing/budget fields, not identical whole-config hashes across different methods.
