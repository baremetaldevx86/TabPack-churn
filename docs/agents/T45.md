# T45 — Independent packed-training oracle test design

## Assignment and status

Design an independent, small oracle for packed versus explicitly looped member
predictions and training. The test is a design for the coordinator and model /
optimizer owners to integrate; it is not an implementation or a claim that a
training run passed.

The oracle must not obtain expected values by unpacking the packed model, by
calling a second packed implementation, or by copying the packed model's
randomly initialized state into the reference. It constructs logical member
parameters independently, builds an ordinary looped reference, and gives the
same logical parameters to the packed model through a documented test seam.

## Required independent fixture

Run on CPU, float32, with dropout disabled and deterministic settings. Use a
fixed tensor fixture rather than a random data generator or a real dataset:

```python
x = torch.tensor([
    [-1.0, -0.5,  0.2,  0.7],
    [-0.4,  0.8, -0.7,  0.1],
    [ 0.2, -0.3,  1.1, -0.9],
    [ 0.9,  0.4, -0.2,  0.6],
    [-0.8,  0.6,  0.5, -0.4],
    [ 0.3, -1.0,  0.8,  0.2],
    [ 1.2,  0.1, -0.6, -0.5],
    [-0.1,  0.9, -0.9,  1.0],
], dtype=torch.float32)
y = torch.tensor([0., 1., 1., 0., 1., 0., 1., 0.], dtype=torch.float32)
indices = torch.tensor([
    [0, 1, 2, 3, 4, 5, 6, 7],
    [6, 3, 0, 7, 4, 1, 5, 2],
    [2, 5, 7, 0, 3, 6, 1, 4],
])
step_indices = [indices[:, :3], indices[:, 3:6], indices[:, 6:],
                indices[:, :1]]  # B=3,3,2,1; fourth step is a shape stress case
# Each step: batch_x = x[I] -> [M,B,F], batch_y = y[I] -> [M,B].
```

These member-specific permutations check input/label routing over several
steps without introducing a data-loader RNG. They are controlled test inputs,
not evidence about random-stream independence. The fixture has
nonconstant features and labels, and the member parameter formula below makes
member gradients intentionally different. The test must assert that the
initial gradient norm is nonzero for each member and that their output-bias
gradients are not all equal; otherwise a member permutation or accidental
broadcast could pass by coincidence. Individual ReLU-connected entries can
legitimately have zero gradients.

Use three heterogeneous members. Treat `hidden_widths` as the exact ordered
list of hidden layers; if the production API exposes `depth`, use
`depth == len(hidden_widths)` for this fixture:

| member | hidden widths | output | learning rate | weight decay |
| ---: | --- | ---: | ---: | ---: |
| 0 | `[3]` | 1 | `1.0e-2` | `0.0` |
| 1 | `[5, 5]` | 1 | `7.0e-3` | `1.0e-4` |
| 2 | `[4, 4, 4]` | 1 | `4.0e-3` | `3.0e-4` |

Every hidden linear layer is followed by ReLU; the final linear layer produces
one logit. There is no output sigmoid in the model. Use AdamW
`betas=(0.9, 0.99)`, `eps=1e-8`, `maximize=False`, `amsgrad=False`, and no
gradient clipping; use `foreach=False, fused=False` on the ordinary oracle.
Each member has one width throughout its hidden blocks, matching the reduced
depth/width configuration rather than requiring an extra variable-layer API.
The per-member hyperparameters are intentional: they expose shared optimizer
state or accidentally shared learning-rate/decay handling.

Generate the initial logical tensors in the test itself, independently of the
model constructor. For example, a deterministic arithmetic helper can use a
fresh `arange` for each requested shape:

```python
def make_weight(shape, member, layer):
    n = math.prod(shape)
    z = torch.arange(1, n + 1, dtype=torch.float32).reshape(shape)
    return (0.013 * (((member + 2) * (layer + 3) * z) % 17 - 8)).clone()

def make_bias(shape, member, layer, *, is_head):
    n = math.prod(shape)
    z = torch.arange(1, n + 1, dtype=torch.float32).reshape(shape)
    if is_head:
        return torch.full(shape, [-0.7, 0.4, 1.1][member], dtype=torch.float32)
    return (0.2 + 0.009 * (((member + 3) * (layer + 5) * z) % 19 - 9)).clone()
```

The exact arithmetic is less important than being deterministic, visible in
the test, and independent of packed storage. Store these as a list of cloned
`(weight, bias)` tensors for each member. Never create the reference by
reading `packed.state_dict()`, and assert that reference member tensors do not
share storage with one another or with tensors handed to the packed model.

## Independent reference implementation

The reference should be a minimal test-local `ExplicitMembers` module (or
plain tensor function) containing one ordinary `ModuleList` per member. It
must implement only the mathematical operation needed by this test, not any
production helper:

```python
def explicit_logits(member_layers, features, *, member_inputs=False):
    logits = []
    for member, layers in enumerate(member_layers):
        h = features[member] if member_inputs else features
        for layer_index, (weight, bias) in enumerate(layers):
            h = h @ weight.T + bias          # independent reference equation
            if layer_index + 1 != len(layers):
                h = torch.relu(h)
        logits.append(h[:, 0])
    return torch.stack(logits, dim=0)         # [members, batch]
```

If `nn.Linear` is used instead, assign the independent tensors to ordinary
looped modules and make the same explicit loop. Do not use the packed model's
forward, unpack routine, masks, loss helper, or output post-processing in the
reference. The expected probability tensor is calculated independently as
`torch.sigmoid(explicit_logits(...))`.

The packed side needs a narrow, documented test seam accepting the logical
member layer tensors (for example, `load_logical_member_parameters`). The
seam may copy these tensors into packed storage, but it must not silently
reinitialize them. If the production API exposes only a state dictionary,
the coordinator should provide a test adapter whose input is the list of
logical per-member tensors. Following T21/T22, document the logical-to-physical
map explicitly, including any matrix transpose; do not trust an export helper
as the sole check of the import helper. The adapter must contain no forward,
loss, or optimizer mathematics. Disjoint member slices may legitimately share
one packed allocation; do not reject packed storage merely for that reason.
After loading, verify the packed model's documented active logical slices
match the fixture tensors once, and verify that any padded slots start at
zero or at their documented inert value. This is a setup check, not an oracle
constructed from packed values.

## Test A: heterogeneous prediction and loss oracle

Suggested name: `test_packed_forward_matches_explicit_member_oracle`.

1. Construct the independent layer tensors, the explicit reference, and a
   packed model with the table above. Load the same logical tensors through
   the test seam. Use `x` as one batch.
2. Call the packed model once and obtain member logits with shape `[3, 8]`.
   If its public contract is `[3,8,1]`, assert that exact raw shape and remove
   only the final dimension. No bare `squeeze()` or implicit broadcasting.
   Supply `x.expand(3,-1,-1)` if shared `[B,F]` inputs are unsupported.
   Call `explicit_logits` once. Compare logits **member by member**, not just
   their mean: `torch.testing.assert_close(..., rtol=1e-6, atol=1e-7)`.
3. Independently compute probabilities with sigmoid on both logits. Assert
   shape `[3, 8]`, finite values, and values in `[0, 1]`. Assert the packed
   ensemble probability equals the arithmetic mean over the member
   probabilities, not the sigmoid of mean logits. Compare this mean to the
   production ensemble output at `rtol=1e-6, atol=1e-7`.
4. Independently compute the objective on both sides with
   `binary_cross_entropy_with_logits`:

   ```python
   member_losses = F.binary_cross_entropy_with_logits(
       explicit_logits(member_layers, x), y.expand(3, -1), reduction="none"
   ).mean(dim=1)
   expected_total = member_losses.sum()
   ```

   Compare the packed objective to `expected_total`. The expected reduction is
   mean over the eight samples **for each member**, followed by sum over the
   three members. Do not use a production loss helper to create the expected
   value. Also compare packed and reference gradients before any optimizer
   step; each logical active parameter's gradient must match and padded packed
   entries must be zero/absent.
5. Assert the three member logits and losses are not all identical. This
   catches a model that broadcasts one member's result to the pack while still
   satisfying a weak ensemble-average assertion.

This test is deliberately heterogeneous: member 0 exercises unused depth and
width slots, member 1 exercises a middle depth, and member 2 reaches the
maximum depth. It therefore checks active/padded masks without making a mask
derived from the packed output the expected answer.

## Test B: short packed-training trajectory oracle

Suggested name: `test_packed_training_matches_explicit_looped_adamw`.

Use the same independently generated parameters and four fixed member-indexed
batches. Index both features and labels with the identical `[M,B]` index tensor;
never expand a shared label vector in this training case. Make
fresh copies for the packed and reference runs; no tensor or optimizer state
may be shared between them.

For the reference, execute this ordinary loop at each batch:

```python
reference_losses = []
for member, optimizer in enumerate(reference_optimizers):
    optimizer.zero_grad(set_to_none=True)
    z = explicit_logits([reference_members[member]], batch_x[member])[0]
    loss = F.binary_cross_entropy_with_logits(z, batch_y[member], reduction="mean")
    loss.backward()                          # independent backward, one member
    reference_losses.append(loss.detach())
    # Save this member's logits/gradients for the pre-update assertions.
    optimizer.step()                         # one AdamW per logical member
expected_total = sum(reference_losses)        # reporting comparison only
```

The reference optimizer list contains three ordinary `torch.optim.AdamW`
instances, each owning only that member's `nn.Parameter`s and its own
`lr`/`weight_decay` from the table. This is an explicit loop over ordinary
parameters, not the production packed optimizer. Separate mean BCE backward
calls avoid duplicating the packed reduction in the reference. Summing losses
here is only a scalar observation; it does not drive reference updates.

On the packed side, invoke the normal production packed training/optimizer
entrypoint with the same batch and hyperparameters. If the entrypoint takes a
loss closure, the test may compute its packed-side logits and the BCE formula
above directly; it must not call a production loss helper to obtain the
expected reference. If the entrypoint owns loss construction, instrument it
only to expose the scalar and gradients for comparison.
Use `reduction="none"`, then `.mean(dim=1).sum()` for the packed loss;
`batch_y` already has the full `[M,B]` shape. This exercises actual production
loss construction when that entrypoint exists; manually constructing it tests
the model/optimizer bridge only and must be labeled accordingly.

After every one of the four steps, compare:

- packed member logits on the just-used batch and on the full `x` against the
  explicit reference, member by member;
- member probabilities and arithmetic mean probabilities;
- each member's mean loss and the summed total loss before the update;
- every active logical weight and bias tensor, with the production's mapping
  adapter selecting active slices from packed storage;
- each active AdamW state tensor (`exp_avg`, `exp_avg_sq`, and step count), if
  the production optimizer exposes state. The packed state may be physically
  padded, but its active slices must equal the corresponding ordinary
  optimizer state;
- padded parameter values and padded optimizer moments, which must stay at
  their documented inert values and receive no updates.

Use candidate CPU float32 bounds `rtol=2e-5, atol=2e-6` for post-update
parameters/logits, and `rtol=2e-5, atol=2e-7` for gradients and optimizer state.
Following T22, compare update deltas too, and use targeted relative comparisons
for deliberately small nonzero gradients/moments; a generic absolute bound
must not allow a zero expected-to-be-nonzero moment to pass. Compare counters
exactly. These are proposed bounds, not measured implementation tolerances.
If the implementation deliberately documents a different numerical
accumulation order, tighten or relax only after a CPU measurement and record
the reason; never replace parity with an aggregate score check. A final
comparison only is insufficient: checking every step localizes a first-step
loss/reduction error from a later optimizer/state error.

The test should also record a pre-step gradient comparison. A missing
division by sample count, an extra division by member count, or training on
an averaged ensemble prediction will then fail before AdamW's normalization can
partially hide the scaling. The expected total is a **sum**, not a mean over
members.

## Companion sensitivity checks

Keep these tiny and reuse the independent fixture rather than duplicating an
entire test suite:

1. **Pack-size invariance (T33):** replay member 0 alone, then with the two
   companions, preserving its logical weights, hyperparameters, and explicit
   batch indices. Compare its raw gradients, moments, update deltas, and
   full-input logits after each step against its same standalone oracle.
2. **Cross-member isolation:** repeat one step after changing only member 1's
   labels or head bias. Members 0 and 2 must remain unchanged relative to the
   unperturbed run, while member 1 must show a nonzero expected change.
3. **Negative control:** in a test-local loss expression, replace the member
   sum by a mean. Confirm the raw-gradient assertion detects the factor of
   three. This establishes assertion sensitivity without mutating production
   source. Similarly verify that broadcasting member 0's labels to the others
   fails for the declared member index fixture.
4. **Dropout boundary (T21):** the core trajectory proves zero-dropout parity
   only. Add a controlled-mask replay with rates `[0,0.1,0.2]` if the production
   forward offers the explicit mask seam specified by T21 F07. Supply the same
   logical keep masks to ordinary and packed paths, applying
   `h * keep / (1-p)` only after active hidden blocks. Retain ordinary independent
   backward/AdamW calls and stepwise assertions. A common global seed is not
   an adequate mask oracle; if the seam is unavailable, report this extension
   as unimplemented rather than claiming stochastic-training equivalence.

## Required guards against circular or weak assertions

- The oracle owns the input values, architecture list, initial tensors, BCE
  equation, sigmoid equation, and ordinary AdamW reference. None is read from
  packed model output or metadata.
- Compare `[member, sample]` logits and gradients, never only the averaged
  ensemble probability, final ROC-AUC, or a hand-written golden metric.
- Do not seed the packed constructor and copy its state into the reference.
  Seed state is irrelevant because all logical tensors are injected from the
  fixture.
- Do not compare a packed model with a second implementation that shares its
  packing helper, mask helper, loss helper, optimizer, or state serializer.
- Ensure all three reference members have separate parameter objects and
  optimizer objects. A storage alias assertion is useful for catching a
  reference that accidentally shares a tensor.
- Check the first failing step and member in the assertion message, including
  logical layer and active slice. Avoid an allclose over a flattened state
  that could hide a member permutation.
- Keep this to four direct optimizer steps on eight rows. It is an oracle, not
  a long training experiment, a speed benchmark, or Churn evidence.

Expected bug detection includes: member broadcasting or permutation (per-
member logits fail), sigmoid-before-BCE (loss/gradient fail), mean-over-
members reduction (pre-step gradients fail), wrong active/padded mask (short
member or padded state fails), parameter sharing (two member states fail), and
shared AdamW hyperparameters/state (trajectory diverges after a step with the
distinct table values).
