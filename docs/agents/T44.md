## Proposed reporting contract

1. The observation unit is **one completed experiment run for one method and seed**. Ensemble members, epochs, selected snapshots, and mini-batches are not independent runs.
2. Aggregate within a declared comparable experiment group and method. Its identity must distinguish dataset/split fingerprint, protocol/budget, and relevant execution context (especially device/dtype for timing). The configured seed list is the expected population of runs. Do not group by run-specific timestamps or accidentally split each seed into its own group.
3. For finite scalar values `x`, report arithmetic mean and **sample** standard deviation, with denominator `n - 1`. Label the convention. Preserve unrounded numeric values in artifacts; round only for display.
4. For `n = 1`, report the observation as mean and `null` std; for `n = 0`, report `null` for both. A measured zero remains zero. Do not emit NaN/Infinity into JSON.
5. Report expected, successful, failed, cancelled, and absent seeds/runs distinctly. A live/in-progress run belongs to the separate progress artifact described by T20, not a completed `result.json`. Incomplete groups may have an explicitly incomplete descriptive summary; a strict completeness gate must fail instead of producing an apparently complete result.
6. Required final metrics missing from a nominally successful record are validation errors. Missing optional measurements have per-field counts and do not erase otherwise valid metrics. Never average over zero-filled omissions.
7. Duplicate logical `(experiment group, method, seed)` outcomes are errors until the manifest explicitly names an accepted run ID and reason. Do not select the last file encountered or the highest test score; failed/cancelled attempts remain visible.
8. JSON preserves the declared schema and scalar types. CSV preserves its declared flat table projection; it need not reconstruct nested run artifacts. Determinism includes ordering, formatting, and omission of newly generated timestamps from the canonical aggregation payload.

## Golden fixtures and independent oracles

Use three successful records for one method, with different run IDs and seeds:

| seed | test ROC-AUC | test log-loss | measured training seconds | member count |
| --- | --- | --- | --- | --- |
| 0 | 0.6 | 0.2 | 10 | 1 |
| 1 | 0.7 | 0.4 | 14 | 4 |
| 2 | 0.8 | 0.6 | 18 | 7 |

The varying member count is a dedicated observation-unit fixture; real homogeneous-budget groups should carry valid fixed-budget metadata.

Expected numerical summaries:

| field | n | mean | sample std |
| --- | --- | --- | --- |
| ROC-AUC | 3 | 0.7 | 0.1 |
| log-loss | 3 | 0.4 | 0.2 |
| training seconds | 3 | 14 | 4 |

Additional hand-checkable variants:

- Remove seed 1: ROC-AUC mean `0.7`, std `sqrt(0.02) = 0.1414213562373095`; seeds 0 and 2 contribute equally.
- Retain only seed 0: ROC-AUC mean `0.6`, std `null`, count 1.
- Three identical ROC-AUC values `0.7`: std `0.0`, not `null`.
- Three timing values `[0, 0, 0]`: both mean and std `0.0`.
- Two methods with ROC-AUC vectors `[0.6, 0.7, 0.8]` and `[0.2, 0.3, 0.4]`: means `0.7` and `0.3`, never a pooled `0.5`.
- Three large finite timings `[1e12, 1e12 + 2, 1e12 + 4]`: mean `1e12 + 2`, std `2`; this detects cancellation in a naive `E[x²] - E[x]²` calculation.

Use literal expected values and Python standard-library `statistics.mean`/`statistics.stdev` as independent cross-checks. Never compute test expectations with the production aggregation helper. For ordinary float64 calculations use a small numerical tolerance (for example `1e-12` absolute/relative); compare counts, identities, nulls, and output ordering exactly.

## Serialization comparison details

- Compare JSON objects semantically for round-trips **and** bytes for canonical output determinism; these detect different failures. Python's `True == 1` means plain dict equality alone does not verify scalar types.
- JSON numeric fields must not be emitted as locale-specific strings or percentages. `0.7` ROC-AUC remains a fraction, not `70`. CSV headers/units identify seconds rather than silently converting to milliseconds.
- Use full-precision numeric export (a shortest round-trip float representation is sufficient). CSV is text: test typed reconstruction through the schema, not raw string equality with JSON numbers.
- Exclude only explicitly nondeterministic metadata from canonical comparisons, with the exclusions spelled out. Prefer keeping aggregation generation timestamps outside the canonical results payload; otherwise identical runs will not produce byte-identical complete files.
- Pick and assert one CSV newline policy (recommended `\n`), opening Python CSV files with `newline=""`. Run the same tests on Windows and Linux without requiring cross-platform byte identity for undeclared operating-system paths.
- If no CSV importer is a supported product feature, `csv.DictReader` plus a small **test-local**, schema-declared normalization is enough to verify the export contract. Do not add an importer solely to satisfy a test.
