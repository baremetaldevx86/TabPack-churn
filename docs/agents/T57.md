# T57 — Runner and CLI integration regression tests

## Assignment and coordination

Read `swarm.md` first, then coordinated against T42's synthetic all-path smoke
contract, T53's selection/aggregation API, and T51's model/checkpoint API. The
owned files are `tests/test_experiment.py` and `tests/test_cli.py`; no source
module was changed.

## Tests added

- `tests/test_experiment.py` uses only `make_synthetic_fixture()` and
  `prepare_data()` (32/12/12 rows, train-only preprocessing, unknown `violet`
  categories ignored) and a CPU configuration with one seed, two members, two
  epochs, baseline width 4, and heterogeneous width choices 4/8.
- The all-method integration test runs ordinary MLP, independent homogeneous
  MLP ensemble, and packed heterogeneous ensemble. It checks finite bounded
  validation/test metrics, frozen selection, event ordering from a trainer and
  test-prediction spy, categorical unknown handling, and all expected run
  records.
- Each selected inference checkpoint is loaded with
  `torch.load(..., weights_only=True)`, rebuilt as ordinary modules, and replayed
  on the test matrix. Recomputed ROC-AUC, log-loss, and accuracy must match the
  emitted metrics.
- A second fresh CPU run must retain the exact selected snapshot IDs/selection
  trace and numerically identical predictions, metrics, and training metadata.
- Non-empty output directories are refused without changing their sentinel.
- Report tests reject an incomplete matrix and a tampered expected seed matrix.
- `tests/test_cli.py` covers JSON CPU preflight, the synthetic CLI smoke plus
  report round trip, and CLI refusal of a non-empty smoke output directory.

`comparison_hash` to match the manifest and requires each declared checkpoint
to exist with the recorded SHA-256 digest. Replacing
`manifest.json["comparison_hash"]` with 64 zeroes raises a validation error.
