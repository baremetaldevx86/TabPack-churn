## Findings

### Official Churn path and feature types

`build_dataset` first calls `Dataset.from_dir`, which loads top-level `.npy`
  arrays (`x_num`, `x_bin`, `x_cat`, and `y`) and applies persisted split index
  arrays from `data/churn/splits/<split_id>/`. `load_data` validates numeric data
  as `float32`, binary data as `float32`, categorical data as `int64` or strings,
  and classification labels as `int64`. The split is applied before the
  preprocessing functions, so each transform receives separate train/val/test
  arrays. Labels are loaded into `Task` separately and are not passed to feature
  transforms.

The official Churn config does the following, in order:

1. Detect binary columns in `x_num` (`extract_bin_from_num=true`), moving detected
   columns to `x_bin`.
2. Convert all `x_bin` to categorical (`bin_policy=convert-to-cat`). Missing
   binary values would be represented by category `2`; extracted binary columns
   are selected only when they have no missing values.
3. Apply `noisy-quantile` to remaining `x_num`.
4. Apply `ordinal` to `x_cat`; model-side `OneHotEncoding` expands known values
   while OOV values produce all-zero blocks.

The paper’s Table 5 reports Churn as 6,400 train / 1,600 validation / 2,000
test rows, with 7 numeric, 3 binary, and 11 categorical source features. The
official configs do not encode those row counts; a loader must validate them
against the actual canonical data artifact rather than infer them from config.

### Numeric handling and transform details

`NumPolicy.NOISY_QUANTILE` constructs sklearn `QuantileTransformer` with
`output_distribution="normal"`, no effective subsampling, and
`n_quantiles=max(min(n_train // 30, 1000), 10)`. Before fitting, it adds iid
normal noise with standard deviation `1e-5` to the **training numeric matrix**
using the supplied seed. The fitted transformer is then used to transform every
split. This tiny jitter makes tied train values less ambiguous, but it is a
seeded stochastic preprocessing step and must be recorded for reproducibility.

There is no explicit median imputer in the official implementation. NaNs are
left for sklearn handling and subsequently passed through `np.nan_to_num`; the
source comment calls this a quick NaN workaround and relies on zero being the
mean after conventional normalization. Infinite values are also subject to
NumPy’s default `nan_to_num` replacement. Constant-column removal is based on
the transformed **training** matrix (`len(np.unique(x)) > 1`) and the same
train-derived mask is applied to every split.

This is materially different from the project’s reduced-protocol decision in
`swarm.md`: the independent reproduction must use an explicit train-fitted
numeric median imputer followed by a train-fitted quantile-normal transform.
Do not describe the official zero-after-transform NaN behavior as median
imputation, and record the difference if any official numbers are cited.

### Categorical and binary handling

`transform_cat` fits `OrdinalEncoder` on `X_cat['train']` only. Unknown values
are first encoded to a large sentinel, then validation/test sentinel entries
are rewritten to `max(train_encoded) + 1`; this is the explicit OOV index. With
the Churn `ordinal` policy, the integer matrix is passed to the model’s
`OneHotEncoding`. That module uses `one_hot(..., cardinality + 1)[..., :-1]`,
so known categories have stable columns and OOV categories are all zeros. With
the generic `one-hot` policy, `OneHotEncoder(handle_unknown="ignore")` is fit
on transformed training categories and likewise leaves unknown categories as
zero blocks.

`convert_bin_features_to_cat_` uses the existing categorical dtype when one is
present; otherwise it creates integer categorical columns. A missing binary
value is category 2. This conversion is done before `transform_cat`, so binary
columns ultimately share the categorical ordinal/OOV path. The official code
does not one-hot fit separately per split.

### Leakage audit

The ordinary numeric and categorical estimator fits are train-only, and labels
are not used by preprocessing. The main leakage caveat is
`_extract_bin_from_num`: it concatenates **all split values** before deciding
whether a numeric column has exactly two values and no missing values. This
means holdout feature values influence the decision to classify a column as
binary (feature-distribution/schema leakage, even without labels). The later
`OrdinalEncoder.fit` for selected columns is train-only, and the constant-column
mask is train-only. The official implementation therefore has a useful
train-only transform fit but does not satisfy a strict “all learned preprocessing
metadata is train-only” contract when binary extraction is enabled.

The cache key hashes `build_dataset` arguments after removing `path` and
`cache`; it includes policy arguments and seed but not the resolved dataset path.
Two distinct datasets sharing a directory basename and argument set could
therefore collide in the shared cache. The independent implementation should
include a canonical dataset identity/path and preprocessing fingerprint in its
cache key, or avoid caching until that contract is tested.

## Integration advice

1. For the independent Churn experiment, keep the persisted canonical split
   indices and assert the expected 6,400/1,600/2,000 row counts when the official
   artifact is available. Preserve row IDs/lineage through preprocessing.
2. Implement one explicit train-fitted preprocessing object: numeric median
   imputation, quantile-normal transform fit on train only, categorical mode
   imputation, and one-hot encoding with `handle_unknown="ignore"`. Fit once;
   transform all three splits with one schema and feature order.
3. Avoid reproducing official global binary discovery. Prefer a declared source
   schema or train-only binary detection, and document the final transformed
   dimensions. Do not use labels, validation, or test rows to decide feature
   transformations.
4. Expose a preprocessing fingerprint/metadata summary (imputer statistics,
   learned quantile state, category vocabulary, feature names, output width,
   and split row IDs) so the T24 leakage tests can assert holdout invariance.
   Unknown-category blocks should be all zeros; missing categories should first
   be filled by the train mode.
5. Record seed and quantile implementation/version. If a reference comparison
   intentionally reproduces official `noisy-quantile` or ordinal behavior, make
   those explicit alternate settings rather than silently mixing them with the
   reduced protocol.
