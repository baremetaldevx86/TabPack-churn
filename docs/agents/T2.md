# T2 — Packed architecture mathematics and official mechanics

## Assignment and scope

Research paper sections 3.2/3.3 and the pinned official implementation for
packed heterogeneous MLP mechanics: member/pack tensor shapes, width and depth
handling, masks, and integration constraints. This note is reference material
only; no upstream code is imported or executed.

## Sources and evidence

- Paper v1, sections 3.2 and 3.3: <https://arxiv.org/html/2607.05380v1>.
  Section 3.2 defines packing as stacking parameters and inputs along a new
  pack dimension and applying all models with broadcasting/vectorized matrix
  multiplication. Section 3.3 says heterogeneous models are widened/deepened
  to the per-pack maxima, with narrow representations zeroed, unneeded deeper
  layers skipped, and per-member dropout masks sampled at different rates.
- Official repository source at pinned HEAD
  `05a89e21b955f12de84889d662e15ca534019aaa`:
  [`src/project/nn.py`](https://raw.githubusercontent.com/yandex-research/tabpack/05a89e21b955f12de84889d662e15ca534019aaa/src/project/nn.py)

  The relevant classes are `PackView`, `LinearPack`, `DropoutPack`, and
  `MLPBackbonePack`; `ModelPack` composes them. The source fixes
  `PACK_DIM = 0` and `BATCH_DIM = 1`.
- Related local note read: `docs/agents/T27.md` (architecture documentation).

## Findings

### 1. Pack dimension and input broadcasting

Use `M` for pack/member count, `B` for batch size, `F` for input features, and
`H_max` for the maximum hidden width. The official layout is:

```text
ordinary input                         X             [B, F]
PackView(X)                            X_pack        [M, B, F]
packed hidden representation                         [M, B, H_max]
packed binary output logits                          [M, B, 1]
after final squeeze                                  [M, B]
```

`PackView` creates `[M, B, F]` from `[B, F]` with `unsqueeze(0).expand(M,
-1, -1)`. Expansion only broadcasts the input view; it does not share model
parameters. In training, an already-packed input must be rank 3 and have the
expected member dimension. The member dimension remains explicit through the
forward pass; it is reduced only by a separately specified ensemble operation.

### 2. Packed linear layer and exact shapes

For a `LinearPack` with member-specific input/output widths `d_in[m]` and
`d_out[m]`, let `D_in` and `D_out` denote allocated maximum dimensions. They
must be at least the corresponding largest member dimension. The official
config builder may allocate the sampling range's upper bound, even when no
sampled member attains it; explicit member configurations can use their actual
maxima. The official storage is:

```text
weight       [M, D_out, D_in]
bias         [M, D_out]       (if enabled)
in_features  [M]              (when supplied as a list, including equal values)
out_features [M]              (when supplied as a list, including equal values)
```

The batched operation is

```text
Y = bmm(X, weight.transpose(-2, -1))
```

with `X [M,B,D_in]`, producing `Y [M,B,D_out]`; with bias, the official code
uses `baddbmm(bias.unsqueeze(1), X, weight.transpose(-2,-1))`. The input must
already be masked to its actual width. After the operation, if widths vary,
the output mask is

```text
mask[m,j] = (j < d_out[m])       [M, D_out]
Y          *= mask[:, None, :]   [M, B, D_out]
```

Thus padded channels are exactly zero after each active linear block. The
output mask is important both for the next layer's input contract and for
preventing padded channels from reaching a head. There are no cross-member
terms: each `weight[m]`, `bias[m]`, and `X[m]` participate only in member `m`'s
matrix multiplication.

The official `ParameterPack` stores trainable tensors with a leading member
axis; dimension metadata that varies by member is held as a non-trainable
`BufferPack` (for example `[M]` widths). The implementation accepts an integer
for a common dimension or a list of length `M` for heterogeneous dimensions,
and requires explicit/inferred maxima for list-valued dimensions.

Initialization uses each member's *actual input fan-in*: both its weights and
biases are uniform in `[-1/sqrt(d_in[m]), +1/sqrt(d_in[m])]`. Initializing every
member with the padded maximum's fan-in would change the narrow members'
initialization distribution. Inactive weights need not be zero: zero input
columns and masked output rows ensure they have no effect on predictions and
receive zero data gradients. Under AdamW, weight decay can still change such
stored values; test functional/gradient isolation rather than requiring every
unused parameter to remain numerically zero.

### 3. Heterogeneous depth and width

`MLPBackbonePack` accepts `n_blocks` and `d_block` as either one integer or a
list of `M` values. It constructs the allocated `max_n_blocks` block slots;
this capacity is at least `max_m n_blocks[m]`, with the same sampling-bound
caveat as widths. Depth means the number of hidden Linear-ReLU-Dropout blocks,
excluding the separate linear output head. Within a member, the hidden width
is constant across blocks (this is not arbitrary layer-by-layer widths).
each slot contains a packed linear layer followed by activation and dropout.
The first slot has input width `d_in`; later slots have padded input width
`H_max`; every slot stores output capacity `H_max`. A list-valued `n_blocks` is
stored as a `[M]` buffer.

For each block index `k`, the official active-member predicate is:

```text
active[k,m] = (k < n_blocks[m])   [max_n_blocks, M]
```

The code caches the member indices active for each block. If all members are
active it calls the block on the full packed input (`[M,B,F]` for block 0,
`[M,B,H_max]` thereafter). Otherwise it selects
`X[active_members]`, calls the block with matching parameter/width metadata,
and writes the results back with `index_copy` along `PACK_DIM`. If no members
remain for a block, it breaks. Consequently a depth-1 member is never sent
through the depth-2/3 member computation merely because those layers exist in
the packed module.

Widths and depths interact safely: the last active linear block masks a
member's channels to its `d_block[m]`; skipped deeper blocks leave this padded
representation unchanged (with inactive channels zero); the output head then
consumes the padded width with the same member-specific input-width contract.
The head in official `ModelPack` is a `LinearPack` over the backbone maximum
width, with one binary output (`[M,B,1]` before squeezing).

The paper's mechanism supports different widths, but its main experiments use
one fixed backbone width by default (section 3.7). The varying-width experiment
in section 5.1 is a separate ablation. Thus the proposed local varied-width
reduction exercises a supported mechanism without matching the default paper
configuration.

### 4. Dropout masks

`DropoutPack` accepts one probability or a list `p[m]`. For a heterogeneous
pack, the code builds `p_keep[m] = 1-p[m]`, reshapes it to `[M,1,1]` for a
rank-3 hidden tensor, samples `bernoulli()` after expanding to `[M,B,H_max]`,
and scales by `1/p_keep` before multiplying the hidden representation. The
member axis is therefore present in the stochastic mask; one member's dropout
rate/mask is not shared with another's. Evaluation mode returns the input
unchanged. The list-valued implementation permits `p=1` in constructor checks
but divides by `1-p` in forward, implying a `0/0` edge case by inspection;
the local `[0,0.1,0.2]` range avoids it. This was not executed as a bug test.

### 5. Loss and batch independence relevant to packed forward

The official `tabpack.py` loss helper flattens the leading pack and batch axes
only to invoke the unreduced base loss, then unflattens back to `[M,B]` and averages
over `B`. This preserves one loss per member rather than a loss of the
probability-averaged ensemble. The local reduced protocol additionally records
the intended reduction explicitly as sample mean then member sum.

The official training batch generator samples random permutations with shape
`[M, train_size]` and splits along the batch axis, so each member can receive a
different batch sequence. This is separate from model packing and should not
be replaced by one shared permutation if independent-training semantics are
required.

## Integration advice

1. Keep `[M,B,*]` as the public packed contract even if implementation groups
   equal shapes internally. Make parameter tensors `[M,...]`, with no views or
   optimizer state shared across members.
2. For a simple local implementation, padded `[M,B,H_max]` tensors plus
   explicit per-layer width masks are faithful to the official behavior. Apply
   output masks after every active linear layer. The official code skips
   inactive depth slots by member index; a simpler compute-and-select variant
   can be mathematically equivalent if it retains the member's previous hidden
   state unchanged and routes no gradient through its unused block. Zeroing
   that member's hidden representation is not a valid depth skip. Record the
   extra computation and different dropout random-number consumption if this
   alternative is used.
3. Broadcast `[B,F]` inputs only along the member axis. For binary output,
   return member logits `[M,B]` (or `[M,B,1]` internally), apply sigmoid per
   member, and average probabilities only in the ensemble consumer.
4. Preserve the agreed local objective: each member's BCE is mean-reduced over
   samples and the member losses are summed, not averaged over `M`. Test this
   reduction independently from probability averaging.
5. Add an equivalence test with unequal widths and depths, including a member
   whose later block is skipped. Compare packed outputs with independently
   evaluated members, and assert padded hidden channels and inactive data
   gradients are zero. Use identical copied parameters and dropout disabled (or
   explicitly supplied matching masks) for the numerical oracle; equal seeds
   alone do not ensure equal random draws between packed and looped execution.
   Packed member slices share an allocation but must occupy disjoint,
   non-overlapping regions; test no aliasing of actual member coordinates, not
   different storage pointers for slices of the same packed tensor.
6. This repository's reduced experiment intentionally uses AdamW and omits
   official periodic embeddings/Muon/base pruning; preserve the qualifier
   “packed TabPack-style” in result names.
